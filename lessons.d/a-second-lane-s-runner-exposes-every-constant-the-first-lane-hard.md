# A second lane's runner exposes every constant the first lane hard-coded

The Python Warrant lane (WD-101) wrote `toolchain.name == "python"` into the
digest that binds `domain-labels.json` to its manifest. Nothing failed until the
TypeScript lane (WD-102, toolchain `node`) asked the Python `validate-manifest`
to accept its manifest: the manifest passed, the label sidecar was refused with
"differs from the labels derived from the corpus", because the Python runner
recomputed the digest with its own name. The runner was written as "the shared
validator", but one literal made it a Python-only one.

Fix: read the toolchain name from the manifest being checked (the name stays in
the digest, since swapping runtimes is drift; only `toolchain.version` is
ignored). The change moved `runner.src_sha256`, so the Python `ct-compare`
manifest had to be regenerated by a real run in the same change.

Do differently: when a runner or validator is meant to serve several lanes, run
it against the *second* lane's artifact before calling it shared, and grep it for
the first lane's own name (`"python"`, `.py`, `sys.executable`). Remember that
editing a runner's source invalidates every committed manifest that embeds its
digest, in every lane that uses it.
