## Unreleased — LANG83 PR7f-1 — the dynamic-value primitives, under neutral names

- LANG83 PR7f registers the tagged-word dynamic-value representation as ten Builtins (`dyn_box_int`, `dyn_unbox_int`, `dyn_tag`, `dyn_pair_new`, `dyn_pair_first`, `dyn_pair_rest`, `dyn_is_pair`, `dyn_is_nil`, `dyn_nil`, `dyn_symbol`), renaming the Lisp-vocabulary `dyn_cons` / `dyn_car` / `dyn_cdr` / `dyn_pair_p` / `dyn_null_p` / `make_nil` / `make_symbol` wherever they are lowered. `check_module_for` now gates them: native x86-64 / AArch64 and LLVM lower all but `dyn_symbol`; WASM, JVM, CLR, BEAM, the VM and the JIT refuse them (`NO_TAGGED_WORD_RUNTIME`). No frontend emits them yet — the frontends still emit `cons` / `car` / `null?`, which the tagged-word pipelines rename to the registered names after the check — so no program's IIR before the check, and no program's output, changed.
- The scalar-narrowing evidence lists (`concretize_scalar_any_for_llvm` / `_jvm` / `_clr`) name the registered primitives (and drop `make_nil` / `make_symbol`, which nothing emits).
- `jit_lisp` registers its McCarthy callbacks under the new names (`dyn_pair_new`, `dyn_pair_first`, `dyn_pair_rest`, `dyn_is_pair`).
- `op_conformance`: a case runs every primitive but `dyn_symbol` (pairs, tags, nil, the pair and nil tests, a nested list) and prints each result; a second case pins that `dyn_symbol` is refused everywhere. The gate `pr7f_dynamic_values_run_on_the_tagged_word_backends` pins the support matrix, requires the case on LLVM and native x86-64 when present, and checks that WASM, JVM, CLR, BEAM, the VM and the JIT refuse it with `UnsupportedOps` before any pass.
- Tests that named the old runtime symbols (`end_to_end_smoke`, `conformance`, `llvm_lambda`, `macos_native_lisp`) use the new ones.
