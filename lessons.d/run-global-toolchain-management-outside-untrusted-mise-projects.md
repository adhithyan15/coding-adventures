# Run global toolchain management outside untrusted mise projects

On a fresh sibling worktree, a globally installed command such as `rustup` can be intercepted before execution when `mise` discovers an untrusted repository `mise.toml`. Do not trust project configuration merely to install a global validation component. Run the global toolchain-management command from a neutral directory such as `/tmp`, then return to the worktree for the build. If the command name is itself a `mise` shim and the neutral directory has no default version, explicitly select an already-installed tool (for example, `mise exec rust@stable -- rustup ...`) instead of retrying the unresolved shim. This preserves the repository trust boundary and avoids changing project-local tool activation state.
