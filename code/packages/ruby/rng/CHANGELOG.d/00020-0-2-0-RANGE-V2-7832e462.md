## [0.2.0] — next_int_in_range spec v2

### Fixed

- **Wide ranges were unreachable.** The range draw used one 32-bit draw for
  every span, so a range wider than 2^32 could never return more than
  2^32 − 1 above `min`. It now follows spec v2 (`code/specs/rng.md`): 32-bit
  draws for spans up to 2^32 (unchanged, so those sequences are the same as
  0.1.0), 64-bit draws with 64-bit rejection for wider spans, one plain
  64-bit draw for the whole signed 64-bit domain. The three generators share
  one helper.
- Bounds must be integers inside the signed 64-bit domain, as the spec
  requires; anything else raises `ArgumentError` before any draw.

### Added

- A conformance test running the shared corpus (`cases.json`), plus regressions.
  Changelog sharded.
- `standardrb` findings in the existing sources and tests fixed.
