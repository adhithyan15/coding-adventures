## Unreleased - [D74] `ill-typed` in `v2-fault`, [D75] `Int` model parameter, R113, R115 (b), R117 (CV2-F17, VER04r 16.22)

- **[D74], R110: `v2-fault` has `ill-typed`.** `ERROR_CODES["v2-fault"]` is `ill-typed`, `level-missing`, `subject-forbidden`. `derive_fault` runs
  `check_type_table(types, "ill-typed")` first, then `level-missing`, then `subject-forbidden`, then the typing of the row; a fault row with no common
  type (R94, R96 to R98), an expression ill-typed as a tree and an op row naming `Int` or an undeclared type are `ill-typed` and no longer
  `KitError("the oracle cannot compile the fault")`. `instantiate_fault` writes its templates from the records whose fields all parse, so an undeclared
  field is an outcome (`ill-typed`), not an uncaught `Refused`.
- **[D75], R111: a model parameter may be `Int`.** `_models` and `reached_levels` parse a model parameter with `allow_int`, also under `Option`,
  `Result`, a tuple and `List`. Op rows (now `ill-typed`, was the out-of-set `type`), fields, binders, `env` entries (`type`) and values still refuse
  `Int`. The oracle's `v2-chunk` reader does not read corpus model rows, so nothing is needed there. The generation side (R105) is untouched.
- **R113.** `bindings_v2.read_corpus` applies `check_type_table(types, "corpus")` to `corpus.types`; a bad table is a `BindingKitError` (`v2-binding`
  has no table code, so such a case cannot be a vector).
- **R115 (b).** `compile_ir_case` checks the `max_ir_cost` bound before the table (the oracle said `ill-typed` for a bad table with a bound outside
  `2,000..=65,536`; it now says `ir-cost`, as both lanes do).
- **R117 and R110 (a).** `check_type_table` reads the table whole: an error name anywhere but the second argument of `Result` (a field or constructor
  component, alone or under `Option`, a tuple or `List`) is refused, as is every member text the type parser refuses (over-deep, `Int`, malformed,
  `Result<U8,Q>` with `Q` a record) and any row outside section 2.2 rules 2 to 4 (a row that is not an object or of another kind, an error with 0 or more
  than 64 or repeated cases, a record with 0 or more than 32 fields, a variant with fewer than 2 or more than 64 constructors, a constructor with more
  than 8 fields, a name outside `[A-Za-z_][A-Za-z0-9_]*`). `parse_type` and `lower._resolve` (`type`, "an error type is not a value type") refuse an
  error name used as a value type.
- **Review fixes.** `check_type_table` also refuses a type name outside `[A-Za-z_][A-Za-z0-9_]*` or that is a reserved built-in (R58, via `lower._DECLARED_RESERVED_V1`), an error case name outside the grammar, a constructor named like a built-in, and a field or constructor entry that is not a list of exactly a name and a second element (a 2-character string passed by indexing). An `env` entry naming an error type is `ill-typed` (`ERROR_NOT_VALUE`); an `Int` env entry stays `type`. `instantiate_fault` skips malformed rows instead of crashing. The duplicate `_IDENT` is gone.
- Tests: `tests/test_cv2_16_22_checks.py`; five tests that pinned the old behaviour change: `test_conformance.py::test_derive_fault_table_errors` and `test_s5e_vectors.py::test_a_fault_needs_a_common_type_not_assignability` move from `KitError` to `ill-typed`; `test_conformance_tables.py::test_error_codes_stay_in_the_closed_sets_and_every_code_is_used` exempts the unused v2-fault `ill-typed`; `test_cv2_16_21_checks.py::test_malformed_rows_are_refused_not_crashes` expects an unreferenced non-object row to be refused. No committed fixture, dump,
  corpus or kit byte moves (`make_conformance.py --check`: 958 cases in 7 files identical). No kit vector is added (S10d and S11d own them).
