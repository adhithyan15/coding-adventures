## Unreleased — LANG83 PR7b — `f64_class`, `f64_digits`, `f64_exp10` on every backend

- LANG83 PR7b — the language-neutral float primitives (`f64 → i64`, pure, never a trap) are lowered on all nine backends. `tests/op_conformance.rs` gains four cases over PR6a's 90 table values, each result printed with `write_i64`: `f64_class`, `f64_digits` and `f64_exp10` of the 87 finite values (all nine backends, BEAM included), and all three of `±Infinity` and NaN (the eight IEEE backends; BEAM cannot hold those constants). The expectations, `FLOAT_DIGITS_TABLE`, were generated by host `python3` (`repr` split at the digits).
- New gate `pr7b_ops_are_lowered_on_every_backend`: the support matrix, all four cases on WASM, VM, JIT, LLVM, native and JVM whenever their tools exist (locally all six run), and BEAM compiling the finite cases while refusing the non-finite one. New `float_digits_table_follows_the_float_table` (the rows match `FLOAT_TABLE`'s values and Python strings, and re-read as the same double) and `float_digits_table_matches_host_python3` (re-derives every row when `python3` is installed). CLR, BEAM and AArch64 are structural here.
- `concretize_scalar_any_for_jvm` counts every registry Op with an `f64` operand as wide-model evidence, so a module whose only real is a float literal propagated into `f64_digits` (whose result reaches 10^17) is not narrowed to `int`.
