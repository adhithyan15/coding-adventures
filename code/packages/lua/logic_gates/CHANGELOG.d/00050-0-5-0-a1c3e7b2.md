## [0.5.0] - 2026-11-24

### Changed (BREAKING)

- `sequential.lua` now reuses `gates.lua`'s validator: every bit (inputs and
  stored flip-flop / counter state) must be the integer 0 or 1; `1.0` and all
  other non-bits raise the structured `INVALID_BIT` error.
- Counter widths must be integers in 1..64 (`MAX_COUNTER_WIDTH`); data widths
  (Register / ShiftRegister) 1..65536 (`MAX_WIDTH`). Checked before any loop or
  allocation, so `width = 1e9` is rejected instantly with `INVALID_WIDTH`.
- `Counter` requires `state.width == #state.bits` and validates the state on
  every path (hold, reset, increment); mismatches raise `INVALID_SHAPE`.
  An empty `bits` table is no longer lazily filled.
- Counter's returned output and state bits are now independent fresh tables.

### Added

- Error codes `INVALID_WIDTH` and `INVALID_SHAPE` with
  `is_invalid_width` / `is_invalid_shape` predicates and a generic
  `error_code(err)` accessor; `MAX_WIDTH`, `MAX_COUNTER_WIDTH` exports.
- `tests/test_sequential_hardening.lua`.

### Fixed

- Register / ShiftRegister validate flip-flop state fields up front and return
  fresh canonical values (no raw `slave_q` leakage as `serial_out`).
- LGE-LUA-STALE: BUILD / BUILD_windows of `logic_gates`, `fpga`,
  `arm1_gatelevel`, `intel4004_gatelevel` now always `luarocks make` the local
  logic-gates (and transistors) rockspec instead of skipping when ANY version
  is installed, so cached trees cannot test against an older, permissive
  validator.

### Packaging

- Rockspec renamed to `coding-adventures-logic-gates-0.5.0-1.rockspec`.
