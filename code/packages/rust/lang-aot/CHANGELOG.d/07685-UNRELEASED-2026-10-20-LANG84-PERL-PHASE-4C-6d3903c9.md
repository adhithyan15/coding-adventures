## 0.584.0 (UNRELEASED)

- LANG84 phase 4c — the Perl release sweep on the backends. `lang_matrix`'s `Prog` gains `release: Option<&'static str>` and `case: Option<&'static str>` (`"<subset>/<name>"`); every existing non-Perl literal names `release: None, case: None` (748 literals, added by a string- and comment-aware script; no other change). Every runner now compiles through one `prog_iir(p, name)` helper, `compile_source_to_iir_at(p.lang, p.release, ..)` followed by the backend's `compile_iir_to_*` entry point (native takes a `LanguageRequest`), so a row tagged with a release really runs that release's grammar on every column; for `release: None` this is exactly the old `compile_source_to_<backend>` path. The Perl rows are now the `pl-int-print` corpus (`code/grammars/perl/corpus/pl-int-print/`, sources `include_str!`ed through `perl_case!`) on the three IIR-identity class representatives of `perl-iir-compiler`'s release sweep: 12 cases on the default `5.38.0`, 11 on `1.000` and 10 on `5.003_26` (33 rows, 264 cells, all eight columns via `EVERY_COLUMN`). With them `release_inventory.py check --matrix` covers B(`pl-int-print`) for all 118 checked Perl releases (33 cells direct, 1,196 by IIR class, 187 not applicable). New named test `perl_rows_run_their_corpus_case` (in BUILD with `-- --exact`): each row's source and expectation equal its corpus files, and the rows are exactly the sweep's boundary set read from `release_classes.csv`. `perl_rows_pass_the_lang83_check_on_all_nine_backends` compiles each row against its own release and checks the module records it. `feature_coverage_doc_counts_match_programs_source` and LANG-VM-FEATURE-COVERAGE.md now say Perl 33 rows / 264 cells. Locally (no `dotnet`, no `erl`): the Perl rows ran 198 cells and skipped the 66 CLR/BEAM ones, agreed with host perl v5.38.2, and `non_algol_matrix_every_proven_cell_agrees` passed; a planted `crlf_layout` row on 5.003_26 failed in the runner with that release's lex error (`Perl 5.003_26: Perl tokenization failed at 1:10`), so the row's release reaches the backends.
- The Ruby and Python rows now name their default release (`3.3.6`, `3.13.16`) and their corpus case. Ruby gains the `empty_program` row (`src: "\n"`, stdout `""`). The Ruby, Perl and Python host-interpreter oracles now feed each source to the interpreter on stdin (`ruby -`, `perl -`, `python3 -I -`) through one helper, `run_host_oracle`, instead of passing it with `-e`/`-c`. On Windows, Rust quotes an argument only when it holds a space or tab, and the mingw-built `ruby` and `perl` split their command line on any whitespace. So `build (windows-2025)` failed twice: Ruby's `empty_program` (`"\n"`) reached Ruby as `-e` with no code, and Perl's `crlf_layout` (`"print(1);\r\nprint(2);\r\n"`) ran only `print(1);`.
