# vos-sched-any

The **most-general (`-any`) scheduler** of the verified-OS program (backlog VOS-012a). It
implements [`vos-sched-contract`](../vos-sched-contract) (VOS10) for eight threads and does
*every* thing the contract's safety tier permits, chosen by a hidden register (the oracle).
Crate class **K**, kind **any**; it carries the **safety** and **any** tiers and *not*
canonical or policy.

> **EVIDENCE ONLY. NEVER SHIPPABLE (SH16).** This crate is not a scheduler to boot. It exists
> so the verification can show the safety tier is neither empty nor over-tight: that its
> soundness and coverage hold for *every* oracle value. No image may contain it; the name ends
> in `-any`, `vos.toml` says `kind = "any"`, and `check-doc` rejects an `-any` crate declared
> `production`. What it is evidence for, and what it is not, is VOS01 section 3.

## How it works

State is the ready set (`mask`, bit `t` set when thread `t` is ready) plus `choice`, the oracle.

```text
  insert(t)   mask | (1 << t)                     choice untouched (never read)
  remove(t)   mask & !(1 << t)                    choice untouched (never read)
  dispatch    PROPOSE  t = choice
              VALIDATE t < 8 and bit t of mask is set
              DEFAULT  Idle otherwise;            when Run(t): clear bit t; choice untouched
```

* **Sound**: `dispatch` answers only what the contract's `safe_dispatch` permits (`Idle`, or a
  ready thread, which then leaves the ready set) and never moves the oracle.
* **Covering**: the oracle value `t` produces `Run(t)` for every ready `t`, and `255` produces
  `Idle` for every mask, so every permitted output is reachable.

`choice` is private. Production `init` makes `choice = 0`, so the shipped surface only ever
proposes thread 0. The **only** code that can build a state with another oracle value is the
`ghost` module (cargo feature `ghost`, evidence build only), which is how the harness quantifies
over all 256 oracle values. `#![no_std]`, `#![forbid(unsafe_code)]`,
`clippy::arithmetic_side_effects` denied (SH9).

## Checks

```text
cargo test -p vos-sched-any                     # behaviour tests (the shipped surface: oracle 0)
cargo test -p vos-sched-any --features ghost    # plus the ghost wrappers and all 256 x 256 states
cargo run -q -p vos-shape-check -- .            # SH1-SH18, class K, kind any
vos-link check-doc .                            # the document is current and lawful (R6 any rules)
```

Line coverage of `src/*` is a **gate** (VOS-D070, VOS04 5.6): `coverage-floor = 95` in `vos.toml`, enforced on Linux by the
`cargo tarpaulin ... --include-files 'vos-sched-any/src/*' --fail-under 95` line of BUILD, and `vos-link check-component` fails if the floor,
the line or its `--include-files` is missing or disagree. Measured (tarpaulin, LLVM engine, `--lib --test behaviour --features ghost`,
2026-11-17): **100%, 67 of 67 lines of `src/lib.rs`**. The generated evidence suite is not part of the measurement (VOS-D106).

`BUILD` and `BUILD_windows` are generated by `vos-link gen-build` (do not edit above the marker; add your own lines below it): edit `vos.toml`, `evidence.bindings` or `warrant/sabotage.plan` and regenerate.

## The generated evidence

```text
cargo run -p coding_adventures_warrant_grammar --example gen_evidence -- vos-sched-any          # regenerate
cargo run -p coding_adventures_warrant_grammar --example gen_evidence -- --check vos-sched-any
```

8 exhaustive claims, **262,914 cases** (the largest 65,536, 16.4% of the 400,000 budget): the
safety tier (`insert_safe`, `remove_safe`, `dispatch_safe`, `safety_alpha_build`, `safety_init`) and the any tier
(`dispatch_sound`, `dispatch_covers_run`, `dispatch_covers_idle`), plus the same 8 as property and
fuzz suites, 3 examples and 18 negative controls: 45 tests, all pass. `safety_init` (VOS-D081) has no negative control of its own: its subject is `alpha_w`, whose only fault, `field-zero`, is inert on the empty state (VOS-D065, WX-SV2); a mask-8 `init` is caught by it, by the behaviour tests, and by the contract-check mutants. A plain
`cargo test --features ghost --test warrant_evidence` exits 0: no claim has `init` as its subject,
so the known-inert `init` / `field-zero` controls of `vos-sched-fp-bitmap` (VOS-D065) do not arise
and no tolerance script is needed.

**Mutation sanity.** Source mutants run against the generated suites (not kept in BUILD): an
oracle-ignoring dispatch fails `dispatch_covers_run` and `dispatch_covers_idle`; a dispatch that
skips validation fails `dispatch_safe` and `dispatch_sound`; one that moves the oracle fails
`dispatch_sound`. **Known gap (VOS-D080):** a mutant whose `insert` or `remove` overwrites the
oracle passes the generated evidence, because the safety claims quantify over `build(M)` and
`alpha` forgets the oracle; only the hand-written behaviour test catches it.

**The ceiling `heap 0` is evidenced on every bound operation** (VOS-D063): the harness's heap observer
counts the export call only, so all eight bound operations carry a `heap <= 0` row.
