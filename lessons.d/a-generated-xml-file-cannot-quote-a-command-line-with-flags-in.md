# A generated XML file cannot quote a command line with -- flags in a comment

**What went wrong.** The generated Android project (UI89 step 4) copied the
Kotlin and Gradle files' banner into `AndroidManifest.xml` and
`res/values/strings.xml`:
`<!-- AUTO-GENERATED by mosaic-compile pkg --backend compose --emit-project ... -->`.
XML forbids `--` anywhere inside a comment, so the Android resource merger
refused the file (`The string "--" is not permitted within comments`) and the
APK build failed on its first CI run. The local tests only checked for
substrings, and the APK could not be built locally, so nothing parsed the XML
before CI did.

**Fix.** The XML banners say `(Compose backend, emit-project)` instead of
quoting the command line, and the builder test walks every comment in the
generated XML and asserts it contains no `--`.

**Do differently.** When a generator writes a file in a format with its own
syntax rules (XML, JSON, TOML, plist), parse the output with a strict parser
in a test, even if the real toolchain only runs in CI. A banner string reused
across file types is the usual way this slips in:
`python3 -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" f.xml`
reproduces the failure in a second.
