## Unreleased — LANG83 PR7e — no float writers, and no language-named builtins

- LANG83 PR7e removes `write_f64_py` / `write_f64_js` from the registry and all nine backends (each compiler lays a float out in its own module since PR7c-js / PR7c-py). `lang_matrix`'s VM runner and both halves of its JIT runner drop their `write_f64_js` / `write_f64_py` sinks (and `py_float_text` / `js_number_text`, which called vm-core's removed formatters). Every row prints what it printed before.
- `lang_matrix` and `op_conformance` runners check, on every run, that no builtin they register names a source language (`interpreter_ir::op_registry::language_name_violation`, through vm-core's new `BuiltinRegistry::names()` and jit-core's `GenericCirJit::builtin_names()`); `op_conformance` also has `harness_builtins_name_no_language`.
- `op_conformance` keeps PR6a's 90-value table as the oracle. The two writer table cases become four helper cases: python-iir-compiler's `__py_write_float` and javascript-iir-compiler's `__js_write_number`, taken verbatim from the module each compiler produces for a one-print program, print the finite rows (all nine backends; BEAM compile-checked) and, separately, `±Infinity` and NaN (the eight IEEE backends), each expecting the PR6a strings that `float_table_matches_host_python3_and_node` re-checks against host `python3` / `node`. The ordered-stream, computed-float and PR7b linked-runtime cases print through the helpers too.
- The gate `pr7e_float_writers_are_gone_and_the_layouts_run_everywhere` replaces `pr6a_ops_are_lowered_on_every_backend`: neither writer is a registry entry or declared by any backend, every compile entry point (LLVM, WASM, JVM, CLR, BEAM, native) refuses a module that calls one and the VM fails on it, and the six PR7e cases run on every executable column whose toolchain is present (all 180 table lines, both layouts).
- The JIT runner now requires every call-free function to be JIT-compiled (`main`, or a layout helper's digit counter and digit writer when `main` calls a helper) and, when the output holds a digit, that a compiled function ran.
- The PR6c IEEE cases print each result as `class digits exp10` (and its sign bit) instead of through `write_f64_js`, so their `main` stays call-free and the JIT still runs the IEEE ops as compiled bytecode. `beam_refuses_non_finite_float_constants` uses the helper tables.
- README: the PR6a paragraph is history and points at the compilers' helpers.
