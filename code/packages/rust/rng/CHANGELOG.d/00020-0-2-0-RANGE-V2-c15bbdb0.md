## [0.2.0] — next_int_in_range spec v2

### Fixed

- **`next_int_in_range` could not return most of a wide range.** It drew one
  32-bit value for every span, so for spans above 2^32 it never returned more
  than 2^32 − 1 above `min`. It now follows spec v2 (`code/specs/rng.md`):
  32-bit draws for spans up to 2^32 (unchanged, so those sequences are the
  same as 0.1.0), 64-bit draws with 64-bit rejection for wider spans, and
  one plain 64-bit draw for the whole signed 64-bit domain.
- **The 0.1.0 code could hang forever.** It took the rejection threshold
  modulo 2^64 while drawing only 32 bits. For a span such as 2^63 + 1 the
  threshold exceeded every possible draw, so the loop never ended. For
  smaller spans the same mismatch was biased and disagreed with the other
  languages.
- The whole `i64` domain made the span wrap to 0 and panicked with a
  division by zero; `min + offset` could overflow `i64` near `i64::MAX`.

### Added

- `tests/conformance.rs` runs the shared corpus (embedded with
  `include_str!`), plus regressions for wide ranges, the whole domain and
  ranges ending at `i64::MAX`.

### Changed

- The three generators share one `int_in_range` helper. The changelog is now
  sharded.
