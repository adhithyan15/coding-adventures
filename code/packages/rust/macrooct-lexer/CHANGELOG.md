# Changelog — `coding-adventures-macrooct-lexer`

## 0.1.0 — 2026-09-21 (PREP01 slice 1)

First release. Tokenizes MacroOct — Oct's lexical rules plus five `@`-prefixed
preprocessor directives and a string literal for include paths — using the
grammar-driven `GrammarLexer` over the embedded `macrooct.tokens` grammar.

MacroOct is the proving ground for the generic preprocessor engine
(`source-preprocessor`, PREP01). Oct is unmodified by this crate and by every
other part of the slice: it is the reference MacroOct's output is checked
against.

### Added

- `code/grammars/macrooct/macrooct.tokens`, derived rule for rule from
  `oct.tokens` in the same first-match-wins order, adding:
  - `AT_INCLUDE`, `AT_DEFINE`, `AT_IF`, `AT_ELSE`, `AT_END` — listed first, so a
    future `@` rule in Oct would be shadowed *by* them rather than silently
    shadowing one of them.
  - `STR_LIT` (`/"[^"\n]*"/`) for include paths. Newline-excluded, so an
    unterminated quote is reported on its own line instead of swallowing the
    rest of the file.
- `src/_grammar.rs`, generated by `grammar-tools compile-tokens`, and a
  `macrooct (rust)` section in
  `code/programs/ruby/grammar-tools/generator.rb` so
  `generate-compiled-grammars.sh` keeps it current.
- `tokenize_macrooct` (panicking, mirroring `oct-lexer`) and
  `try_tokenize_macrooct` (`Result`-returning). The latter exists because the
  preprocessor engine's no-panic contract reaches through `Dialect::lex` into
  this crate: an `@include`d file's text is chosen by the program being
  compiled.

### Tests

11 unit tests. The two that carry the design:

- `macrooct_agrees_with_oct_on_every_non_directive_rule` — parses both
  `.tokens` files and asserts every non-directive definition, every keyword and
  every skip rule matches Oct's, **in order** (the lexer is first-match-wins, so
  order is semantics). PREP01 §7 requires this: restating Oct's rules is the
  slice's one real drift risk. It also asserts the six added rules are present,
  so deleting them cannot make the comparison vacuously pass.
- `the_compiled_grammar_matches_the_macrooct_tokens_file` — closes the gap
  between the file the test above checks and the artefact the lexer actually
  uses.

The rest cover per-directive tokenization, `@include` not lexing as `@if`
(their only ordering hazard — they diverge at the third character), the
keyword `if` staying distinct from `AT_IF`, an unterminated string literal
failing on its own line, and `Token::line` being populated (the engine groups
logical lines by that field, since Oct's skip rules emit no newline token).
