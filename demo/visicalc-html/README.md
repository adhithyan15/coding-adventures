# VisiCalc — HTML demo

The first cross-backend VisiCalc visual demo (per
`code/specs/visicalc-cross-backend-demo-plan.md` Phase 2 / VC2-html).

## What it shows

A static-HTML render of the VisiCalc UI: a one-line formula bar above
a 5×5 spreadsheet grid. Cell A1 (`=SUM(B1:B5)`, value `15`) is the
selected/active cell — highlighted in excel-blue with the same
`#264f78 / #007acc` palette the React demo uses.

No JavaScript. The whole demo is a single `index.html` file you can
open in any browser.

## How it's built

The FormulaBar fragment is **generated by the Mosaic pipeline**:

```bash
bash scripts/build.sh
```

That runs `mosaic-compile --backend html` against
`demo/visicalc/mosaic/FormulaBar.{mil,desktop.mll,dark.msl}` and
writes the result to `build/FormulaBar.html`. The snippet currently
inlined into `index.html` is a snapshot of that output with
`{{cellAddress}}` / `{{formula}}` / `{{readOnly}}` placeholders
pre-substituted to the demo's hard-coded values (so the file works
when opened directly, no runtime mustache renderer needed).

The Grid fragment is **hand-written** in `index.html`. The mosaic
emit-html crate doesn't yet know the `Grid` built-in primitive
(only the React emitter does — see
`code/packages/rust/mosaic-emit-react/src/pipeline.rs`). When the
HTML Grid emitter lands, `build.sh` gains a second `mosaic-compile`
invocation and the hand-written `<table>` block in `index.html`
gets replaced with a reference to `build/Grid.html`.

## How to view

```
open demo/visicalc-html/index.html
```

(Or just double-click the file in a file browser. Any modern
browser works — there's no Web Component, no module loader, no
build step beyond `bash scripts/build.sh` for the FormulaBar
regeneration.)

## Follow-up: live mounting

The static snapshot pattern keeps this demo zero-runtime, which is
the right call for a "look, it renders" first cut. A follow-up
`VC2-html-live` would add a tiny JS shim (~20 lines) that reads
the `{{...}}` placeholders out of `build/*.html` and replaces them
from a real data model — same visual, but with the data flowing
from a JS state instead of pre-baked at build time.
