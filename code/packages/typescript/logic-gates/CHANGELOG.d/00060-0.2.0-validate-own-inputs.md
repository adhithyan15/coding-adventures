## 0.2.0 - 2026-11-24

### Changed (behaviour)

- **Every one of the 11 basic gates validates its own arguments** with the
  package's `validateBit` (NOT, AND, OR, XOR, NAND, NOR, XNOR, nandNot,
  nandAnd, nandOr, nandXor; also nandNor, nandXnor). Previously NAND/NOR/XNOR
  relied on the transistors package, so the error class differed per gate.
- One rule everywhere: non-number or non-integer number (NaN, Infinity, 0.5,
  booleans, strings, bigint, objects, ...) -> `TypeError`; integer other than
  0/1 -> `RangeError`. **Breaking:** `1.5` was a `RangeError` from AND/OR/XOR
  and is now a `TypeError`.
- **`-0` is rejected** (`RangeError`) via `Object.is`; it was previously
  accepted because `-0 !== 0` is false. `1.0` is accepted: JS has no integer
  type and `1.0 === 1`.
- **Arity is enforced**: too few or too many arguments throw `TypeError`.
- `validateBit` (shared with combinational/sequential) gets the same stricter rule.

### Added

- `tests/gates.exhaustive.test.ts`: literal truth tables for all 11 gates,
  NAND-built == direct, every integer in [-1024, 1024] (plus +-2**31, 2**53,
  MAX_SAFE_INTEGER, MAX_VALUE) at every argument position, a 23-value
  type-confusion matrix, result-is-never--0, arity, and `xorN` coverage.
