# A paradigm cell no source prints is hedged in the lesson, never claimed sourced in the docs

The Marwadi A2 core had a sourcing rule: teach only forms that a CDIAL
Marwari or Old Marwari row, or the track's own text, prints. Its changelog
and roadmap said every taught cell met that rule. The independent review
checked each cell against its row and found several that no source prints:

- the first-person present **-ूं** (CDIAL 5593 shows *-uṁ* only in the
  future, *ḍhoḷisuṁ* "I will fan");
- **म्हैं** with a past that agrees with the object (CDIAL 9691 gives *mẽ*
  "I" and nothing about agreement);
- the feminine **ली**;
- the feminine **की** of **कियो**.

The example **म्हैं बात की।** was the Hindi sentence *bāt kī* with a
Marwari pronoun. **की** is also the Hindi genitive, which the tranche
builder refuses. The builder's own table of irregular pasts gave **करी**
as the feminine.

The fix had three parts. The review removed **की** and paired **कियो** with
a masculine thing only. It hedged the other cells in the lesson as "central
Marwari as this book writes it; other districts differ". It reworded the
changelog, roadmap and README so they no longer said every cell was sourced.

Do differently: write the source table cell by cell before writing the
docs. Check each cell's gloss and its tense. A row for the future does not
source the present. Where no row or track text prints a cell, put the hedge
in the lesson that teaches it. When a builder or checker already has a
table of the language's forms, compare the lessons against it. A mismatch
there is the cheapest warning you will get.
