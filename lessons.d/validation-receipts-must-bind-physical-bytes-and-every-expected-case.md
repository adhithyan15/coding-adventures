# Validation receipts must bind physical bytes and every expected case

Independent preflight caught two gaps before the native31 helpers executed.
The first red gate accepted any compiled failure containing a refusal phrase;
an early assertion could therefore hide unexecuted source rows or guard cases.
It now requires the exact five-function result, all342 planned refusal IDs,
all12 post-assertion guard markers, four complete attempt summaries and the
actual library/source/executable join. A source failure is not build success.

The test writer also hashed its generated LF bytes but proposed write_text
with Windows' default newline translation. That would produce CRLF bytes and
fail the new physical hash gate before Cargo. Write the already-hashed UTF8
bytes directly, preserving all proposals before mutation and the old library's
exact module-registration inverse. Pin the test body, prior receipt, explicit
input additions/removals and helper as well. Keep the unexecuted preflight
WITHHELD record; these corrections do not turn it into a successful execution.

The native31 green-v1 helper was withheld before execution: an unpinned
append receipt or fixture, name-only binary join and unspecified selected-target
census could overstate evidence. Pin the reviewed objects, exact target source/
kind and shared runtime executable bytes, and whitelist typed status labels.
Keep selected library coverage distinct from a full reverse integration suite.

A native31 docs carrier passed tooling but static review withheld its stale
top-of-backlog "current" attribution. Put the latest execution and pending
work first and explicitly label older README/status prose historical.
Appending a new result at EOF does not update the current resume frame.

The unexecuted native31 publisher-v1 preflight was also withheld. A sole open
PR is insufficient authorization: bind the authorized PR identity and discover
its current head/ref. Check every configured fetch and push URL, and rehash
physical source, ignored locks, runtime logs and executable inputs before and
after publication. Save each command's raw output and actual exit before
decoding or parsing it, including post-push observations; otherwise a parse
failure can erase evidence of an action that already happened. The reviewed
publisher-v2 separately executed successfully. Preserve v1 as unexecuted and
WITHHELD rather than transferring v2 acceptance backward.
