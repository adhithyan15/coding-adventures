## 0.3.0 - S3d: `accept_blind`, `--expect-generator`, the committed ct-compare v2 fixture

### Added

- `corpus.profile` line `accept_blind <op> <fault>` (owner decision [D15], VER04r 16.8),
  mirroring the generator: the reader checks that the line repeats a `fault` line and does not
  repeat itself; `derive_controls` lets an all-blind fault pass when named (the control row has an
  empty `required_claims`, `slim_witness` is `[]`) and records its control id in
  `accepted_blind_faults`, sorted by bytes; naming a fault a claim can see is a `corpus` error.
  `derive_controls` now returns a fourth value, the accepted ids.
- `verify-v2 --expect-generator name@version` (owner decision [D13]): the recorded `generator`
  must equal the pair, else a `header` difference at `generator`. A malformed value is exit 2.
- `tests/test_accept_blind.py` and the small synthetic fixture `tests/fixtures/accept-blind-v2/`
  (written by the Rust generator, regenerated byte for byte by its tests). `verify-v2` of the
  committed `code/specs/fixtures/ct-compare-warrant-v2/` is a test and a BUILD line.
- BUILD and BUILD_windows: `verify-v2` on the accept-blind fixture and on the committed
  ct-compare v2 fixture with `--profile <fixture>/corpus.profile` ([D14]), `--bindings` and
  `--expect-generator warrant-corpus-gen@0.4.0`.

### Changed

- `accepted_blind_faults` is no longer always `[]`; a corpus that lists one the profile does not
  accept (or omits one it does) fails in the `controls` group.
- The generator's reader now refuses whitespace-only profile lines too (the erratum of VER04r 16.7
  item 3 is closed); this oracle's reader already did.
