# Choose generic preprocessor work from the first consumers rather than the distant C horizon

Repeated PREP01 selections advanced small C-specific stages while the first
consumer priority was MacroNib and MacroOct. The user corrected the scheduling:
C is a long-term horizon, and Ruby and JavaScript must remain explicit native
execution backlog streams alongside Python and Perl.

Keep the already published C slice as existing work, but select the next
generic-engine item from a demonstrated MacroNib or MacroOct need. Preserve
their identity proofs against hand-expanded Nib/Oct and their distinct dialect
syntax. Record this ordering in both the spec/backlog and heartbeat scheduler
so old checkpoint descriptions do not silently select another C slice.

Audit shared documentation and transitive dependencies before publication.
Changing the priority does not remove existing completion evidence, authorize
overlapping writes or put Semantic IR in native dynamic-language execution.

A scope lookup also passed a wildcard directory as a ripgrep path on Windows;
the command reported an invalid path. Search an existing directory with a glob
filter instead, and do not count a failed lookup as evidence of absent files.

The temporary overlap auditor initially used its Python grammar fallback for
the C package. Extend its resource inputs to C, Ruby and Twig grammars before
claiming that closure audit. A quoted inline Python replacement then failed
PowerShell parsing without changing files; a direct patch corrected the helper.
