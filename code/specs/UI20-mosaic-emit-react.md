# UI20 — mosaic-emit-react: React JSX Backend

**Status:** Implemented (retroactive spec)  
**Layer:** UI  
**Depends on:** UI01 (mosaic-vm), UI00 (mosaic-analyzer)

---

## 1. Purpose

`mosaic-emit-react` is the React JSX backend for the Mosaic compiler. It
implements the `MosaicRenderer` trait (from `mosaic-vm`) and is driven by
`MosaicVM`. The output is a TypeScript file (`.tsx`) containing a single React
functional component ready for use in any React 18+ application.

The component is **type-safe**: slot definitions become a TypeScript
`interface ComponentProps {}` and the component signature is fully typed. Slot
references in JSX are resolved by prop access rather than by string interpolation,
giving the TypeScript compiler full visibility into every data flow.

```text
.mosaic source
     │
     ▼
mosaic-analyzer  →  MosaicFile (IR)
     │
     ▼
MosaicVM  (drives MosaicRenderer callbacks)
     │
     ▼
ReactRenderer  →  ComponentName.tsx
```

The generated file has **zero runtime dependencies** beyond React itself — no
Mosaic runtime is shipped to the browser.

## 2. Output Structure

```tsx
// Auto-generated by mosaic-emit-react. Do not edit.
import React from "react";

interface ProfileCardProps {
  avatarUrl: string;      // image slot → string (URL)
  displayName: string;   // text slot → string
  count: number;          // number slot → number
  visible: boolean;       // bool slot → boolean
  items: Array<string>;   // list<text> slot → Array<string>
  body?: React.ReactNode; // node slot → React.ReactNode (optional)
}

export function ProfileCard({
  avatarUrl,
  displayName,
  count,
  visible,
  items,
  body,
}: ProfileCardProps) {
  return (
    <div style={{ display: "flex", flexDirection: "column" }}>
      <img src={avatarUrl} alt={displayName} />
      <span>{displayName}</span>
      {visible && (
        <>
          <span>{count}</span>
        </>
      )}
      {items.map((item, _idx) => (
        <React.Fragment key={_idx}>
          <span>{item}</span>
        </React.Fragment>
      ))}
      {body}
    </div>
  );
}
```

Key structural invariants:

1. The `import React from "react"` line is always the first non-comment line.
2. The `interface` is always emitted, even for zero-slot components
   (`interface ComponentProps {}`).
3. The `export function` declaration always follows the `interface`.
4. The return statement wraps all top-level JSX in a single root element; if the
   root Mosaic node is already a single container, it is used directly — no
   unnecessary wrapping `<>` fragment is added.

## 3. Architecture

### 3.1 `ReactRenderer` struct

```rust
pub struct ReactRenderer {
    component_name: String,
    slots: Vec<MosaicSlot>,
    /// Stack of open JSX frames during depth-first traversal.
    ///
    /// When `begin_node` is called, a new `JsxFrame` is pushed.
    /// When `end_node` is called, the frame is popped, its children are
    /// wrapped with the opening/closing tags, and the result is appended
    /// to the parent frame's `children` list (or to `root_lines` if the
    /// stack becomes empty).
    stack: Vec<JsxFrame>,
    /// JSX lines accumulated at the root level.
    root_lines: Vec<String>,
}
```

Each `JsxFrame` records the element being built:

```rust
struct JsxFrame {
    /// The opening JSX tag string, e.g. `<div style={{ display: "flex" }}>`.
    open_tag: String,
    /// The self-closing tag if this element has no children, e.g. `<img … />`.
    self_closing: Option<String>,
    /// Child JSX strings accumulated while this frame is on the stack.
    children: Vec<String>,
    /// The closing tag, e.g. `</div>`.
    close_tag: String,
}
```

The stack-based approach guarantees correct nesting regardless of how deeply the
Mosaic node tree is nested. A frame is created for every `begin_node` call and
destroyed by the matching `end_node` call — the VM guarantees these are balanced.

### 3.2 camelCase conversion

Mosaic slot names use kebab-case. React props use camelCase. The renderer
converts every slot name on first use:

```rust
/// "avatar-url" → "avatarUrl", "display-name" → "displayName".
fn to_camel_case(kebab: &str) -> String { … }
```

This conversion is applied to:

- `interface` property names.
- Destructured parameter names in the function signature.
- JSX expression `{propName}` slot references.

### 3.3 `is_safe_js_identifier()` validation

Before embedding any slot-ref name into JSX output, the renderer calls:

```rust
fn is_safe_js_identifier(name: &str) -> bool {
    let mut chars = name.chars();
    chars.next().map_or(false, |c| c.is_ascii_alphabetic() || c == '_')
        && chars.all(|c| c.is_ascii_alphanumeric() || c == '_')
}
```

If this check fails, `emit()` returns `Err("unsafe slot ref name: …")`. This
prevents code injection via crafted slot names such as `"};alert(1);//"`.

## 4. Node → JSX Mapping

| Mosaic node | JSX output |
|-------------|-----------|
| `Box`       | `<div>` |
| `Column`    | `<div style={{ display: "flex", flexDirection: "column" }}>` |
| `Row`       | `<div style={{ display: "flex", flexDirection: "row" }}>` |
| `Text`      | `<span>{content}</span>` (content text as child) |
| `Image`     | `<img src={…} alt={…} />` (self-closing) |
| `Spacer`    | `<div style={{ flex: 1 }}>` |
| `Scroll`    | `<div style={{ overflow: "auto" }}>` |
| `Divider`   | `<hr />` (self-closing) |
| `Stack`     | `<div style={{ position: "relative" }}>` |
| `Icon`      | `<span className="icon">` |
| `Grid`      | `<table>` with `.map()` header and row rendering (see §5) |

### 4.1 Inline styles

React requires style objects, not CSS strings. Properties that map to CSS are
emitted as object literals:

```tsx
// Column
<div style={{ display: "flex", flexDirection: "column" }}>

// custom padding from a Mosaic prop
<div style={{ display: "flex", flexDirection: "row", padding: "8px" }}>
```

Non-style props (accessibility, data attributes) are emitted as plain JSX
attributes: `aria-label={…}`, `role="…"`, `data-testid="…"`.

## 5. Grid Rendering

`Grid` emits a full `<table>` with its header and row content driven by
the `headers` and `rows` slot props:

```tsx
<table>
  <thead>
    <tr>{headers.map((h, _idx) => <th key={_idx}>{h}</th>)}</tr>
  </thead>
  <tbody>
    {rows.map((r, _idx) => (
      <tr key={_idx}>
        <td>{r}</td>
      </tr>
    ))}
  </tbody>
</table>
```

React requires a `key` prop on every element produced inside a `.map()` call. The
renderer uses the iteration index `_idx` (underscore-prefixed to silence the
"unused variable" TypeScript warning) as the key value.

## 6. Slot → TypeScript Type Mapping

| Mosaic slot type | TypeScript type |
|-----------------|----------------|
| `text`          | `string` |
| `number`        | `number` |
| `bool`          | `boolean` |
| `image`         | `string` (URL as a string) |
| `color`         | `string` (CSS color string) |
| `list<text>`    | `Array<string>` |
| `list<number>`  | `Array<number>` |
| `list<bool>`    | `Array<boolean>` |
| `list<T>`       | `Array<T>` (recursively resolved) |
| `node`          | `React.ReactNode` |
| `Component(X)`  | `React.ReactNode` (until strongly-typed components are in scope) |

`node` and `Component(_)` slots are emitted as **optional** (`body?:
React.ReactNode`) because they can be legally omitted by a parent that has no
child to slot in:

```tsx
interface CardProps {
  title: string;
  body?: React.ReactNode;  // ← optional
}
```

All other slot types are **required** (no `?`) unless the Mosaic slot declaration
carries an explicit `optional` modifier.

## 7. Control Flow

### 7.1 `when @slot` — conditional rendering

```
when @visible {
  Text { content: "Hello"; }
}
```

Emits:

```tsx
{visible && (
  <>
    <span>Hello</span>
  </>
)}
```

The `&&` short-circuit pattern is the idiomatic React way to conditionally render.
A React Fragment (`<>…</>`) wraps the body so that multi-child bodies are valid
JSX without adding an extra DOM element.

### 7.2 `each @items as item` — list rendering

```
each @items as item {
  Text { content: @item; }
}
```

Emits:

```tsx
{items.map((item, _idx) => (
  <React.Fragment key={_idx}>
    <span>{item}</span>
  </React.Fragment>
))}
```

Inside an `each` body, slot references that match the loop variable name (`item`)
are resolved to bare `{item}` — no `props.` or component-prop access. This
distinction is tracked by a `loop_vars: Vec<String>` field on `ReactRenderer`
that is pushed/popped alongside the `each` open/close callbacks.

## 8. Security

### 8.1 `is_safe_js_identifier()` — prevents code injection

Every slot-ref name that will be embedded as a JSX expression (`{propName}`) is
validated by `is_safe_js_identifier()` before output is produced. If validation
fails, `emit()` returns an `Err`. This guards against slot names containing
characters that would break out of the JSX expression context.

### 8.2 String literal escaping

Mosaic prop values that are string literals are embedded inside JSX attribute
strings. Backslashes and double-quotes are escaped to prevent unterminated string
attacks:

```rust
fn escape_jsx_string(s: &str) -> String {
    s.replace('\\', "\\\\").replace('"', "\\\"")
}
```

This escaping is separate from React's own runtime XSS protection. The goal here
is source-file integrity — the generated `.tsx` must be syntactically valid even
when Mosaic source contains unusual string literals.

## 9. Package

**Crate name:** `mosaic-emit-react`  
**Version:** 0.1.0  
**Language:** Rust  
**Public API:**

```rust
pub struct ReactRenderer { … }

impl MosaicRenderer for ReactRenderer {
    fn begin_component(&mut self, name: &str, slots: &[MosaicSlot]);
    fn begin_node(&mut self, tag: &str, is_primitive: bool, props: &[(String, ResolvedValue)]);
    fn end_node(&mut self, tag: &str);
    fn end_component(&mut self);
    fn emit(self) -> EmitResult;
}

impl ReactRenderer {
    pub fn new() -> Self;
}
```

The `emit()` method returns `EmitResult { output: String, component_name: String }`,
identical to other backends, so that `MosaicVM` can handle all backends uniformly.

## 10. Testing Strategy

Each test calls `analyze(src)` → `MosaicVM::new(file)` → `vm.run(ReactRenderer::new())` →
asserts on the resulting `output` string.

| Test | What it covers |
|------|----------------|
| `test_import_react` | Output starts with `import React from "react"` |
| `test_interface_emitted` | `interface ComponentProps` present |
| `test_export_function` | `export function ComponentName` present |
| `test_text_slot_string_type` | `text` slot → `string` in interface |
| `test_number_slot_number_type` | `number` slot → `number` in interface |
| `test_bool_slot_boolean_type` | `bool` slot → `boolean` in interface |
| `test_image_slot_string_type` | `image` slot → `string` in interface |
| `test_list_slot_array_type` | `list<text>` slot → `Array<string>` in interface |
| `test_node_slot_react_node` | `node` slot → `React.ReactNode` and is optional |
| `test_column_flex_column` | Column → `flexDirection: "column"` |
| `test_row_flex_row` | Row → `flexDirection: "row"` |
| `test_spacer_flex_1` | Spacer → `flex: 1` |
| `test_divider_self_closing` | Divider → `<hr />` |
| `test_when_and_operator` | `when @slot` → `{slot && (<>…</>)}` |
| `test_each_map_call` | `each @items as item` → `items.map(…)` |
| `test_safe_identifier_validation` | Unsafe slot name → `Err(…)` |
