# A long list of examples reads as proof that someone checked, and the length is what stops you checking

`HI-A1-SCR-16` was called the sharpest finding in the Hindi exam inventory, and
its note argued the case with fourteen words: *shukriya, khushi, zarur, safed,
darvaza, mez, sabzi, zyada, safar, tohfa, bukhar, fasal, khushbu, mulaqat*.
Thirteen of them carry the nuqta. **The first one does not.** शुक्रिया is
श + ु + क् + र + ि + य + ा, with no U+093C anywhere in it.

**The list was the reason nobody looked.** A claim backed by two examples invites
a spot check. A claim backed by fourteen reads as already audited — the writer
evidently went through the corpus, so why repeat their work. The length did the
persuading, and the lead item was the one that got the least scrutiny because it
was read first, before the reader had decided to be careful.

This is the sibling of the lesson that a note can be precise about the grammar
and wrong about the vocabulary. That one is about the claim. This one is about
**the evidence offered for the claim**, which no gate reads and no test pins.

**What to do instead.** When a note's examples matter to what you are about to
build, count them against the corpus rather than reading them. It is one script:
extract the list, grep each item for the feature the note says it has, print the
misses. Doing that here took under a minute, replaced fourteen recalled examples
with a counted thirty-six, and turned a vague "the corpus is full of them" into a
per-carrier table that decided how many lessons the work needed.

**The tell:** a list long enough that you would not read it all is long enough
that its author probably did not either.
