# UI24 — Mosaic emit→dispatch: Flux Event Union for All Backends

**Status:** Specified  
**Layer:** UI  
**Depends on:** UI13 (mosmodel), UI20 (mosaic-emit-react), UI01 (mosaic-vm)  
**Implemented in:** `mosaic-emit-react`, `mosaic-analyzer`, `mosaic-vm`

---

## §1 Purpose

The original React backend (UI20) generated one callback prop per `emit`
declaration:

```tsx
// BEFORE (UI20 style)
interface GridProps {
  columnHeaders: string[];
  onNavigate?: (row: number, col: number) => void;
  onEditCommit?: (value: string) => void;
  onEditCancel?: () => void;
}
```

This approach has several problems:

1. **N closures, N capture chains.** The host must create and pass N separate
   callback objects, each of which may capture state independently.
2. **No single event log.** You cannot record all events fired by a component
   without wrapping every individual callback.
3. **Optional props create optional handling.** TypeScript allows the host to
   skip an `onNavigate?` entirely; there is no compile-time guarantee all
   events are handled.
4. **Non-uniform shape.** A HOC that intercepts events has to know every
   callback name; wrapping becomes a brittle allowlist.

The **Flux/Redux architecture** solves all four problems. Components fire
typed, discriminated-union events through a single `dispatch` prop. The host
uses `useReducer`. This is the idiomatic React pattern for complex stateful
components.

```tsx
// AFTER (UI24 style)
type GridEvent =
  | { type: "navigate"; row: number; col: number }
  | { type: "editCommit"; value: string }
  | { type: "editCancel" };

interface GridProps {
  columnHeaders: string[];
  dispatch: (event: GridEvent) => void;   // always required
}
```

Benefits:
- **Single event handler** — the host passes one `useReducer` dispatch, not N
  closures.
- **Type-safe discriminated union** — TypeScript's exhaustive `switch` works.
- **Testable** — record events as data, replay them in unit tests.
- **Uniform** — all backends use the same logical pattern (different
  platform-specific implementations; see §4).
- **Required** — no optional `?` on dispatch; the host is always forced to
  handle the full event surface.

## §2 mosmodel Emit Syntax — Unchanged

The `.mil` and `.mosaic` source syntax does **not** change. The emit declaration
grammar remains exactly as specified in UI13:

```mosmodel
emit onNavigate ( row : number , col : number ) ;
emit onEditCancel ;
```

`emit` is a keyword. Void emits (no parameters) are valid. Payload parameter
names use kebab-case. This is a **backend-emitter change only** — no source
files need to be modified.

### Emit declaration in `.mosaic` files

In `.mosaic` layout source files (the format consumed by the Mosaic compiler
pipeline), emit declarations appear inside the component block before the
visual tree:

```mosaic
component Grid {
  slot column-headers : list<text> ;
  slot total-rows     : number ;

  emit onNavigate  ( row : number , col : number ) ;
  emit onEditStart ( row : number , col : number ) ;
  emit onEditCommit ( value : text ) ;
  emit onEditCancel ;
  emit onScroll ( offset : number ) ;
  emit onSelect ( start-row : number , start-col : number ,
                  end-row : number , end-col : number ) ;

  Grid {
    headers: @column-headers;
    rows:    @viewport-rows;
  }
}
```

The analyzer stores emits in `MosaicComponent.emits: Vec<MosaicEmit>`. The VM
passes them to backends via `begin_component(name, slots, emits)`.

## §3 React Backend — New Output Format

### §3.1 Complete Generated Output

For a `Grid` component with 6 emits:

```tsx
// Auto-generated by mosaic-emit-react. Do not edit.
import React from "react";

// Discriminated union of all events this component can fire.
// Use in your host reducer: switch (event.type) { case "navigate": ... }
type GridEvent =
  | { type: "navigate"; row: number; col: number }
  | { type: "editStart"; row: number; col: number }
  | { type: "editCommit"; value: string }
  | { type: "editCancel" }
  | { type: "scroll"; offset: number }
  | { type: "select"; startRow: number; startCol: number; endRow: number; endCol: number };

interface GridProps {
  columnHeaders: string[];
  totalRows: number;
  dispatch: (event: GridEvent) => void;
}

export function Grid({ columnHeaders, totalRows, dispatch }: GridProps) {
  return (
    <table>
      {/* ... */}
    </table>
  );
}
```

### §3.2 Key Rules

| Rule | Detail |
|------|--------|
| Union type name | `{ComponentName}Event` (e.g. `GridEvent`, `ButtonEvent`) |
| `type` field conversion | Strip `on` prefix, camelCase remainder (§5) |
| Param name conversion | kebab-case → camelCase (same as slot names) |
| Param type mapping | `text` → `string`, `number` → `number`, `bool` → `boolean`, `color` → `string` |
| `dispatch` optionality | Always **required** — no `?` |
| `dispatch` position | Always the **last** entry in the `interface` |
| Union type position | Emitted **before** the `interface` |
| Zero emits | `type ButtonEvent = never;` + `dispatch: (event: ButtonEvent) => void;` (§6) |

## §4 Backend Mapping Table

Different backends express the same event-dispatch pattern using their
platform's native idioms.

| Backend | Mechanism | Notes |
|---------|-----------|-------|
| **React (TSX)** | `type XEvent = \| { type: "..." } \| ...`; `dispatch: (e: XEvent) => void` prop | Flux/useReducer — this spec |
| **WebComponent (JS)** | `this.dispatchEvent(new CustomEvent(type, { detail: payload, bubbles: true, composed: true }))` | Standard DOM event bus; type field = camelCase event name |
| **HTML (static)** | No-op — emits not rendered | Events require a JS runtime; static snapshots omit them |
| **paint-vm** | Per-emit closure stored in renderer state; called when widget fires | Already closure-based; no union type needed |
| **Qt (future)** | `Q_SIGNAL void navigated(int row, int col);` — one Qt signal per emit | Qt's native signal/slot system |
| **SwiftUI (future)** | `var dispatch: (XEvent) -> Void` — same union pattern as React | Swift `enum` as the discriminated union |
| **Jetpack Compose (future)** | `sealed class XEvent { data class Navigate(...): XEvent() }; onEvent: (XEvent) -> Unit` | Same Flux pattern, Kotlin sealed classes |
| **XAML/WinUI3 (future)** | `event EventHandler<XEventArgs> Navigate;` — one .NET event per emit | .NET event model; no union type |

## §5 Emit Name → type Field Conversion

The `type` field string is derived from the emit declaration name using a
two-step algorithm:

### Step 1 — Strip the `on` prefix

Remove the leading `on` (case-insensitive match):

| Emit name | After strip |
|-----------|-------------|
| `onNavigate` | `Navigate` |
| `onClick` | `Click` |
| `onEditCommit` | `EditCommit` |
| `onEditCancel` | `EditCancel` |
| `onScroll` | `Scroll` |
| `onSelect` | `Select` |
| `onEditStart` | `EditStart` |

### Step 2 — Convert to camelCase

Lower-case the first character of the stripped result, then leave the rest
as-is (it is already PascalCase):

| After strip | `type` field |
|-------------|-------------|
| `Navigate` | `"navigate"` |
| `Click` | `"click"` |
| `EditCommit` | `"editCommit"` |
| `EditCancel` | `"editCancel"` |
| `Scroll` | `"scroll"` |
| `Select` | `"select"` |
| `EditStart` | `"editStart"` |

### Algorithm in Rust pseudo-code

```rust
fn emit_name_to_type_field(emit_name: &str) -> String {
    // Step 1: strip "on" prefix (case-insensitive).
    let stripped = if emit_name.to_lowercase().starts_with("on") {
        &emit_name[2..]
    } else {
        emit_name
    };
    // Step 2: lower-case first char, preserve rest.
    let mut chars = stripped.chars();
    match chars.next() {
        None => String::new(),
        Some(first) => {
            let lower_first = first.to_lowercase().to_string();
            lower_first + chars.as_str()
        }
    }
}
```

### Full Grid example

```
onNavigate   → "navigate"
onEditStart  → "editStart"
onEditCommit → "editCommit"
onEditCancel → "editCancel"
onScroll     → "scroll"
onSelect     → "select"
```

## §6 Zero-Emit Components

Components with no emit declarations still get the union type and dispatch
prop, with `never` as the union:

```tsx
// Auto-generated by mosaic-emit-react. Do not edit.
import React from "react";

type ButtonEvent = never;

interface ButtonProps {
  label: string;
  disabled: boolean;
  dispatch: (event: ButtonEvent) => void;
}

export function Button({ label, disabled, dispatch }: ButtonProps) {
  return (
    <span>{label}</span>
  );
}
```

**Rationale:** uniform interface — the host always passes a `dispatch` prop,
even if it never fires. This makes HOC wrappers and prop-spreading simpler
because there is no conditional `dispatch?` to handle.

```tsx
// HOC pattern works uniformly for all components:
function withLogging<E>(Component: React.ComponentType<{ dispatch: (e: E) => void }>) {
  return function Wrapped({ dispatch, ...rest }: { dispatch: (e: E) => void }) {
    const loggingDispatch = (e: E) => {
      console.log("event:", e);
      dispatch(e);
    };
    return <Component dispatch={loggingDispatch} {...rest} />;
  };
}
```

## §7 Host Usage Pattern

Complete host-side example using `useReducer`:

```tsx
import { useReducer } from "react";
import { Grid, GridEvent } from "./Grid";

// Application state owned entirely by the host.
type AppState = {
  selectedRow: number;
  selectedCol: number;
  editRow: number;
  editCol: number;
  pendingEdit: string;
};

// The host can combine GridEvent with its own actions.
type AppAction = GridEvent | { type: "resetSelection" };

const initialState: AppState = {
  selectedRow: 0,
  selectedCol: 0,
  editRow: -1,
  editCol: -1,
  pendingEdit: "",
};

function reducer(state: AppState, action: AppAction): AppState {
  switch (action.type) {
    case "navigate":
      return { ...state, selectedRow: action.row, selectedCol: action.col };
    case "editStart":
      return { ...state, editRow: action.row, editCol: action.col };
    case "editCommit":
      // Commit the pending value; clear edit state.
      return { ...state, pendingEdit: action.value, editRow: -1, editCol: -1 };
    case "editCancel":
      return { ...state, editRow: -1, editCol: -1, pendingEdit: "" };
    case "scroll":
      // Trigger a viewport-rows re-fetch at the new offset.
      return state; // side-effect handled outside reducer
    case "select":
      return { ...state, selectedRow: action.startRow, selectedCol: action.startCol };
    case "resetSelection":
      return { ...state, selectedRow: 0, selectedCol: 0 };
    default:
      return state;
  }
}

export function App() {
  const [state, dispatch] = useReducer(reducer, initialState);

  return (
    <Grid
      columnHeaders={["Name", "Value", "Type"]}
      totalRows={100}
      dispatch={dispatch}
    />
  );
}
```

**Why `useReducer`?** It enforces a single source of truth for component
state, matches the discriminated-union type exactly, and makes the reducer
testable in isolation — pass events, assert new state.

## §8 Security

### §8.1 Type field injection prevention

The `type` field string embedded in the generated TypeScript code comes
entirely from the emit declaration name in the `.mosaic`/`.mil` source — it
is **not** supplied by the end user at runtime. The same `is_safe_js_identifier()`
validation that guards slot names (UI20 §8.1) also guards emit names:

```rust
/// Returns true if `s` is a valid JavaScript identifier.
fn is_safe_js_identifier(s: &str) -> bool {
    let mut chars = s.chars();
    match chars.next() {
        None => false,
        Some(c) => {
            (c.is_alphabetic() || c == '_' || c == '$')
                && chars.all(|c| c.is_alphanumeric() || c == '_' || c == '$')
        }
    }
}
```

If `is_safe_js_identifier` returns `false` for an emit name or any emit
parameter name, `emit()` returns `Err("unsafe emit name: …")`. This prevents
template-injection attacks via crafted component source.

### §8.2 No new runtime surface

The `dispatch` prop is a function reference passed by the host — it introduces
no new injection surface beyond what already exists in the slot API. The
generated component code calls `dispatch(...)` with a struct literal; the
values in that literal come from the component's internal state (slot values
and local variables), not from external string input.

## §9 Migration from Callback Props

Since the change is entirely in the **backend emitter**, no `.mosaic` or `.mil`
source files need to change. Only the generated output and host code that
consumed the generated callbacks need updating.

### Before (UI20 callback style)

```tsx
// Generated output (old):
interface GridProps {
  columnHeaders: string[];
  onNavigate?: (row: number, col: number) => void;
  onEditCommit?: (value: string) => void;
  onEditCancel?: () => void;
}

// Host usage (old):
<Grid
  columnHeaders={headers}
  onNavigate={(row, col) => dispatch({ type: "navigate", row, col })}
  onEditCommit={(value) => dispatch({ type: "editCommit", value })}
  onEditCancel={() => dispatch({ type: "editCancel" })}
/>
```

### After (UI24 dispatch style)

```tsx
// Generated output (new):
type GridEvent =
  | { type: "navigate"; row: number; col: number }
  | { type: "editCommit"; value: string }
  | { type: "editCancel" };

interface GridProps {
  columnHeaders: string[];
  dispatch: (event: GridEvent) => void;
}

// Host usage (new):
<Grid
  columnHeaders={headers}
  dispatch={dispatch}   // one prop instead of three
/>
```

The host code that previously built closures for each callback now passes the
`useReducer` dispatch directly. The reducer handles the discriminated union
cases — the same logic that was previously inline in each callback.

Tests for the new behavior live in `mosaic-emit-react`. Each test exercises
one invariant of the generated TypeScript output.

| Test | What it covers |
|------|---------------|
| `test_event_union_type_emitted` | Component with emits generates `type XEvent = \| ...` |
| `test_dispatch_prop_in_interface` | `dispatch: (event: XEvent) => void` appears in interface |
| `test_emit_type_field_conversion` | `onNavigate` → `{ type: "navigate"; ... }` |
| `test_zero_emit_component` | No emits → `type XEvent = never` + dispatch still present |
| `test_void_emit_variant` | `emit onEditCancel;` → `{ type: "editCancel" }` (no extra fields) |
| `test_multi_param_emit` | `emit onSelect(start-row: number, ...)` → all params in union variant |
| `test_dispatch_required` | `dispatch` has no `?` — it is always required |
| `test_union_before_interface` | The `type XEvent = ...` line appears before `interface` |
| `test_param_kebab_to_camel` | `start-row: number` → `startRow: number` in union variant |

## §11 IR Changes

This spec introduces three new types in `mosaic-analyzer`:

```rust
/// A typed emit declaration in a `.mosaic` component.
#[derive(Debug, Clone, PartialEq)]
pub struct MosaicEmit {
    /// camelCase name with `on` prefix, e.g. `onClick`, `onNavigate`.
    pub name: String,
    /// Payload parameters. Empty = void emit.
    pub params: Vec<MosaicEmitParam>,
}

/// A parameter carried by an emit's payload.
#[derive(Debug, Clone, PartialEq)]
pub struct MosaicEmitParam {
    /// kebab-case parameter name, e.g. `row`, `start-col`.
    pub name: String,
    /// The parameter type (same vocabulary as slot types).
    pub param_type: MosaicType,
}
```

`MosaicComponent.emits: Vec<MosaicEmit>` stores all emit declarations
found in the source. Backends access emits via `begin_component(name, slots,
emits)` — the third argument is new.

### MosaicRenderer trait change

```rust
pub trait MosaicRenderer {
    // CHANGED: added `emits` parameter.
    fn begin_component(&mut self, name: &str, slots: &[MosaicSlot], emits: &[MosaicEmit]);
    // ... (all other methods unchanged) ...
}
```

All existing backends must be updated to accept the new `emits` parameter in
their `begin_component` implementation, even if they ignore it.

## §12 Grammar Changes

To support `emit` declarations in `.mosaic` source files, two grammar layers
require updates:

### §12.1 Lexer (`mosaic-lexer`)

Add `emit` to the KEYWORD list:

```
keywords: ["component", "slot", "emit", "import", "from", "as",
           "text", "number", "bool", "image", "color", "node",
           "list", "true", "false", "when", "each"]
```

### §12.2 Parser (`mosaic-parser`)

Add `emit_decl` and `emit_param` rules. Update `component_decl` to allow
zero or more emit declarations after slots:

```
component_decl = KEYWORD NAME LBRACE
                 { slot_decl }
                 { emit_decl }
                 node_tree
                 RBRACE ;

emit_decl = KEYWORD NAME [ LPAREN emit_param { COMMA emit_param } RPAREN ] SEMICOLON ;
emit_param = NAME COLON slot_type ;
```

Since the grammar files are pre-compiled into `_grammar.rs`, both
`mosaic-lexer/src/_grammar.rs` and `mosaic-parser/src/_grammar.rs` must be
updated inline.

## §13 Divergence from UI20

This spec supersedes the emit-handling section of UI20. Specifically:

- UI20 §9 showed `begin_component(name, slots)` — this is now
  `begin_component(name, slots, emits)`.
- UI20 had no emit → TypeScript output mapping — this spec adds the full
  mapping (§3, §5).
- The generated `interface` no longer has per-emit callback props. All emit
  handling is consolidated into the `dispatch` prop.

UI20 is updated with a cross-reference to this spec.
