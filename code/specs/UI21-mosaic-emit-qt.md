# UI21 — mosaic-emit-qt: Qt/QML Backend

**Status:** Planned  
**Layer:** UI  
**Depends on:** UI01 (mosaic-vm), UI00 (mosaic-analyzer)

---

## 1. Purpose

`mosaic-emit-qt` is a **two-phase** Qt backend for the Mosaic compiler:

- **Phase A — QML code generation:** A `MosaicRenderer` implementation that
  produces a `.qml` file describing the component's visual structure using Qt's
  declarative UI language. The `.qml` file can be loaded by any Qt 6 application
  or toolchain (Qt Creator, qmlscene, etc.) without modification.

- **Phase B — Headless render daemon:** A standalone process called
  `mosaicbook-qt-daemon` that accepts Mosaic source over a Unix domain socket,
  renders each component offscreen using `QQuickView` + `QOffscreenSurface`, and
  returns PNG bytes. This daemon is how MosaicBook (UI19) produces Qt preview
  images without running a full display server.

```text
Phase A — code generation:

.mosaic source
     │
     ▼
mosaic-analyzer  →  MosaicFile (IR)
     │
     ▼
MosaicVM  (drives MosaicRenderer callbacks)
     │
     ▼
QmlRenderer  →  ComponentName.qml


Phase B — headless render daemon:

mosaicbook-server
     │  Unix domain socket (/tmp/mosaicbook-qt.sock)
     ▼
mosaicbook-qt-daemon
     │
     ├──  mosaic-analyzer  →  MosaicFile
     ├──  QmlRenderer      →  QML string
     ├──  QQmlEngine + QQuickView (offscreen)
     └──  PNG bytes  →  JSON response
```

These two phases are complementary. Phase A gives developers a portable `.qml`
artefact that integrates with Qt tooling. Phase B gives MosaicBook a raster
preview without requiring the developer to own a Qt SDK installation on the
machine running the browser UI.

## 2. Phase A — QML Code Generation

### 2.1 Output Structure

A complete `.qml` file for a `ProfileCard` component:

```qml
// Auto-generated by mosaic-emit-qt. Do not edit.
import QtQuick 2.15
import QtQuick.Layouts 1.15

Item {
    id: root

    // Slot properties — set by the parent component or engine.
    property string avatarUrl: ""
    property string displayName: ""
    property int    count: 0
    property bool   visible_: false   // 'visible' is a built-in; trailing _ avoids collision
    property var    items: []         // list<text> → var (dynamic QML array)

    ColumnLayout {
        anchors.fill: parent

        Image {
            source: root.avatarUrl
            Layout.fillWidth: true
        }

        Text {
            text: root.displayName
        }

        Item {
            visible: root.visible_

            Text {
                text: root.count
            }
        }

        Repeater {
            model: root.items
            delegate: Text {
                text: modelData
            }
        }
    }
}
```

Key structural invariants:

1. The first two lines are always `import QtQuick 2.15` and
   `import QtQuick.Layouts 1.15`.
2. The top-level element is always `Item { id: root … }`.
3. All slot properties are declared at the `Item` level with a `property`
   declaration and a type-appropriate initial value.
4. The component body is a child of `root`, not a sibling.

### 2.2 Node → QML Element Mapping

| Mosaic node | QML element | Notes |
|-------------|-------------|-------|
| `Box`       | `Item { anchors.fill: parent }` | Generic container |
| `Column`    | `ColumnLayout { anchors.fill: parent }` | Vertical stack |
| `Row`       | `RowLayout { anchors.fill: parent }` | Horizontal stack |
| `Text`      | `Text { text: "…" }` | `text` prop set from slot or literal |
| `Image`     | `Image { source: "…" }` | `source` prop set from slot or literal |
| `Spacer`    | `Item { Layout.fillWidth: true }` | `fillHeight` in a Column context |
| `Scroll`    | `Flickable { contentWidth: contentItem.width; contentHeight: contentItem.height }` | Scrollable container |
| `Divider`   | `Rectangle { height: 1; color: "#e0e0e0"; Layout.fillWidth: true }` | 1 px horizontal rule |
| `Stack`     | `Item { }` with `z`-ordered children | Children overlap at origin |
| `Icon`      | `Text { font.family: "Material Icons"; text: "…" }` | Icon codepoint as text |
| `Grid`      | `GridLayout { }` | Column count from `columns` prop |

### 2.3 Slot → QML Property Type Mapping

| Mosaic slot type | QML `property` type | Initial value |
|-----------------|---------------------|---------------|
| `text`          | `string`            | `""` |
| `number`        | `real`              | `0` |
| `bool`          | `bool`              | `false` |
| `image`         | `url`               | `""` |
| `color`         | `color`             | `"#000000"` |
| `list<text>`    | `var`               | `[]` |
| `list<number>`  | `var`               | `[]` |
| `list<bool>`    | `var`               | `[]` |
| `node`          | `Component`         | `null` |

`list<T>` slots use the `var` type because QML does not have a statically typed
generic array. At runtime, the engine treats `var` arrays as JavaScript arrays,
so `.length` and index access work correctly inside `Repeater` delegates.

### 2.4 Reserved QML Property Names

Several names are pre-defined in QML (`id`, `width`, `height`, `visible`,
`opacity`, `enabled`, `x`, `y`, `z`, `parent`, `children`). If a Mosaic slot
shares one of these names, the emitted QML property gets a trailing underscore
(`visible` → `visible_`, `width` → `width_`) to avoid shadowing the built-in.

A comment is emitted alongside the renamed property to document the collision:

```qml
// 'visible' is a QML built-in property; renamed to 'visible_' to avoid shadowing.
property bool visible_: false
```

### 2.5 Control Flow

#### `when @slot` — `visible` property

```
when @visible {
  Text { content: "Hello"; }
}
```

QML does not have an `if` statement in the declarative layer. The conventional
approach is to wrap the conditional body in an `Item` and set `visible`:

```qml
Item {
    visible: root.visible_

    Text { text: "Hello" }
}
```

The `Item` wrapper is always present in the generated QML even when the body
contains a single child, ensuring structural consistency.

#### `each @items as item` — `Repeater`

```
each @items as item {
  Text { content: @item; }
}
```

```qml
Repeater {
    model: root.items
    delegate: Text {
        text: modelData
    }
}
```

Inside the delegate, the loop variable resolves to `modelData` (the QML
built-in for the current item value in a `Repeater` using a JavaScript array
model). If the each body references `@item.someField` (for complex object
models), the delegate uses `modelData.someField`.

### 2.6 `QmlRenderer` Struct

```rust
pub struct QmlRenderer {
    component_name: String,
    slots: Vec<MosaicSlot>,
    /// Stack of open QML element frames during depth-first traversal.
    stack: Vec<QmlFrame>,
    /// QML lines accumulated at the root level.
    root_lines: Vec<String>,
    /// Indentation depth (2 spaces per level).
    indent: usize,
}

struct QmlFrame {
    /// The QML element name, e.g. "ColumnLayout".
    element: String,
    /// Properties to emit before children, e.g. ["anchors.fill: parent"].
    props: Vec<String>,
    /// Child QML strings accumulated while this frame is on the stack.
    children: Vec<String>,
}
```

The `emit()` method serializes the frame tree into an indented QML string,
then prepends the import lines and the top-level `Item { id: root … }` wrapper
containing all slot property declarations.

## 3. Phase B — Headless Render Daemon

### 3.1 Daemon Overview

`mosaicbook-qt-daemon` is a standalone C++ application (compiled separately from
the Rust workspace) that:

1. Starts a `QGuiApplication` and creates a `QOffscreenSurface`.
2. Listens on a Unix domain socket at `/tmp/mosaicbook-qt.sock`.
3. Accepts one JSON request per connection.
4. Renders the component offscreen using `QQmlEngine` + `QQuickRenderControl`.
5. Captures the frame as a `QImage` and encodes it to PNG.
6. Returns the PNG as base64 in a JSON response.
7. Closes the connection.

The daemon is started by `mosaicbook-server` at startup and monitored for crashes.
If the daemon exits unexpectedly, the server restarts it with exponential backoff
(initial delay 1 s, max delay 30 s).

### 3.2 Transport: Unix Domain Socket

```
Socket path:  /tmp/mosaicbook-qt.sock
Mode:         SOCK_STREAM
Framing:      4-byte big-endian length prefix + UTF-8 JSON payload
Concurrency:  Each connection is handled sequentially within the daemon.
              The daemon processes one render at a time; concurrent renders
              are queued at the socket accept level.
```

The 4-byte length prefix contains the byte length of the JSON payload that
follows (not including the 4 bytes themselves). Maximum payload size: 4 MiB.
Payloads larger than 4 MiB are rejected with an error response before rendering.

```text
Request wire format:
┌──────────────────────────────────────────────┐
│ 0x00 0x00 0x02 0x80  │  { … JSON … }         │
│  4 bytes (big-endian) │  640 bytes of UTF-8   │
│  length = 640         │                        │
└──────────────────────────────────────────────┘

Response wire format:
┌──────────────────────────────────────────────┐
│ 0x00 0x01 0xA4 0x00  │  { … JSON … }         │
│  4 bytes (big-endian) │  107520 bytes UTF-8   │
└──────────────────────────────────────────────┘
```

### 3.3 Request Schema

```json
{
  "action": "render",
  "source": "component ProfileCard { … }",
  "width": 400,
  "height": 300,
  "slots": {
    "display-name": "Jane Doe",
    "avatar-url": "https://example.com/avatar.png",
    "count": 42,
    "visible": true,
    "items": ["Alpha", "Beta", "Gamma"]
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `action` | `"render"` | yes | Must be `"render"` (reserved for future actions) |
| `source` | string | yes | Full Mosaic component source text |
| `width` | integer | yes | Canvas width in logical pixels (1–4096) |
| `height` | integer | yes | Canvas height in logical pixels (1–4096) |
| `slots` | object | no | Fixture values for each slot (same format as UI18 fixture) |

The `slots` object is optional. If absent, all slot values fall back to their
type-appropriate defaults (empty string, 0, false, empty array).

### 3.4 Response Schema — Success

```json
{
  "ok": true,
  "png_base64": "iVBORw0KGgoAAAANSUhEUgAA…"
}
```

The `png_base64` value is standard base64 (RFC 4648, not URL-safe). The client
decodes it to get the PNG byte stream, which may be written to a file, served as
a `data:image/png;base64,…` URL, or passed to `render_scene_png()` for further
processing.

### 3.5 Response Schema — Error

```json
{
  "ok": false,
  "error": "mosaic-analyzer: unknown slot type 'widget' at line 3"
}
```

Error cases include:

- Mosaic source parse or analysis errors (reported from `mosaic-analyzer`).
- `width` or `height` out of range (< 1 or > 4096).
- Payload exceeds 4 MiB size limit.
- QML engine errors (syntax error in generated QML).
- Render timeout exceeded (default: 5 seconds per render).

### 3.6 Daemon Lifecycle and Isolation

Each render is isolated within the daemon process:

- A fresh `QQmlComponent` and `QQuickItem` subtree is created per request.
- The component is destroyed after the PNG frame is captured.
- Qt object ownership is managed via `QScopedPointer`; no state leaks between
  renders.

The daemon does **not** fork per request. All rendering happens on the daemon's
main Qt event loop thread, serialized by the accept loop. This keeps the Qt
context single-threaded (a Qt requirement) while still allowing the Rust
`mosaicbook-server` to handle many concurrent HTTP clients by queuing render
requests.

### 3.7 Qt Version and System Requirements

| Requirement | Value |
|-------------|-------|
| Qt version | Qt 6.4+ |
| Rendering API | `QQuickRenderControl` + `QOffscreenSurface` |
| Graphics API | OpenGL (fallback: software rasterizer via `QT_QUICK_BACKEND=software`) |
| Build system | CMake 3.21+ with Qt6 CMake targets |
| System libs (Linux) | `libGL`, `libEGL` (or Mesa software driver) |
| System libs (macOS) | Metal (automatic via Qt) |
| System libs (Windows) | Direct3D 11 via ANGLE (automatic via Qt) |

For CI environments without a GPU, the `QT_QUICK_BACKEND=software` environment
variable forces Qt to use the CPU-based rasterizer. The output is pixel-identical
to the GPU path for the node types that Mosaic uses.

## 4. Security

### 4.1 QML Injection Prevention

Slot values injected into QML property values are validated before emission. A
string slot value that contains newlines, closing braces `}`, or QML escape
sequences is rejected:

```rust
fn is_safe_qml_string(s: &str) -> bool {
    !s.contains('\n') && !s.contains('\r') && !s.contains('}') && !s.contains('"')
}
```

Safe string values are emitted as `"value"` QML string literals. Unsafe values
are replaced with `""` and a warning is emitted to stderr.

The slot *names* are validated by `is_safe_js_identifier()` (same function as the
React backend) before being used as QML property names.

### 4.2 Unix Socket Permissions

The daemon creates `/tmp/mosaicbook-qt.sock` with permissions `0600` (read/write
for owner only). This prevents other users on the same machine from sending
render requests to the daemon.

```cpp
// After bind():
chmod("/tmp/mosaicbook-qt.sock", S_IRUSR | S_IWUSR);
```

### 4.3 Render-only Sandbox

The daemon does not load any Qt plugins that perform network access, file I/O
beyond reading the QML string from the in-process engine, or system calls
unrelated to rendering. The `QQmlEngine` is created with `QML_DISABLE_DISK_CACHE=1`
to prevent writing compiled QML bytecode to disk.

## 5. Integration with MosaicBook (UI19)

Phase B of this spec is the Qt implementation of UI19's **Tier 3 — Compilation-
server** backend. From the server's perspective:

1. On startup, `mosaicbook-server` runs `mosaicbook-qt-daemon` as a child process
   and verifies the socket appears at `/tmp/mosaicbook-qt.sock`.
2. When the browser requests a Qt preview, the server proxies the request to the
   daemon over the Unix socket.
3. The PNG response is base64-decoded by the server and returned as
   `Content-Type: image/png` to the browser.
4. If the daemon is unavailable (crashed, not installed), the server returns a
   503 with a user-visible message instead of crashing.
