# A nesting-limit refusal is not evidence about a formatter policy

Adding a fifth standard-function layer to an already powered/additive test
exceeded ALGOL's unchanged nesting cap135. Both the name-refusal and value-
acceptance tests failed at parse, so neither had reached the intended formatter
boundary. Preserve the actual0PASS/2FAIL/Cargo101 receipt; never call that the
expected policy refusal. Simplify fixture arithmetic while keeping five layers,
both root dependencies and exact9/1 outputs; do not raise the production cap.

The first locked test was also refused before compilation because metadata
--no-deps had not completed feature resolution. Full offline metadata updated
the lock before failing to fetch an uncached existing platform crate. Compare
registry names/versions/sources/checksums and prove the locked test executes;
do not label the failed metadata command successful or introduce new versions.
