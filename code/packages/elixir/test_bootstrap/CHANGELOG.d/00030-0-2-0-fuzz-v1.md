## 0.2.0

- Elixir coverage-guided fuzz engine conforming to fuzz-v1 (VER06n): mutator algebra
  (parity flips that never build a million-bit integer, floored offsets, explicit
  width masks), 65,536-edge bitmap, power schedule with half-away-from-zero rounding,
  crash signatures (`Module.function/arity` frames, no messages, no line numbers),
  minimiser, deterministic campaign, TAP failure lines reduced to the VER06 9.3 byte grammar (no
  escapes), and a strict corpus runner with sabotage hooks.
- Every target execution runs in its own monitored process with `max_heap_size`
  (`kill: true`) and a wall-clock kill; `:killed` is an oom only from that
  execution's own monitor. Each execution gets a fresh `:atomics`-backed handle,
  retired atomically afterwards, with a token checked on every call; budget
  exhaustion is sticky and judged by a post-run check, so a target that swallows
  the sentinel is still a timeout or an oom.
- Verdicts: zero executions is never a pass, crash witnesses are re-run before being
  reported (`:reproduced`, `:flaky`, `:unverified`), and CI mode (`:unset` included)
  carries no seed or witness.
- Caps: 256 MiB retained bytes, 1 MiB inputs, a campaign-wide minimisation budget
  that counts rejected candidates, and a `mutate_sequence` aggregate cap of 2^24
  that charges failed calls and zeroes the allowance on a breach.
- Tests: all 25 fuzz-v1 cases, Go's 820 reference vectors, per-case corruption
  controls that must fail, every sabotage hook, and pinned values for the energy
  ties, real `sig_hash` values, the rejection draw and the bisection halves.
- `required_capabilities.json` now declares `thread:spawn` and `thread:message`.
