# journal-mosaic-web

Journal in the browser (J5c-2 of #14416). This is a small Vite and React page
that mounts the generated `JournalApp` over the `journal-mosaic-app` runtime,
built for wasm32. It has the same shape as VisiCalc's host.

```text
index.html → src/main.tsx → src/App.tsx
                              ├─ JournalApp (generated by mosaic-compile --backend react)
                              └─ journal_mosaic_app.wasm (the Rust runtime, via mosaic-host.mjs)
```

The runtime owns every piece of state, and this host only does three things:

- **Loads the wasm.** It passes the clock the runtime imports, through a shim
  that never throws.
- **Relays.** Props go in, with kebab-case keys turned into camelCase, and
  events go straight to the runtime.
- **Saves.** After each event it stores the runtime's snapshot in
  `localStorage` (`journal-mosaic/state`), and it restores that snapshot on
  the next visit. A stored journal the runtime refuses is kept aside under
  a key of its own (`journal-mosaic/state.unreadable.<time>`), and never
  deleted or overwritten. When another tab changes the journal, this tab stops
  saving and asks for a reload, so an older tab never undoes newer work.

## Running it

```sh
npm install
npm run dev     # builds the components and wasm, then serves on :5175
npm test        # Vitest against the real wasm
npm run build   # production build into dist/
```

`npm run components` (`../../scripts/build-web.sh`) regenerates the
git-ignored `src/components/` and `public/journal_mosaic_app.wasm`. Set
`JOURNAL_WASM_PROFILE=release` for an optimised runtime.
