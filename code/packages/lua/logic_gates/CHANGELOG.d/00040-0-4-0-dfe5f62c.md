## [0.4.0] - 2026-11-24

### Changed (BREAKING)

- Invalid inputs now raise a structured error table `{ code = "INVALID_BIT",
  param = <"a"|"b">, value = <bounded description> }` (with a `__tostring`
  metamethod rendering the readable message) instead of a free-text string.
  Use `logic_gates.is_invalid_bit(err)` to test for it.
- A bit is valid only if `math.type(v) == "integer"` and `v` is 0 or 1. The
  floats `1.0`, `0.0`, `-0.0`, NaN and +/-inf, strings, booleans, nil, tables,
  functions, userdata and coroutines are all rejected (in Lua 5.3+ `1.0 == 1`,
  which the old `~=` check silently accepted).
- Extra arguments to any of the 11 basic gates raise an `INVALID_ARITY` error
  (`logic_gates.is_invalid_arity(err)`); missing arguments are `INVALID_BIT`.
- Validation never calls `tostring` on the offending value, so hostile
  metatables are never invoked while building the error.
- `ANDn`/`ORn` use the same strict validator.

### Added

- `tests/test_exhaustive.lua`: literal truth tables for all 11 gates, NAND-built
  equals direct, every integer in [-1024, 1024] outside {0, 1} plus extreme
  values in every argument position, full type-confusion matrix, arity, result
  type.

### Fixed

- Existing sequential tests no longer assign to the loop variable `_` (a
  read-only constant in Lua 5.5).

### Packaging

- Rockspec renamed to `coding-adventures-logic-gates-0.4.0-1.rockspec`; BUILD
  references in `fpga`, `arm1_gatelevel`, `intel4004_gatelevel` updated.
