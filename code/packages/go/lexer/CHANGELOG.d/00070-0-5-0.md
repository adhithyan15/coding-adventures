## [0.5.0] - 2026-11-16

### Added

- **`Compile(tg) (*Compiled, error)`** compiles every pattern of a grammar once.
  Bad patterns come back as errors that name the token (the panic text the
  constructor used to carry); nothing panics. A `*Compiled` is immutable and
  safe for concurrent use, so one compile serves any number of inputs.
- **`(*Compiled).Tokenize(source) ([]Token, error)`** is the panic-free entry
  point. Unexpected input, reserved words used as identifiers, a tab in
  indentation, an inconsistent dedent, and a rule or skip pattern that matches
  the empty string all return a `*LexError` carrying `Line`, `Column` and
  `Message`. The hot path contains no `recover()`. Output is token-for-token
  identical (types, values, lines, columns, flags) to
  `NewGrammarLexer(src, tg).Tokenize()` on every input the legacy path accepts:
  skip handling, keywords, reserved words, context keywords, groups, F10
  transitions and flat-mode inheritance, `escapes: none`, case-insensitive
  mode, indentation and layout modes, and the `*STRING*` quote-stripping rule
  (kept for compatibility and now documented on `stripQuotes`).
- **`LexError`** (`Line`, `Column`, `Message`). `Error()` yields exactly the text
  the legacy panic carried, for example `LexerError at 2:5: Unexpected
  character '§'`.
- **First-byte dispatch.** Each group's rules are indexed by the byte they can
  start with (a conservative FIRST-set computed with `regexp/syntax`, falling
  back to "any byte"), so a token attempt tries only the handful of rules that
  can match instead of every rule. Order is untouched: first match still wins,
  and dispatch only ever skips rules that cannot match.
- **Literal fast path.** Literal rules, and regexes that parse to a plain
  string, match with `strings.HasPrefix`.
- **Deterministic matchers (`matcher.go`).** Common token shapes (identifier,
  integer, hex, `name<annotation>`, quoted strings with escapes, whitespace and
  line comments) run as a few lines of byte-at-a-time code instead of the
  regexp engine. A pattern is accepted only if it provably gives the same
  answer as leftmost-first regexp matching (FIRST/FOLLOW disjointness for
  greedy runs, exclusive branches for alternation); anything else stays on
  `regexp`. This also removes the regexp engine's cost that grows with the
  remaining input, which made large inputs slow.
- Benchmarks (`bench_test.go`): `BenchmarkTokenize{Legacy,Compiled}{StraceWhole,
  StracePerLine,JSON}` and `BenchmarkCompile`.
- Differential tests (`compiled_diff_test.go`) against a frozen copy of the
  previous engine (`legacy_oracle_test.go`): real grammars from
  `code/grammars` (json, c, python, css, xml, cobol with F10 transitions,
  haskell layout mode, sql, dot, idl, javascript, java, lisp, dartmouth_basic),
  every prefix of every sample, random byte-level mutations, and
  `FuzzCompiledMatchesLegacy`. `FuzzMatcherMatchesRegexp` checks the matchers
  and first-byte sets against `regexp` directly.

### Changed

- `NewGrammarLexer` and `GrammarLexer.Tokenize` are now thin layers over the
  same engine: the constructor calls `Compile`, and `Tokenize` panics with the
  `LexError` text where it always panicked. Callbacks, pre/post hooks and
  `LexerContext` are unchanged. The constructor still yields a nil lexer for a
  grammar with an invalid pattern, as before.
- The flat-mode (F10 `set_mode`) merged pattern list is built once at compile
  time instead of being rebuilt for every token.
- Token positions advance by whole matches rather than byte by byte.
- `processEscapes` returns its input unchanged (no allocation) when it has no
  backslash.

### Behaviour notes

- A token rule or skip pattern that matches the empty string used to loop
  forever; it now reports an error.
- The `errors:` section of a grammar is still not honoured in Go (it is in the
  other ports); doing so would change what currently panics, so it is left for
  a separate change.

### Performance

Measured on an Apple M2 Max, single core, strace-like trace lines and a JSON
document (see `bench_test.go`). Before = the engine at commit 3f144795c8c.

| workload                       | before     | after (Compiled) |
| ------------------------------ | ---------- | ---------------- |
| strace-like, per line          | 0.23 MB/s  | about 46 MB/s    |
| strace-like, whole document    | 1.26 MB/s  | about 39 MB/s    |
| JSON document                  | 2.09 MB/s  | about 32 MB/s    |
