## 0.2.0 - coverage-guided fuzz engine (VER06o)

- New `CodingAdventures.TestBootstrap.Fuzz` (and `Fuzz.*`): the Haskell lane of the Level 2 fuzz engine. Mutator algebra
  (word-wise parity flips, so a 1,000-digit count or a 1 MiB input never builds a big `Integer`), 65,536-edge bitmap,
  power schedule, crash signatures, the VER06 9.3 byte-grammar TAP token, deterministic campaign, minimiser (campaign-wide
  budget that counts rejected candidates), CI-redacted verdicts with crash re-verification.
- Coverage is target-reported through a per-execution `Handle` (HPC is not used in the hot path; see VER06o 4.2). The
  handle is one `IORef` updated atomically: live/retired flag, identity token, step and memory budgets and counters, a
  1,024-word edge bitmap. Exhaustion is sticky in both directions; the verdict is judged after retirement from the sticky
  flag and the counters.
- One forked thread per execution under a wall-clock `timeout`; only `tryRecoverable` catches (async exceptions are
  rethrown); crashes are classified by exception type only. Memory is a per-thread allocation limit
  (`setAllocationCounter`/`enableAllocationLimit`), classified `oom` only from the worker's own limit.
- New `fuzz-v1-conformance` suite: `fuzz-v1: 25/25` and the Go lane's `vectors: 820/820`; `spec` gains the pinned blind-spot
  tests (energy ties, real sig_hash values, the rejection draw, bisection halves, TAP tokens from the Ruby lane),
  isolation tests and negative controls for every case and sabotage hook.
- `required_capabilities.json` declares `thread:spawn`, `thread:message` and `time:read`; the Go build tool selects this
  package on fuzz-v1 and reference-vector changes.
- New spec `code/specs/VER06o-haskell-fuzz-engine.md`.
