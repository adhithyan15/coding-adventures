## Mandatory type and source ingress

Add `TimelineConfig.font_size: f64` with default **16.0**, after the existing
family field while retaining all old field order. The cloned optional config
in LayoutedTemporalDiagram carries the authored accepted value exactly. This
is a public Rust constructor/API change, with no new serialization/FFI format.

Read only a direct `fontSize` member of the first genuinely closed init root.
If that member is absent, fall back to a direct `config.fontSize` YAML field.
A present init member, even empty, nonnumeric or invalid, suppresses YAML and
later init roots. An absent member in the selected root can use YAML, but must
never borrow from a later root. YAML top-level fontSize, config.timeline,
config.themeVariables, arrays, nested maps and description text are not this
root field. Preserve the existing scanner and decoder semantics unchanged.

Decode through the existing strict owned string/text decoder, then the existing
parse_mermaid_font_size helper unchanged. It trims whitespace and accepts bare
f64 text or case-sensitive suffixes rem/em (scale16), ex (scale8), px (scale1).
After scaling require a finite value strictly greater than zero; otherwise use
16.0. In particular ±0, negatives, NaN, infinities, overflow, empty/invalid
containers, unsupported escapes/tails and unrecognized units fall back. No
arbitrary magnitude cap is added. A positive finite subnormal and f64::MAX are
valid transported sizes at this stage, since this stage performs no new
size-dependent multiplication, rendering or layout arithmetic.

Quoted/bare numeric text are both allowed by the current decoder. This is not
a complete JSON/YAML implementation or CSS font-size syntax parser. Preserve
root/present-invalid suppression before parsing rather than rescanning raw
source to find a convenient numeric token.

allocation and derived geometry work, refuse a Timeline config whose size is
nonfinite or not strictly positive with that exact typed error. Preserve the
old three input priorities and all old Geometry diagnoses when size is valid.

All finite positive sizes retain the old complete layout except for the new
transported config field. This includes smallest-positive subnormal and MAX,
empty positive/zero-height layouts, both directions, title/section/event cases,
and representable large-coordinate inputs under the old geometry admission.

admission contract; acceptance here cannot certify a future doubled-font result.
Non-Timeline branches and None-config painting remain byte-equivalent.
