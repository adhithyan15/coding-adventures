## Unreleased - [D77] the static codes of `v2-fault`, R119 to R126 (CV2-F17, VER04r 16.23)

- **[D77], R119: `v2-fault` has `unknown-tag`, `depth` and `model-order`.** `ERROR_CODES["v2-fault"]` gains the three. `derive_fault` answers in
  section 11's order: (1) the table and the op row's types (`ill-typed`), (2) `level-missing`, (3) `fault_static_refusal` (`unknown-tag`, `depth`,
  `model-order`, in no pinned order among themselves), (4) `subject-forbidden`, (5) the typing of the row. Before, an unknown tag ended in an uncaught
  `OracleError` (`fault_levels` called `ir_levels`), a nesting over 64 in a `KitError`, and a `model_call` was written as `ill-typed`. `fault_levels`
  levels only the tags a defined level owns (`known_levels`), so an unknown tag adds no level; `too_deep` measures the nesting by tag shape (root is
  level 1; 64 accepted, 65 refused). `requires_of` gives a `v2-fault` `unknown-tag` case its `levels` (R24; R119 (e)).
- **R120.** In `v2-ir` every refusal of an `env` type text (`Int`, an undeclared name, `Result<U8,Q>` with `Q` a record, `Bytes<07>`, `U8<`) is
  `ill-typed` (`_env_types`; it was the out-of-set `type`). An entry that is not `[name, {"type": text, "value": V}]` is a `KitError` (it was a
  `KeyError`).
- **R122.** `compile_ir_case` reads every op signature straight after the table and before `static_refusal` (the order: `max_ir_cost` bound, table,
  op signatures, `env` types, everything else). An unused bad op row is `ill-typed` where a tree defect used to win. Model signatures are left open.
- **R123.** `check_type_table` (the consumer side) reserves `TABLE_RESERVED` = `V0_BUILTINS` plus `U16 U32 I8 I16 I32 I64` in place of
  `lower._DECLARED_RESERVED_V1`, for row and constructor names; a row called `rem` or `take` is no longer refused. Lowering keeps its version-scoped set.
- **R124.** `_models` leaves an unreached model uncompiled when its parameter types or tags (or those of a model it calls) need a level outside
  `levels` (`_uncompiled_models`; a stand-in named in `subjects` counts as reached). Its parameters are still parsed; the tag-name checks, its
  expression depth and the chain depth of R77 still apply (`_check_skipped`). The `Refused("depth")` of a skipped model passes `compile_ir_case`
  unchanged.
- **R125.** `check_corpus_and_row` (the `v2-chunk` reader) calls the new `check_corpus_ops_models`: `ops` and `models` objects, op rows and their type
  texts (`Int`, an error type, an undeclared name, `Result<U8,Q>`, unparseable text), model parameters (an error type or undeclared name; `Int` stays
  accepted, [D75]), an unknown tag in a model body and a `model_order` that does not name models are `corpus`.
- **R126.** `check_fault_row` makes a malformed fault row (an extra or missing key, a bad `kind`, a bad `rewrites` list, a rewrite naming no or a
  repeated parameter) or an undefined level name in `fault.requires` a `KitError`, read before the table.
- Tests: `tests/test_cv2_16_23_checks.py`. Four tests that pinned the old behaviour change, each for the reason named:
  `test_cv2_16_22_checks.py::test_v2_fault_has_ill_typed_in_its_closed_set` expects the six codes ([D77]);
  `test_conformance_tables.py::test_error_codes_stay_in_the_closed_sets_and_every_code_is_used` exempts the three new codes until S10d and S11d add
  their vectors ([D77]); `test_cv2_16_22_checks.py::test_int_stays_refused_in_an_op_row_an_env_entry_a_field_and_a_value` and
  `...::test_an_env_entry_of_an_error_type_is_ill_typed_and_so_is_int` (renamed from `..._but_int_stays_type`) expect `ill-typed`, not `type`, for an
  `Int` `env` entry (R120). No committed fixture, dump, corpus or kit byte moves (`make_conformance.py --check`: 958 cases in 7 files identical). No kit
  vector is added.
