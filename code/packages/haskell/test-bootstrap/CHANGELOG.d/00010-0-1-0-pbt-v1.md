## 0.1.0 - pbt-v1 conformance

First release of the Haskell test-bootstrap package (spec:
`code/specs/VER05n-haskell-pbt-engine.md`). Haskell previously had no test
bootstrap, property engine or fuzz engine. GHC boot packages only (`base`,
`bytestring`, `containers`, `text`, `deepseq`, `stm`).

### Added
- `Prng`: SplitMix64 on `Word64` (native wrap), `bounded` (rejection threshold
  `negate n `mod` n` computed unsigned; `bounded 1` consumes a word; `2^64` is one
  raw word), `boundedBig` (k-word rejection above `2^64`), `fnv1a64`, `subSeed`.
- The generator algebra (`bool`, `u8`, `u64`, `i128`, `int`, `bytes`, `constant`,
  `mapG`, `filterG`/`filterM`, `flatMap`, `oneOf`, `frequency`, `list`, `tuple2`,
  `tuple3`, `customGen`) with integrated shrinking; invalid constructors fail
  closed (the sampler throws, the runner reports `property-exhausted`).
- Shrinkers that match the corpus minimals and step counts exactly (integer walk
  with floored bisection, the sequence shrinker over a `Seq`), plus pinned tests for
  what the corpus cannot catch (the forced rejection draw, the `2^63 + 1` boundary,
  `bounded 1`, bisection order, floor vs truncation).
- The VER05e 4.1 hierarchical budget tree on STM: one `atomically` per all-or-nothing
  charge, depth cap 64, public entries open child scopes and internal combinators
  join, `check` wraps its whole body, nested checks pay at entry / per case / per
  sample size / per filter retry, top-level filter retries are work, starvation is
  never a pass, a refused re-verification keeps the original witness, and a closed or
  stale handle is spent (never a fresh root). The ambient budget is an explicit
  `Maybe Budget` parameter with a hand-written `PropM` reader monad
  (`askBudget`, `checkM`, `withBudget`, `forkWithBudget`).
- `check`, `checkM`, `checkPure`, `checkWith`: verdict honesty (zero cases, generator
  error, re-verified witness, lazy bottoms forced inside every handler, asynchronous
  exceptions rethrown and classified by type only), the closed failure vocabulary,
  CI redaction that fails closed (`CiUnset` redacts; `ciFromLookup` is pure).
- Total canonical rendering (`Canon`) with depth, node and output caps enforced
  while traversing lazy values, the Elixir lane's exact escape set (controls, C1,
  bidi, invisible formatting), and bounded `sameVal`.
- Strict JSON reader (depth 64, 8 MiB, 200k nodes, duplicate keys by decoded bytes,
  invalid UTF-8, BOM, leading zeros, trailing data; numbers kept as text), strict TFV
  validator, and the corpus evaluator with CWE-400 caps (fixture integers at most
  1,000 digits).
- Tests: the committed pbt-v1 corpus 25/25 in its own suite; per-case per-op
  corruption (each must fail and name exactly that case), every field wrong-typed,
  dropped/truncated corpora, sabotage through `Config`, the laziness and
  asynchronous-exception hazard suite, the VER05e budget-tree set plus thread and
  spent-handle cases, a starved-shrinker sweep, and decoder-cap tests. Every test
  runs under a timeout. HPC coverage of the library at release: 96% of expressions (6350/6612), 95% of alternatives, 99% of local declarations.
