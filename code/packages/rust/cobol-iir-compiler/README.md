# cobol-iir-compiler

Lower a parsed **COBOL-60** program to the shared **IIR** (`interpreter_ir::IIRModule`)
so COBOL runs on every execution backend the LANG VM AOT chain targets —
Native-AOT, LLVM, WASM, JVM, CLR, and the generic register VM / JIT.

This is the COBOL sibling of [`flow-matic-iir-compiler`](../flow-matic-iir-compiler),
and step 4 of [PL09](../../specs/PL09-codegen.md). The tree-walking interpreter
[`cobol-runtime`](../cobol-runtime) is the **semantic oracle**: the compiled
program's output must be byte-identical to what the interpreter `DISPLAY`s.

## Where it sits in the stack

```
COBOL-60 source (carded, 80-column)
   │  cobol-lexer + cobol-parser   (cobol.grammar → CST)
   ▼
GrammarASTNode  (rule_name == "program")
   │  cobol-iir-compiler::compile_source     ← this crate
   ▼
interpreter_ir::IIRModule   (one `main`, returns i64 exit code)
   │  lang-aot  (Language::Cobol60)
   ▼
NativeAOT · LLVM · WASM · JVM · CLR · VM · JIT
```

## This slice (v0.21 — the core plus control flow, reference modification `IDENT(start:len)`, `STRING … DELIMITED BY {SIZE | delim} INTO [WITH POINTER] [ON/NOT ON OVERFLOW]`, `UNSTRING … DELIMITED BY … INTO [WITH POINTER] [ON/NOT ON OVERFLOW]`, `EVALUATE` (numeric/alphanumeric, multi-value/`THRU`), `COMPUTE` incl. `**` and nested `/`, `ON SIZE ERROR`, signed, alphanumeric, compound (AND/OR/NOT) + symbolic conditions, level-88 with ranges + `SET … TO TRUE`)

COBOL's WORKING-STORAGE is a **PICTURE-typed** data model. Each elementary item
becomes one IIR register: a **numeric** item (`PIC 9…`) is an `i64` holding its
value *scaled* by its fractional-digit count (`PIC 9(2)V9` holding 12.3 is the
integer `123`); an **alphanumeric** item (`PIC X`/`A`) is a `str`.

| COBOL | IIR |
| --- | --- |
| `VALUE <lit>` / `MOVE <lit> TO item` | the register's `const`/`str_const` — the literal formatted into the item's picture at compile time |
| `MOVE item TO item` | numeric→numeric rescales the implied point; character→character reshapes to the receiver's size (`str_slice` to truncate, `str_concat` to space-pad); **numeric→alphanumeric** (unsigned **or** signed, integer **or** scaled `PIC [S]9(i)V9(d)`) builds the `(i+d)`-digit zero-padded image at run time (each digit `(slot / 10^k) % 10` sliced out of a constant `"0123456789"` table — integer part then fractional part, **no decimal point**, since the scaled slot already holds `value·10^d`) and feeds it through the same char reshape (left-justify, space-pad, or truncate) — so `9(2)V9=4.2 → X(3)` is `"042"`, `→ X(5)` is `"042  "`, `→ X(2)` is `"04"`. A **signed** source (`PIC S9…`) additionally folds the operational sign into a **trailing overpunch** on the units digit: `neg = slot < 0`, `units = \|slot\| % 10`, and the last character is re-sliced from a single combined table `"{ABCDEFGHI}JKLMNOPQR"` at `units + neg*10` (positive row `{A…I`, negative row `}J…R`) — byte-identical to the runtime's `overpunch_trailing`/`__cob_print_signed` — so `S9(3)=+123 → "12C"`, `= -123 → "12L"`, `S9V9=-4.2 → "4K"` (a signed *positive* source overpunches too, differing from an unsigned `"123"`); **alphanumeric→unsigned numeric** (integer **or** scaled `PIC 9(i)V9(d)`) folds the `m` source bytes left-to-right into an `i64` (`d = str_index(src,k) - '0'`; `value = value*10 + d`); that fold **is the receiver's scaled slot magnitude directly**, so the store hands `store_scaled` the receiver's own scale `d` (a no-op rescale) and keeps the low-order `(i+d)` digits (`mag mod 10^(i+d)`), the implied point `d` from the right — right-justified, zero-padded or high-order-truncated (`MOVE "042" TO 9(2)V9` is `042` reads `4.2`, `MOVE "12345" TO 9(2)V9` is `345` reads `34.5`; **not** the arithmetic decimal-align rule — `value` is not multiplied by `10^d`; `d=0` reproduces the integer-receiver path). The receiver may now be **signed or unsigned** (`PIC [S]9(i)V9(d)`) — this **completes the Char↔Numeric MOVE matrix**: an alphanumeric source has **no operational sign**, so the fold's MAGNITUDE is stored **POSITIVE** (the fold is `emit_abs`-ed before `store_scaled`, so `reapply_sign` is a no-op — a SPACE or any sub-`'0'` byte can never leak a stray sign), and `DISPLAY` overpunches the units digit on its **positive** row (`{A…I`): `MOVE "123" TO S9(3)` shows `12C`, `MOVE "120"` shows `12{`. A `SIGN` clause with `SEPARATE`/`LEADING`, a group on either side, and a source wider than 18 chars are later rungs |
| `ADD`/`SUBTRACT`/`MULTIPLY`/`DIVIDE … [GIVING r] [ROUNDED] [ON SIZE ERROR …]` | `add`/`sub`/`mul`/`div` on the `i64` slots, the result reduced to the receiver's field; a size error runs the handler and leaves the receiver unchanged |
| `COMPUTE r [ROUNDED] = expr [ON SIZE ERROR …]` | the precedence cascade (`+ - * /`, unary minus, `**` with a constant exponent, parentheses) evaluated bottom-up over scaled `i64`, each step overflow-guarded |
| `DISPLAY op…` | each operand's image emitted, then `putchar('\n')` — a literal prints its source text, a numeric item via the fixed-width digit helper (signed items via a trailing-overpunch helper), an alphanumeric via `print_str` |
| `IDENT(start:len)` / `IDENT(start:)` (reference modification) | a 1-based substring of an alphanumeric item over the byte range `[start-1, start-1+len)` (omitted length runs to the item's end), in `DISPLAY`, alphanumeric-comparison (`IF`/`EVALUATE`) operands, and as a **MOVE source** into an **alphanumeric** receiver (`MOVE base(start:len) TO dst`). **Constant (literal) indices** lower to a constant-index `str_slice`, bounds validated at compile time. **Computed (data-name) indices** — `WS(J:K)`, `WS(J:)`, `WS(2:K)` — read each index into an `i64` register and build `start0 = start-1` / `end = start0+len` (or the item width) with `sub`/`add`, feeding a run-time `str_slice`. The index item must be an unsigned integer. An out-of-range computed refmod **traps at run time** under the same predicate (`start0 < 0 \|\| end < start0 \|\| end > width`) the oracle applies, so both engines error identically. As a **MOVE source** the slice (from the SAME `ref_mod_slice` helper) is fit to the receiver's width by the ordinary alphanumeric char rule via `move_slice_into_char` — left-justify, space-pad if wider, truncate if narrower — constant `SRC(2:3)`, omitted-length `SRC(3:)`, and computed `SRC(J:K)` indices all supported, into one or more receivers `MOVE SRC(1:3) TO A B`; a **numeric** receiver stays a later rung |
| `IF cond then… [ELSE else…]` | conditions combine simple conditions with `AND`/`OR`/`NOT` (and parentheses; `NOT` tightest, then `AND`, then `OR`) — `AND`/`OR` fold the `0`/`1` leaf booleans with bitwise `and`/`or`, and a `NOT` inverts one with `xor` against `1`. A simple condition is a relation (numeric: align operands + `cmp_*`; alphanumeric: space-pad + `str_cmp`; **mixed numeric ↔ alphanumeric** (integer **or** scaled `PIC [S]9(i)V9(d)`, **unsigned or signed**): build the numeric side's `(i+d)`-digit zero-padded image (int part then frac part, no point) with the same run-time digit helper the numeric→alphanumeric `MOVE` uses, then space-pad + `str_cmp` like any alphanumeric relation — so `NUM = "042"` is true, `NUM = "42"` is false, and `9(2)V9=4.2 = "042"` is true. A **signed** operand additionally folds the operational sign into a **trailing overpunch** on the units digit (via the same `emit_signed_num_alpha_image` the signed→alphanumeric `MOVE` uses), so `S9(3)=-123` equals `"12L"`, `= +123` equals `"12C"`, `S9V9=-4.2` equals `"4K"`; ordering follows the byte comparison of those images) or a level-88 condition-name (`cmp_eq` on its slot). Relations use word (`GREATER THAN`, …) or symbolic (`> < = >= <= <>`) operators; a relop `NOT` and the baseline negation `>=`/`<=`/`<>` carry compose by XOR and invert the relation directly. `jmp_if_false` over the then-branch |
| `88 cond-name VALUE lit… [lo THRU hi]` | registers a boolean condition-name over the preceding item; `IF cond-name` / `PERFORM … UNTIL cond-name` hold when the variable equals any listed value or falls in any inclusive range — lowered as an OR-fold of `cmp_eq` / `and(cmp_ge, cmp_le)`. **Numeric** variable: numeric `cmp_*` on its scaled slot. **Alphanumeric** (`PIC X`) variable, **string VALUEs** (`88 IS-YES VALUE "Y"`, `88 VOWEL VALUE "A" "E" "I"`, `88 PASSING VALUE "A" THRU "D"`): an OR-fold over the SAME space-padded `str_cmp` path an `IF var = "…"` / `IF var >= "…"` relation uses (`emit_str_condition`) — a discrete string is `cmp_eq`, a **string THRU range** is `and(cmp_ge, cmp_le)`. A THRU range with a **non-string bound** or a **numeric/figurative** VALUE on an alphanumeric 88 stays a later rung (rejected identically on both engines) |
| `SET cond-name TO TRUE` | stores the condition-name's first `VALUE` (a range's low bound) into its conditional variable. **Numeric** variable: a `const` store into the slot. **Alphanumeric** (`PIC X`) variable with string VALUEs: the first value's string (a discrete string, or a range's LOW bound) fit to the receiver width (`format_into_picture`) and stored as the slot's `str_const`, exactly as `MOVE "…" TO item` — a THRU range with a non-string bound or a numeric/figurative VALUE stays a later rung |
| `EVALUATE subj WHEN v… [lo THRU hi]… WHEN OTHER … END-EVALUATE` | a `jmp_if_false` branch cascade (a chain of `IF`s): each `WHEN` OR-folds its value-list (a single value → `cmp_eq`, a `THRU` range → `and(cmp_ge, cmp_le)`) into one boolean; the first match runs and jumps to the end (no fall-through); `WHEN OTHER` runs unconditionally once reached. Each subject-vs-`WHEN`-value comparison reuses the **same relation dispatch** an `IF subject <relop> value` uses (`emit_operand_relation`), so `EVALUATE` inherits `IF`'s full category handling: numeric (scaled `cmp_*`), alphanumeric (`str_cmp`, space-padded), and **mixed numeric↔alphanumeric** (unsigned / **signed** overpunch / **scaled** digit image), plus figuratives and the `ZERO`-numeric routing (`WHEN ZERO` stays a numeric comparison). Deferrals are inherited too: a numeric-literal `WHEN` against an alphanumeric subject (and a group operand) is a clean reject on both engines |
| `STRING s… DELIMITED BY {SIZE \| delim} INTO t` | **`DELIMITED BY SIZE`**: the sending fields concatenated with a `str_concat` chain (each source a `(reg, compile-time len)` pair — an item's slot, a `str_const` literal, a figurative constant SPACE/ZERO reduced to its single-character `str_const` image (SPACE→`" "`, ZERO→`"0"`, length 1 — the same string-literal path), or a CONSTANT-index reference-modification slice `WS(2:3)` / `WS(3:)` from the shared `ref_mod_slice` helper, whose `SliceLen::Const` length feeds the same contract — a numeric item, a group item, and a computed data-name index, whose length is only known at run time, stay later rungs), then overlaid onto the receiver: a result at least as wide is truncated (`str_slice(concat, 0, width)`), a shorter one preserves the receiver's old tail (`str_concat(concat, str_slice(t, len, width))`) — COBOL's no-space-fill rule. **`DELIMITED BY delim`** (a single-character delimiter): each field's prefix boundary is data-dependent, so a per-field **scan loop** (`flen = str_len(F); j = 0; while j < flen && F[j] != d { j++ }; prefix = F[0,j]`) cuts the run before the first delimiter char; the prefixes are `str_concat`-ed and the same no-space-fill overlay runs at run time (`take = min(str_len(concat), W); t = concat[0,take] ++ t[take,W]`). The delimiter is reduced by the SAME `single_delim_code` UNSTRING uses (a 1-char literal, a `PIC X(1)` item, a figurative constant SPACE/ZERO reduced to its single ASCII byte — SPACE 0x20, ZERO 0x30, or a CONSTANT reference-modified slice `base(start:len)` of length 1 via `ref_mod_slice` — computed index / length != 1 later rungs); a non-ASCII literal delimiter and a non-ASCII string-literal sending field under a delimiter are rejected (byte-vs-char), matching the oracle. **`WITH POINTER p`** (a `PIC 9(n)` unsigned integer): after the concatenation is built, a shared run-time overlay (`emit_string_pointer_overlay`) reads the pointer register `pv`, computes the 0-based start `pv − 1`, `avail = size − start`, and `chars_placed = min(concat_len, avail)`, and rebuilds the receiver as `recv[0,start] ++ concat[0,chars_placed] ++ recv[start+chars_placed, size]` (overwriting only the filled run — the compile-time slicing of the no-pointer `SIZE` path no longer applies, so the concat length is materialised as a `const`); an out-of-range guard — `if p < 1 or p > size` jump past the overlay and the write-back to a trailing `st_end` label (ISO overflow ⇒ no data movement, pointer unchanged) — precedes it because the pointer's value is only known at run time; after the overlay the pointer is stored as `pv + chars_placed` through the same `store_scaled` path INSPECT's counter uses. The pointer's picture is validated at build time (unsigned integer, `≤ 18` digits) — a signed / fractional / non-numeric / over-wide pointer is a later rung. **`ON OVERFLOW imp…` / `NOT ON OVERFLOW imp…`**: `emit_string` (and `emit_string_pointer_overlay`) yield an `overflow` i64 register computed with the IDENTICAL comparison the oracle uses — for the no-pointer path a compile-time `total > width` const; for the `WITH POINTER` path the flag is pre-seeded to `1`, out-of-range guards fall through with it set, and the in-range path overwrites it with the run-time drop test `clen > avail`; for `DELIMITED BY delim` (no pointer) the run-time `clen > width` test is the flag. The `statement` children are split at the `NOT` keyword (as `emit_if` splits at `ELSE`) into the ON / NOT-ON lists, then the usual `jmp_if_false`/branch/`label` skeleton runs the selected imperative (both clauses absent ⇒ no skeleton — a plain STRING lowers unchanged) |
| `UNSTRING s DELIMITED BY d INTO r1 [r2 …]` | a run-time **scan loop** (the delimiter position is data-dependent): `len = str_len(s)`, a cursor `p`, and a single delimiter byte `d` (a `const` for a 1-char literal, a `const` of the single ASCII byte for a figurative constant SPACE (0x20) / ZERO (0x30), `str_index(item, 0)` for a `PIC X(1)` item, or `str_index` of the single byte of a CONSTANT reference-modified slice `base(start:len)` of length 1 via the shared `ref_mod_slice` — a computed `base(J:K)` index and a length != 1 slice stay later rungs). The source `s` is an item's char register, a fresh `str_const` register of an alphanumeric string-literal source's bytes (`UNSTRING "a,b,c" …`), a **figurative constant** SPACE/ZERO reduced to its single-character `str_const` image (SPACE→`" "`, ZERO→`"0"`, length 1 — the same string-literal path, both known-ASCII so no non-ASCII guard is needed), OR — for a reference-modified source `UNSTRING S(2:3) …` — the `str_slice` register the SHARED `ref_mod_slice` helper emits (the same slice DISPLAY/comparisons use, constant-folded for literal indices or register-computed for a data-name index); all feed the SAME loop unchanged (a numeric-literal source and a computed reference-modified source stay later rungs). Each receiver, guarded by `if p <= len`, scans `s[j]` with `str_index`/`cmp_eq`/`cmp_ge` for the next delimiter (or end-of-source) `q`, cuts `piece = str_slice(s, p, q)`, reshapes it into the receiver as `str_slice(piece, 0, min(len, W)) ++ spaces(W - take)` (the alphanumeric MOVE), and advances `p = q + 1`; an exhausted source leaves the remaining receivers unchanged. **`WITH POINTER p`** (a `PIC 9(n)` unsigned integer): the cursor is initialised from the pointer register `p_value − 1` (instead of 0), guarded by a run-time out-of-range check — `if p < 1 or p > len` jump past every move and the write-back to a trailing `us_end` label (ISO overflow ⇒ no data movement, pointer unchanged), because the pointer's value is only known at run time; after the scan the pointer is stored as `min(p, len) + 1` (clamp removes the phantom step past end-of-source) through the same `store_scaled` path INSPECT's counter uses. The pointer's picture is validated at build time (unsigned integer, `≤ 18` digits) — a signed / fractional / non-numeric / over-wide pointer is a later rung. **`ON OVERFLOW imp…` / `NOT ON OVERFLOW imp…`**: `emit_unstring` yields an `overflow` i64 register computed with the IDENTICAL comparison the oracle uses — after the receiver loop, `overflow = cmp_le(p, len)` (the final cursor did not run past the source ⇒ fields remain); for the `WITH POINTER` out-of-range case the flag is pre-seeded to `1` before the out-of-range guards, which jump straight to `us_end` with it still set, skipping the scan, the `cmp_le` overwrite, and the write-back. The `statement` children are split at the `NOT` keyword (as `emit_if` splits at `ELSE`) into the ON / NOT-ON lists, then the usual `jmp_if_false`/branch/`label` skeleton runs the selected imperative (the whole flag + skeleton is emitted only when a clause is present — a plain UNSTRING lowers unchanged) |
| `INSPECT s TALLYING c FOR ALL d` (or `FOR LEADING d`) | a run-time **count loop** (the delimiter position is data-dependent): `len = str_len(s)`, a cursor `j`, a count accumulator `cnt` (init 0), and a single delimiter byte `d` (a `const` for a 1-char literal, a `const` of the single ASCII byte for a figurative constant SPACE (0x20) / ZERO (0x30), `str_index(item, 0)` for a `PIC X(1)` item, or `str_index` of the single byte of a CONSTANT reference-modified slice `base(start:len)` of length 1 via the shared `ref_mod_slice` — a computed `base(J:K)` index and a length != 1 slice stay later rungs). While `j < len` (`cmp_ge`) it reads `s[j]` with `str_index`, `cmp_eq`s it to `d`, and bumps `cnt` on a match; then the count is folded into the counter with the same numeric-store path `ADD` uses — INSPECT **adds** to the counter, it does not clear it first. `FOR ALL` counts EVERY match (the not-equal branch skips just the bump and keeps scanning); `FOR LEADING` counts only the run of consecutive matches at the START (the not-equal branch breaks out of the loop) — that jump target is the ONLY difference between the two forms. The STANDALONE form (both `FOR ALL` and `FOR LEADING`) also accepts an optional `{BEFORE\|AFTER} x` **region**: a one-shot scan finds the FIRST occurrence of the single region delimiter `x` (a `found` flag + first index), the window `[start, end)` is derived with the ISO not-found asymmetry (`BEFORE`→whole source, `AFTER`→empty). For `FOR ALL` the count loop scans `0..len` and skips any position with `j < start \|\| j >= end`; for `FOR LEADING` the run is ANCHORED at the window start — the loop counter is seated at `start` and bounded by the window `end`, so the stop-at-first-mismatch break yields the in-window run (e.g. `FOR LEADING "a" AFTER "X"` over `"aaXaab"` counts the run in `"aab"` = 2, not the `"aa"` before the `X`); with no region nothing extra is emitted. **`FOR CHARACTERS`** (single item, single counter) is now supported: it does NOT match a delimiter — the count is simply the LENGTH of the region window, ADDed to the counter (`cnt = str_len(s)` with no region, else `cnt = end - start` over the SAME `emit_inspect_region_window` window `FOR ALL` uses, inheriting the identical `BEFORE`→whole / `AFTER`→empty not-found asymmetry). The per-character match loop and `single_delim_code` are skipped entirely; the count folds into the counter through the SAME `store_scaled` ADD. A MULTI-counter `CHARACTERS` and a MULTI-character region delimiter are later rungs (a MULTI-item `CHARACTERS` — one CHARACTERS item ALONGSIDE other items under ONE counter — is now supported, see the multi-item row below; a `CHARACTERS` TALLYING half in a combined `TALLYING … REPLACING` is now supported too — it routes through this SAME count lowering, see the combined row below; the combined REPLACING half's OWN `CHARACTERS` form stays a later rung; several `FOR` items under ONE counter, several counters each with their own delimiters, and a combined `FOR LEADING` half carrying a region are also supported — see the multi-item, multi-counter, and combined rows below) |
| `INSPECT s TALLYING c FOR ALL a [{BEFORE\|AFTER} p] ALL b [{BEFORE\|AFTER} q] …` | the **multi-item** form (TWO OR MORE `FOR ALL` items sharing ONE counter), where **each item may carry its OWN optional `{BEFORE\|AFTER}` region** — the count-side analogue of the multi-item REPLACING row. Unlike the replace rebuild (which unrolls the compile-time width), the tally builds no string, so this is a genuine **run-time count loop** over `len = str_len(s)` (mirroring the single-item tally loop): `cnt` (init 0), a cursor `j`, and each delimiter reduced to a byte code (`const` for a 1-char literal, `str_index(item,0)` for a `PIC X(1)` item). At each `j` it reads `s[j]` ONCE and walks a **first-match-per-position** `cmp_eq` chain against the items IN WRITTEN ORDER: the FIRST item whose window contains `j` AND whose delimiter matches bumps `cnt` and jumps past the rest to the continue label (so a position is counted at most once — DUPLICATE/overlapping items never double-count, `FOR ALL "a" ALL "a"` over `"aa"` adds 2, not 4); no match falls through with no bump. **Per-item regions**: `str_len(s)` is materialised ONCE up front, and any item's `{BEFORE\|AFTER}` window is derived with the SAME `emit_inspect_region_window` the single-item region path uses (a one-shot scan for the FIRST region-delimiter occurrence, window `[start, end)` with the ISO not-found asymmetry `BEFORE`→whole / `AFTER`→empty). That item's chain link then gates on `start <= j < end AND s[j] == d` against the RUNTIME position `j`; a region-less item's link stays the plain `s[j] == d` (its window guard folds away). Then `counter := counter + cnt` folds via the same `store_scaled` (silent high-order truncation on overflow) the single-item tally uses. A new `inspect_tally_multi` CST reader counts the same `tally_item` children the oracle counts, so the two engines' accept/reject sets stay co-total. Each item may now be `ALL` **or** `LEADING` (this rung lifts the multi-item `LEADING` reject): a `LEADING` item allocates a per-item `active` run register (i64, init 1, before the loop — the runtime-loop analogue of the single-item REPLACING LEADING active flag) and its chain link additionally AND-gates on `active`, so it counts only while its run is alive; at the per-position convergence label — reached by BOTH a match `jmp` and a no-match fall-through — EVERY `LEADING` item's run is updated (`active := active AND eq` region-less, or `active := active AND (eq OR NOT in_win)` windowed so out-of-window positions never touch the run), recomputing `eq`/`in_win` there because an early match `jmp` skips later chain registers — so a matching char claimed by a higher-priority item keeps the run alive, and a `LEADING` run is anchored at its window start (`FOR LEADING "a" AFTER "X" ALL "b"` over `"aaXaab"` = 3). Non-ASCII-clean (a POSITIVE parity, not a trap): the tally only COUNTS (it never `str_slice`s the source into a new string) and each window is content-defined, so this byte-index scan and the oracle's char-index scan count the SAME ASCII matches even on a non-ASCII source (`"aé0b0"` with `ALL "0" BEFORE "b" ALL "0" AFTER "b"` → `002`; `"aaébb"` with `FOR LEADING "a" ALL "b"` → `004` — a `LEADING` run breaks at the multi-byte char's first byte — on both). A list item may also be `CHARACTERS` (this rung lifts the multi-item `CHARACTERS` reject): a `CHARACTERS` item carries NO delimiter and its chain link's `matched` predicate is its window membership ALONE (skipping the `cmp_eq` against a delimiter byte) — the always-eligible catch-all, contributing 1 at every in-window position not already claimed by an EARLIER item in written order. A region-less `CHARACTERS` item is UNCONDITIONALLY eligible, so it emits an unconditional bump + `jmp cont` (shadowing every later chain link, honouring written order) and allocates no `active` register; it is skipped in the leading run-update pass (`FOR ALL "A" CHARACTERS` over a mixed ASCII string totals the source length; `FOR CHARACTERS ALL "A"` shadows the ALL item; a `{BEFORE\|AFTER}` region narrows the catch-all like any item). The multi path is single-char, under EXACTLY ONE counter; several counters and the combined `TALLYING … REPLACING` form with several tally items are later rungs (several counters each with their own delimiter list are supported — that path stays `ALL`-only and keeps rejecting `CHARACTERS`, see the multi-counter row below; a single tally item keeps the full single-item path above). Byte-vs-char count chip (task_396ba6f6): a `CHARACTERS` item counts POSITIONS, and the compiler iterates BYTE positions while the oracle iterates CHAR positions, so a non-ASCII source INSIDE a CHARACTERS window diverges — the SAME chip as the single `FOR CHARACTERS` form, NOT fixed here |
| `INSPECT s TALLYING c1 FOR ALL a [{BEFORE\|AFTER} p] [ALL b …] c2 FOR ALL d [{BEFORE\|AFTER} q] …` | the **multi-counter** form (TWO OR MORE `tally_for` groups, each with its OWN counter and one-or-more single-char `FOR ALL` delimiters), where **each item may carry its OWN optional `{BEFORE\|AFTER}` region** — generalises the multi-item row from one counter to a list of `(counter, delimiter, window)` entries. `emit_inspect_tally_counters` materialises `len = str_len(s)` ONCE up front, then keeps ONE accumulator register per GROUP (init 0) through a single **run-time count loop**. ### Why it is exact

A numeric item does not display as a plain integer: `PIC 9(5)` holding 42 shows
`00042`, and `PIC 9(2)V9` holding 123.456 shows `234` (truncated, implied point).
For a literal stored into a field, the value is known at compile time, so the
compiler calls the very same picture/value functions the oracle uses —
`cobol-runtime`'s `move_into_numeric` / `move_into_char`, re-exported for exactly
this reuse — and stores the resulting scaled value. A numeric *literal* in a
`DISPLAY`, by contrast, shows its **source text** (`DISPLAY 42` → `42`).

Runtime arithmetic is native `i64` over the scaled slots.
`ADD`/`SUBTRACT`/`MULTIPLY`/`DIVIDE` all honour the implied point (`PIC …V…`):
additive verbs align operands to a common working scale then accumulate;
`MULTIPLY` products carry scale `sa + sb`; `DIVIDE` scales the dividend up before
the truncating division to land the receiver's decimals (plus a guard digit for
rounding). Every store rounds **half away from zero** with `ROUNDED` (else
truncates) and keeps the low-order `int_digits + dec_digits` digits (COBOL's
silent-overflow-truncation rule). `ON SIZE ERROR` turns that silent truncation
into a caught condition (handler runs, receiver unchanged) when the integer part
overflows or a divisor is zero.

`COMPUTE` evaluates the grammar's precedence cascade (`+ - * /`, unary minus,
parentheses) bottom-up in the same scaled-`i64` model; every node carries a
compile-time `(scale, integer-digit)` bound and every combining step is
overflow-guarded, so an intermediate that could exceed 18 digits is a clean error
rather than a silent wrap. A **top-level** division reuses the `DIVIDE` verb's
rounding and zero-divisor handling. A division **nested** inside a larger
expression reproduces the oracle's fixed scale-12 intermediate (`COMPUTE_DIV_SCALE`,
re-exported so the two stay in lockstep): `a / b` becomes
`(a · 10^(b.scale+12)) / (b · 10^a.scale)` truncated toward zero, a scale-12 value
the surrounding operators then combine exactly. (Because the scale-12 math is `i64`
here but `i128` in the oracle, a numerator/denominator that could exceed 18 digits
is a clean later rung; and a nested division under `ON SIZE ERROR` — whose zero
divisor would need routing to the handler — is deferred.) **Exponentiation** (`**`) with a compile-time
non-negative integer exponent `e` unrolls into a chain of `e − 1` `mul`s of the
base — the oracle computes `base**e` by multiplying `1` by `base` `e` times, so
the mul-chain's magnitude (`base_scaled^e`) and scale (`e · base.scale`) match it
exactly; `x ** 0` is the constant `1` (the base is never read). `**` folds
right-associatively (`A ** B ** C = A ** (B ** C)`) and binds tighter than `* /`.

**Signed numerics (`PIC S9…`)** keep their sign in the `i64` slot — so arithmetic
and `IF` comparisons are signed — and `DISPLAY` shows the sign as a trailing
**overpunch** on the units digit (`{A-I}` positive, `{J-R}` negative, `'{'`/`'}'`
for zero). An unsigned receiver stores only magnitude, so a signed→unsigned `MOVE`
drops the sign. Numeric **item-to-item `MOVE`** reshapes the source value into the
receiver's picture. Control flow: **`GO TO`** jumps to a paragraph label;
**`PERFORM`** (paragraph / `THRU` / `TIMES` / `UNTIL` / `VARYING`) inlines the
paragraph range at the call site, which reproduces COBOL's return semantics
exactly (a `STOP RUN` inside returns, a `GO TO` inside jumps away), bounded by
depth and instruction-count caps against a recursive `PERFORM`.

Character handling is fixed-length string work: a character item's slot always
holds exactly its declared width, so an item-to-item `MOVE` and an alphanumeric
comparison both reduce to a single compile-time-sized `str_slice`/`str_concat`
(reshape) or a space-pad plus `str_cmp` (compare), with `SPACE`/`ZERO`
figuratives expanded to the partner operand's length. Two figuratives compared
against each other (`IF ZERO = SPACE`) have no length to borrow, so each resolves
to a single fill character (width 1) — `ZERO` → `"0"`, `SPACE` → `" "` — matching
the oracle, so `ZERO = ZERO` is true and `ZERO > SPACE`.

### Deliberately a later rung

Each of these is a clean `CompileError::Unsupported` (never wrong output): group
items, a **group item** in a mixed numeric↔alphanumeric comparison and a
**numeric-literal-vs-alphanumeric** pairing (a different pairing kept out of
scope — a numeric *item* ↔ alphanumeric comparison, **unsigned or signed**,
integer or scaled, is now supported: a signed operand compares by its magnitude
image with the operational sign folded into a trailing overpunch on the units
digit, the same image the signed→alphanumeric `MOVE` builds, so `S9(3)=-123`
equals `"12L"` and `= +123` equals `"12C"`), a `COMPUTE` nested
division whose scale-12 intermediate could exceed the 18-digit `i64` model (or one
paired with `ON SIZE ERROR`), a `COMPUTE` `**` whose exponent is a variable, a
parenthesised expression, negative, fractional, or past the oracle's `MAX_POW_EXP`
(or whose conservative digit bound could exceed the 18-digit model), a
level-88 condition-name over an alphanumeric variable with a **THRU range carrying a
non-string bound** or a **numeric/figurative** VALUE (a discrete-string alphanumeric
88 and a **string-bounded THRU range** are now supported — see the table above), a **reference
modification** with a signed/fractional/non-numeric index item, of a numeric item,
or in a numeric/arithmetic/`MOVE`-source context (an out-of-range *constant*
reference modification is likewise rejected at compile time, never lowered to a
runtime trap; a *computed* one traps at run time, matching the oracle), a `STRING`
with a multi-character or non-ASCII delimiter, a non-ASCII string-literal sending
field under a delimiter, a COMPUTED (data-name) index reference-modification sending
field (`STRING WS(J:K) …` — its run-time length cannot enter the compile-time STRING
image contract), per-field different delimiters, a signed / fractional /
non-numeric / over-wide (`> 18`-digit) `WITH POINTER` item,
a numeric item or figurative as a sending field, or a
non-alphanumeric receiver (a single-character ASCII `DELIMITED BY` delimiter, a
`WITH POINTER p` phrase over a `PIC 9(n)` pointer, a CONSTANT-index reference-
modification sending field `STRING WS(2:3) …`, and the `ON OVERFLOW` /
`NOT ON OVERFLOW` imperative handlers ARE supported), and an `UNSTRING`
with a multi-character / `ALL` / `OR`
delimiter, a signed / fractional / non-numeric / over-wide
(`> 18`-digit) `WITH POINTER` item, a numeric/figurative/reference-
modified delimiter, a NUMERIC-literal / FIGURATIVE / NON-ASCII source or a
NUMERIC-base reference-modified source (an ASCII alphanumeric string-literal source,
an alphanumeric-base reference-modified source `S(2:3)` — literal or computed
index — a `WITH POINTER p` phrase over a `PIC 9(n)` pointer, and the `ON OVERFLOW` /
`NOT ON OVERFLOW` imperative handlers ARE supported), or a
numeric/group source or receiver.

## Usage

```rust
use cobol_iir_compiler::compile_source;

let src = "\
000000 IDENTIFICATION DIVISION.
000000 PROGRAM-ID. HELLO.
000000 PROCEDURE DIVISION.
000000 MAIN.
000000     DISPLAY \"HELLO, WORLD\".
000000     STOP RUN.";
let module = compile_source(src, "hello").unwrap();
assert!(module.validate().is_empty());
// → run `module` on any backend; it prints "HELLO, WORLD\n".
```
