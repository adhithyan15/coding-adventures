## Unreleased

- Fix KRN-006b (VER25 section 8.5): `TypeChecker` threaded one environment through `func.blocks` in vector order, so a read reached by a path that never binds the variable passed (block 0 jumps to 2, block 1 binds `x` and jumps to 2, block 2 reads `x`). `check_function` now runs a control-flow-aware definite-assignment fixpoint (intersection at joins, carrying type and label) and reports `TypeError::UseBeforeDefinition { function, block, var }` for a read that some path reaches with the variable unbound. A name bound nowhere in the function is still `UndefinedVariable`. A diamond whose arms both bind a variable is accepted; a loop that binds only in its body, read in the header, is rejected. Add `TypeError::NoEntryBlock` (no block with id 0) and `TypeError::BlockIdsNotDense` (ids not exactly `0..n`; `BasicBlock::id` is a field separate from the block's position, so this can happen). Add `TypeChecker::check_definite_assignment`, the same rule alone, used by `tests/test_checker_dominance.rs` to run every in-repo adopter lowering (ct-compare, the small lowering sources, the comprehensive snippets) through it: none is rejected. Blocks unreachable from the entry are type-checked against the parameters alone.
- Convert `CHANGELOG.md` to a sharded `CHANGELOG.d/` (one file per entry, history unchanged).
