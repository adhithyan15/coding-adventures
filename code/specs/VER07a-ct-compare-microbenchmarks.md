# VER07a — Constant-Time Equal-Instruction-Count Microbenchmark Suite for ct-compare

**Parent:** [VER00 §7.4](VER00-verified-shipping-program.md), [VER07](VER07-microbenchmarks.md), [CT01](CT01-constant-time-compare.md), [VER26 §3](VER26-ct-compare-pilot.md).

This specification defines the microbenchmark suite and empirical constant-time equal-instruction-count verification for `code/packages/rust/ct-compare`.

It delivers **VER-P017**: the equal-instruction-count benchmark suite covering $n \in \{16, 256, 4096\}$, zero-heap allocation assertion, and empirical constant-time validation under [VER07](VER07-microbenchmarks.md).

1. **Equal Instruction Counts across Equivalence Classes:**
   For a given input size $n$, cryptographic constant-time comparison must execute the exact same instruction sequence regardless of secret data contents. We test four equivalence classes:
   - **Class 1 (Identical):** $a == b$ (full equality, every byte matches).
   - **Class 2 (Diff First):** $a[0] \ne b[0]$ (would exit on iteration 0 in naive short-circuiting implementations).
   - **Class 3 (Diff Last):** $a[n-1] \ne b[n-1]$ (would exit on iteration $n-1$ in naive implementations).
   - **Class 4 (Diff All):** $a[i] \ne b[i]$ for all $i \in [0, n)$.
   - **Class 5 (Diff Middle):** $a[n/2] \ne b[n/2]$.

   When hardware performance counters are live, the harness verifies:
   $$\text{instructions}(Class_1) == \text{instructions}(Class_2) == \text{instructions}(Class_3) == \text{instructions}(Class_4) == \text{instructions}(Class_5)$$

2. **Zero Allocation Invariant:**
   Constant-time operations must not perform heap allocation. Memory allocations introduce allocator lock contention, kernel page faults, and cache eviction patterns that breach constant-time security (CWE-208).
   $$\Delta\text{alloc\_bytes} == 0, \quad \Delta\text{allocation\_count} == 0$$

3. **Multi-Scale Input Sweeps:**
   Measurements are conducted across representative scales:
   - $n = 16$ bytes (AES-128 key / IV scale);
   - $n = 32$ bytes (SHA-256 / Ed25519 signature scale);
   - $n = 64$ bytes (SHA-512 / BLAKE2b scale);
   - $n = 256$ bytes (packet / token scale);
   - $n = 4096$ bytes (memory page scale).

4. **Negative Fault Injection (Sabotage Proof):**
   The suite includes an intentional non-constant-time comparison mutant that short-circuits on the first differing byte. The test proves that the harness successfully detects instruction count divergence between Class 2 (Diff First) and Class 3 (Diff Last).

## 2. Benchmark Definitions

### 2.1 `ct_eq` Sweep
- Inputs: Generated byte slices of sizes $n \in \{16, 256, 4096\}$.
- Budgets:
  - `max_alloc_bytes`: 0 (hard budget);
  - `max_steps`: $n$ comparison steps (hard budget);
  - `max_median_duration_ns`: Advisory ceiling based on linear scaling ($< 5\,\text{ns/byte}$).

### 2.2 `ct_eq_fixed` Sweep
- Evaluated for fixed compile-time widths:
  - $n = 16$ (`ct_eq_fixed::<16>`);
  - $n = 32$ (`ct_eq_fixed::<32>`);
  - $n = 64$ (`ct_eq_fixed::<64>`).
- Asserted zero allocation and equal instruction count across all byte difference positions.

### 2.3 `ct_select_bytes` Sweep
- Evaluated for slice lengths $n \in \{16, 256, 4096\}$.
- Compares execution with `choice = true` (0xFF mask) versus `choice = false` (0x00 mask).
- Asserts that branch-free selection maintains equal instruction counts regardless of choice condition.
- **Not zero-allocation (LH-003a).** `ct_select_bytes` returns a fresh `Vec`, so
  measured through the counting global allocator it makes exactly one
  allocation of `a.len()` bytes per call. The zero-allocation claim (§1, item 2)
  covers `ct_eq`, `ct_eq_fixed` and `ct_eq_u64` only; the select benchmarks are
  named `bench/select_bytes/*`, outside the `bench/ct_*` set the assurance
  report cites, and `bench/select_bytes/allocates_exactly_its_output` pins the
  real profile. Every zero-allocation budget in this suite is checked against
  the real heap and fails if the counter was not live; the negative control
  `bench/sabotage/allocation_detected` proves a one-byte allocation fails it.

### 2.4 `ct_eq_u64`
- Compares 64-bit unsigned integers:
  - Equal operands: $x == y$;
  - High-bit differing: $x \oplus y = 1 \ll 63$;
  - Low-bit differing: $x \oplus y = 1$;
  - Inverted operands: $x == \sim y$.
- Asserts zero allocation and equal instruction count.
