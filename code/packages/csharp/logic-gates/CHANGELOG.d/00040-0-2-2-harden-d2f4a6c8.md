## [0.2.2]

### Security / hardening (LGE-CS-HARDEN)

- `InvalidBitException`'s constructor now rejects a null `parameterName` with
  `ArgumentNullException`; `ParameterName` is a non-null property (no more
  `ParamName!`).
- Exception messages format every number with `CultureInfo.InvariantCulture`;
  `InvalidBitException.Message` is overridden so the base class's culture-
  formatted "Actual value was N" cannot change the text (tested under a custom
  NegativeSign culture).
- Library builds with `TreatWarningsAsErrors`, nullable warnings as errors,
  `AnalysisLevel 9.0-recommended`, `CheckForOverflowUnderflow` (no code relies
  on wraparound) and `ImplicitUsings` disabled (explicit `using System;`).
- Tests assert `AndN`/`OrN`/`XorN` all throw `ArgumentNullException` for null.
- BUILD / BUILD_windows run tests in Debug and Release; the 95% coverage gate
  runs on Release (the configuration `dotnet pack` ships).

### Changed (breaking)

- `new InvalidBitException(null, v)` now throws `ArgumentNullException`.

### Decisions not taken

- TargetFramework stays net9.0: CI (`ci.yml`, `actions/setup-dotnet`) installs
  only SDK 9.0.319 and ~613 sibling projects target net9.0. .NET 9 (STS)
  reached end of support on 2026-11-10; moving to the LTS (net10.0) needs a
  repo-wide SDK bump in the shared CI step, tracked separately.
- No NuGet lock file / locked-mode restore: no sibling package uses one, and
  adding it to one package would diverge from repo precedent and the shared
  artifacts-path restore flow. Package source mapping likewise deferred to a
  repo-wide change.
