## [0.2.0] — next_int_in_range spec v2

### Fixed

- **The range draw could hang forever.** It took the rejection threshold
  modulo 2^64 while drawing only 32 bits, so for a span such as 2^63 + 1
  every possible draw was rejected. For smaller spans the same mismatch was
  biased and disagreed with the other languages, and no span above 2^32 could
  reach more than 2^32 − 1 above `min`. It now follows spec v2
  (`code/specs/rng.md`): 32-bit draws for spans up to 2^32, 64-bit draws with
  64-bit rejection for wider spans, one plain 64-bit draw for the whole
  64-bit domain.
- The whole `int64` domain divided by zero.

### Added

- A conformance test running the shared corpus
  (`code/specs/fixtures/rng-v1/`), plus regressions for wide ranges, the
  whole domain and span 2^63 + 1. Changelog sharded.
