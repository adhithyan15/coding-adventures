## Unreleased — LANG83 PR7f-2 — Lisp's value rules are compiler-emitted IIR

- The tagged-word pipelines (`compile_iir_to_llvm`, the native executables via `twig-aot`, and `jit_lisp`'s McCarthy JIT) no longer call the runtime for Lisp truthiness, `not`, `equal?` or the exit coercion: `iir-builtin-lowering`'s `lower_dyn_repr` writes them as IIR (truthiness and `not` inline; `__lisp_equal` and `__lisp_exit_code` module functions). Every program prints what it printed before.
- `jit_lisp` registers only representation callbacks: `dyn_truthy`, `dyn_not`, `dyn_equal` and `dyn_to_exit_code` are gone, `dyn_tag` and `dyn_is_nil` are new. JIT compile set, measured with `JITCore::is_compiled` over the `jit_mccarthy` programs: unchanged except `main` of `(EQ 7 7)` / `(EQ 7 8)` and the lambda of `((LAMBDA (X Y) (EQ X Y)) 3 3)`, which now call the recursive `__lisp_equal` and so run on the interpreter tier (the JIT has no `call` bytecode). `(ATOM 7)`-shaped functions still compile because truthiness and `not` are inline.
- The scalar-narrowing evidence lists drop the four runtime names (the helpers' `dyn_tag` calls are evidence enough).
- `op_conformance`: new case "Lisp truthiness, not, equal? and exit code as module IIR (PR7f-2)" (built with `lisp_semantics`) runs on LLVM and native x86-64; `pr7f2_lisp_rules_are_module_code_over_the_primitives` checks its expectation against `dynval-runtime`'s Rust value model and that the LLVM module defines `@__lisp_equal` / `@__lisp_exit_code` and references none of the removed runtime rules.
- Comments in the McCarthy LLVM / native / JIT tests name the new helpers.
