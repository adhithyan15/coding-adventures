## Unreleased — LANG83 PR7c-js — JavaScript prints through its own `String(x)` helper

- `javascript-iir-compiler` 0.7.0 no longer emits `write_f64_js`: a JavaScript module that prints a number carries the compiler-written `__js_write_number` (built from `f64_class`, `f64_signbit`, `f64_digits`, `f64_exp10`) and three integer helpers, and each `console.log` argument `call`s it. The `-0` test is `f64_signbit x > f64_class x`, with no `f64_add`. All 38 JavaScript rows print exactly what they printed before; locally 228 cells ran (native x86-64, LLVM, WASM, JVM, VM, JIT) and agree with host node v22. No row changed its columns: every row BEAM refused does `f64_*` arithmetic, and the 11 literal-only rows still list all eight.
- `javascript_rows_pass_the_lang83_check_on_all_nine_backends` walks every function, allows the helpers' ops (`f64_class`/`f64_digits`/`f64_exp10`, integer `add`/`sub`/`mul`/`div`, `cmp_eq`/`cmp_lt`/`cmp_gt`/`cmp_ge`, `jmp`, `call`), rejects any `write_f64_js`, and now requires BEAM's refusal to name only the five arithmetic ops (it used to allow any `f64_*` but `f64_signbit`).
- New `javascript_prints_lower_on_beam_once_the_arithmetic_is_gone`: every row's module with its arithmetic replaced by constants passes BEAM's op check and lowers to BEAM bytes, so the `-0` class test, the call and the helpers never keep a print off BEAM.
- `javascript_rows_compile_and_run_on_the_jit_without_its_interpreter_fallback` is replaced by `javascript_rows_run_with_their_call_free_number_helpers_compiled_by_the_jit`. `main` now `call`s the helper, and the generic JIT has no `call` bytecode, so `main` runs on the interpreter tier (as LANG83 PR7 anticipates). The new test pins the JIT's share of every row's module (exactly `__js_digit_count` and `__js_write_digits`), runs `main` with those compiled, and checks that the stdout is unchanged and that the compiled tier wrote the significant digits. The VM and JIT harnesses keep their `write_f64_js` sinks, which other paths still use until PR7e.
