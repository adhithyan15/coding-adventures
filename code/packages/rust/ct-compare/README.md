# coding_adventures_ct_compare

Compiler-preserved full-scan byte-slice equality for Rust, implemented from
scratch — no external dependencies.

## What It Does

Provides equality primitives whose compiled scans retain every input read,
closing the ordinary early-exit prefix leak for MAC tags, session keys, and
password hashes. This is a compiler-level guarantee, not a claim of general
timing-side-channel resistance:

1. `ct_eq(a: &[u8], b: &[u8]) -> bool` — compiler-preserved full-scan
   equality on byte slices.
2. `ct_eq_fixed::<N>(a: &[u8; N], b: &[u8; N]) -> bool` — type-safe
   fixed-length variant.
3. `ct_select_bytes(a, b, choice) -> Vec<u8>` — source-level branchless
   select between two same-length slices.
4. `ct_eq_u64(a: u64, b: u64) -> bool` — source-level branchless 64-bit
   equality for counters and lease IDs.

## Why A Naive `==` Isn't Enough

```rust
for (x, y) in a.iter().zip(b.iter()) {
    if x != y { return false; }  // early exit leaks how many bytes matched
}
```

An attacker who can time this loop — over the network, in a colocated
tenant, on the same machine — learns the longest matching prefix and
can walk a candidate tag byte by byte. That's exactly how Keyczar's
HMAC verification, Rack's session cookies, Google's 2009 password
incident, and many historic CVEs were broken.

This crate replaces the early exit with an XOR accumulator:

```rust
let mut acc = 0u8;
for i in 0..a.len() {
    // The implementation performs volatile reads of both bytes and `acc`,
    // followed by a volatile write of the combined difference.
    accumulate_volatile(&mut acc, &a[i], &b[i]);
}
read_accumulator(&acc) == 0
```

Every iteration retains observable input reads and an accumulator write
regardless of which byte differs. A release-optimized LLVM-IR regression gate
rejects builds where a loop cycle bypasses the volatile operations or a loop
exit depends on their values.

## What It Does NOT Do

- **Cache-timing / branch-predictor / speculative-execution leaks** —
  those need hardware-level countermeasures.
- **Length hiding** — the public API compares lengths with `==` and
  treats length as public. Real secrets (MAC tags, HMAC outputs, AEAD
  tags, session keys, Argon2 tags) have fixed, publicly-known lengths.
- **Zeroization** — see `coding_adventures_zeroize`.

## Usage

```rust
use coding_adventures_ct_compare::{ct_eq, ct_eq_fixed, ct_eq_u64, ct_select_bytes};

// MAC verification
if !ct_eq(&computed_tag, &received_tag) {
    return Err("invalid tag");
}

// Fixed-size tags (preferred when the length is a compile-time constant)
let ok: bool = ct_eq_fixed(&tag_a, &tag_b);

// Lease-ID comparison
if ct_eq_u64(lease.id, requested.id) { /* ... */ }

// Branchless conditional select
let picked = ct_select_bytes(&option_a, &option_b, predicate);
```

## How It Fits

Part of the D18 Chief-of-Staff Vault crypto stack. Used by Poly1305 AEAD
decryption, HMAC tag verification, Argon2id password verification, and Vault
unlock-key comparison.

Self-contained: no runtime dependencies. Two private safe wrappers contain the
audited volatile-pointer operations; public callers never handle pointers or
invoke `unsafe`.

## CT01 conformance and the VER26 pilot

`cargo test -p coding_adventures_ct_compare` runs the existing unit/optimized-IR
tests and a TF01 L0 target (`tests/conformance.rs`, `harness = false`). Every
shared CT01 case is embedded from `code/specs/fixtures/ct-compare-v1/cases.tfv`.
Fixed-width cases call `ct_eq_fixed::<N>` through generated const-generic arms;
selection cases check fresh ownership, and a real native length-mismatch panic
maps to `CT_SELECT_LENGTH_MISMATCH` without changing the public API.

Five negative adapter checks must reject inverted equality, wrong selection,
missing length errors, wrong work metadata and an unsupported fixed width. The
TF01 harness retains its own independent self-corpus and sabotage check.

From the repository root, regenerate after editing the JSON oracle:

```text
python code/scripts/ct_compare_tfv.py --write
python code/scripts/ct_compare_tfv.py
```

The second command only checks. CI rejects drift in either TFV or generated
dispatch; the build tool selects this crate when the corpus/reference changes.
Use `cargo test -p coding_adventures_ct_compare --test conformance -- --seed 7`
to replay a shuffled L0 run. The bootstrap crate is a dev dependency only.

`expected_work` checks logical public input shape, not observed instructions,
elapsed time or a constant-time proof. Warrant-generated tests, properties,
WIR-level trace proofs and the assurance report remain later VER26 steps.

`cargo test -p coding_adventures_ct_compare --test runtime_capability` runs the
whole public API (`ct_eq`, `ct_eq_fixed`, `ct_eq_u64`, `ct_select_bytes`, including

## Zero-allocation evidence (measured, LH-003a)

`tests/microbenchmarks.rs` installs test-bootstrap's counting
`#[global_allocator]`, so every `max_alloc_bytes: 0` budget is checked against
the real heap, and a benchmark only counts as zero-allocation when the counter
was live and read exactly 0.0 bytes per iteration.
`bench/sabotage/allocation_detected` proves the counter can see a one-byte
`Vec::with_capacity(1)` and fails it.

Measured result: `ct_eq` (16, 256, 4096 bytes), `ct_eq_fixed` (16/32/64) and
`ct_eq_u64` allocate **0 bytes in 0 allocations** per call. `ct_select_bytes`
**does allocate**: it returns a fresh `Vec`, exactly one allocation of
`a.len()` bytes per call (pinned by
`bench/select_bytes/allocates_exactly_its_output`). It is therefore not part of
the zero-allocation claim: its benchmark id is `bench/select_bytes/...`, outside
the `bench/ct_*` set the assurance report cites for CWE-400. A caller that cannot
allocate needs a variant writing into a caller-provided buffer; that API does
not exist yet.

## Implementation Notes

- `#[inline(never)]` on the public functions. Inlining them into
  callers could let the optimiser specialise per-caller in ways that
  reintroduce data-dependent behaviour.
- `ct_eq` and `ct_eq_fixed` use volatile reads for both input bytes and their
  accumulator plus a volatile accumulator write on every iteration. This is a
  compiler-observability boundary, not a claim to defeat cache, speculative,
  power-analysis, or other hardware side channels.
- An integration test compiles the crate at optimization level 3, reconstructs
  the optimized LLVM-IR control-flow graph, verifies every cycle crosses the
  volatile equality block, and rejects volatile-data-dependent loop exits.
- `ct_select_bytes` builds a byte mask `0u8.wrapping_sub(choice as u8)`
  (`0xFF` or `0x00`) and applies `b ^ ((a ^ b) & mask)` per byte. No
  conditional branches, no early exits.
- `ct_eq_u64` folds `a ^ b` into the low bit via
  `(diff | -diff) >> 63`, the classic "is-any-bit-set" trick.
