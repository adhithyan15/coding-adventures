# AF-04a — DSP filter API and assurance inventory

**Status:** scoped inventory and checker contract; observations are pinned to
`origin/main` `cb60dc9820fc069325130193118e75fdba9b96bc` (PR #19651 squash).
This document is not an assurance report and does not mark any float/source
proof live.

## 1. Purpose and boundary

AF-04a records what each shipped `dsp-filters` lane publicly exposes and what
evidence actually reaches those exports. It separates API facts, source/tests,
mathematical models, Warrant binding, and native refinement. It is an inventory
and dependency audit; it adds no DSP behavior, does not promote a partial
operation set to package completion, and does not infer a proof from a Warrant
declaration, test count, fuzz enum, generated harness, or source resemblance.

The initial inventory covers the Rust, Python, and TypeScript
`dsp-filters` packages. It also records all four Warrant copies, the relevant
property/fuzz producer implementations, and the currently available Warrant
binding/evidence mechanisms. It does not claim to inventory all 22 workstation
roots or 45 work families; those remain part of the delivery goal in
`AUDIO-WORKSTATION-BACKLOG.md`.

## 3. Public surface facts at the pinned revision

The machine-readable inventory will include every root-level export,
module-visible Rust symbol, Python `__all__` entry, TypeScript index export,
public class method and signature, alias, constant, error inheritance and
constructor surface, Rust derive/trait declaration, package source path, and
source blob OID. A parser-assisted listing is a completeness aid only: the
inventory must be reviewed against the public source and package exports, and
the checker must state which syntax forms it recognizes. It must not describe
private helpers as public APIs.

### Rust

`biquad` is a private module; `Biquad` and `sosfilt` are re-exported from the
crate root. `design` and `iir` are public modules, and their public functions
are also re-exported at the crate root. The crate exposes `fir`, `fir_fft`,
`iir`, the Biquad/SOS APIs, windowed-sinc designers, Butterworth/Chebyshev
helpers, `WindowType`, `FilterError`, and `MAX_SAMPLES`, `MAX_TAPS`, and
`MAX_ORDER`.

All signal and coefficient scalars are `f32`; buffer APIs borrow slices and
return `Result<Vec<f32>, FilterError>`. `Biquad::new([f32; 6])` takes
`[b0,b1,b2,a0,a1,a2]`; it and `process_sample`, `process`, and `sosfilt` are
checked APIs. `Biquad` has private delay state and no public state accessors,
`Default`, or `PartialEq`. `process` preserves its entry state on returned
failure; `process_sample` checks output and candidate delays before committing.
Normalization uses direct division by `a0`; finite normalized coefficients are
required. There is no pole-stability test. `sosfilt(sections, signal)` is
one-shot, creates fresh section state on each call, accepts empty sections as
identity for nonempty input, and rejects empty input. The signal cap is
`MAX_SAMPLES = 2^24`; its section cap is `MAX_ORDER = 1024`. There is no
aggregate samples-times-sections cap.

`iir(signal, b, a)` is also one-shot; it does not expose persistent delay
state. Its coefficient-array preflight ceiling is `MAX_TAPS = 2^20`, its signal
cap is `2^24`, and `MAX_ORDER = 1024` means maximum polynomial order here, so
accepted coefficient vectors are at most 1,025 elements. The same `MAX_ORDER`
constant therefore has distinct meanings by operation: polynomial order for
`iir`, number of sections for `sosfilt`. Keep units operation-local. Legacy
`design_*` return `Vec<f32>` and panic for invalid arguments; additive
`try_design_*` return `Result`. Designer tap length must be odd, so the largest
accepted designer tap count under `MAX_TAPS` is `1,048,575`; direct `fir` and
`fir_fft` accept even kernel lengths. Cutoffs are normalized
cycles/sample, with Nyquist at `0.5`. Butterworth and Chebyshev helpers support
orders 1 and 2 only; there is no arbitrary-order cascade designer or checked
variant.

`Biquad` derives `Clone` and `Debug`; `WindowType` derives `Copy`, `Clone`,
`Debug`, `PartialEq`, and `Eq`. `FilterError` derives `Debug`, `Clone`, and
`PartialEq`; the inventory records its explicit `Display`, `Error`, and
`From<dsp_fft::FftError>` implementations, including declared method
signatures and conversion behavior. This covers package-declared traits, not
blanket or standard library inherited implementations.

`FilterError` variants are `EmptySignal`, `EmptyKernel`,
`InvalidCoefficient(String)`, and `Fft(String)`. It implements `Display`,
`std::error::Error`, and conversion from the FFT error. `WindowType` has
`Rectangular`, `Hamming`, `Hann`, and `Blackman`; no Kaiser window is exported.
`fir_fft` is whole-buffer FFT convolution, not overlap-add.

### Python

The package `__all__` exports `fir`, `fir_fft`, `iir`; `design_low_pass`,
`design_high_pass`, `design_band_pass`, `butterworth_lowpass`,
`chebyshev1_lowpass`, and `WindowType`; `Biquad`, `sos_cascade`, `sosfilt`,
`CheckedBiquad`, `checked_sosfilt`; constants `MAX_ORDER`, `MAX_SAMPLES`,
`MAX_TAPS`; and errors `FilterError`, `EmptyKernelError`,
`EmptySignalError`, `InvalidCoefficientError`.

Arithmetic and results use binary64; legacy APIs accept Python numeric
sequences and return lists. `Biquad` exposes writable `b0`, `b1`, `b2`, `a1`,
`a2`, `z1`, and `z2` slots; its constructor reciprocal-normalizes after raw
finite/zero checks, but does not reject nonfinite normalized coefficients. It
has `reset`, `process_sample`, `process`, and class constructors `lowpass`,
`highpass`, `bandpass`, `notch`, `allpass`, and `peak`. `process` converts
samples with `float` and commits as it goes, so a later bad sample leaves valid
prefix progress. `sos_cascade(signal, sos)` is the historical argument order;
`sosfilt(sos, signal)` is the alias order. SOS state is local to each call.
`CheckedBiquad`/`checked_sosfilt` accept only exact built-in int/float inputs,
exclude bool/subclasses and convert checked integers once to binary64. They use
direct-division normalization and reject nonfinite normalized coefficients,
outputs, and candidate delays. Checked block processing is atomic for
filter-owned state on ordinary failures/accessor exceptions; exceptions from
caller accessors propagate, and no caller-created reentrant mutation guarantee
is claimed. The checked path has no pole screen.

Python caps are `MAX_SAMPLES = 2^24`, `MAX_TAPS = 2^20`, `MAX_ORDER = 1024`.
The package raises `FilterError` subclasses rather than returning `Result`.
`FftError` is defined inside `fir.py` but is absent from the package `__all__`
and has no raise site in the pinned source. Validation order and Python
accessor exceptions are recorded per operation, not generalized across APIs.

### TypeScript

The package index exports `Biquad`, `sosfilt` with aliases `sosCascade` and
`sos_cascade`, `CheckedBiquad`, `checkedSosfilt`; `fir`, `firFft` and alias
`fir_fft`; `iir`, `lfilter`, `filtfilt`; `designLowPass`, `designHighPass`,
`designBandPass`, `firwin`, `butterworthLowpass`, `butterworthHighpass`,
`butterworthBandpass`, `chebyshev1Lowpass`; types `FilterCoefficients` and
`FirwinOptions`; constants `MAX_FILTER_TAPS`, alias `MAX_TAPS`,
`MAX_SIGNAL_LEN`, alias `MAX_SAMPLES`, and `MAX_ORDER`; and error classes
`FilterError`, `EmptySignalError`, `EmptyKernelError`,
`InvalidCoefficientError`, and `FftError`.

The lane uses JavaScript `number` (binary64) and commonly accepts
`Float64Array | ArrayLike<number>`; outputs are normally `Float64Array`.
Legacy Biquad/SOS normalization uses reciprocal multiplication. `Biquad`
exposes readonly normalized coefficient fields and TypeScript-`private`
`z1`/`z2` (compile-time privacy only; ordinary runtime properties). It has
`reset`, `processSample`, `process`, and static `lowpass`, `highpass`,
`bandpass`, `notch`, `allpass`, and `peak` constructors. Legacy `process`
Number-coerces indexed values and mutates state per sample. `sosfilt(sos,
signal)` is one-shot with fresh section state on each call. Checked APIs use
strict finite primitive numbers and direct division, validate output/delay
state, and make block processing failure atomic for filter-owned state on
ordinary failures; they do not promise atomicity against caller-created
reentrant accessors or add a pole screen.

TypeScript caps are `MAX_SIGNAL_LEN = 2^24`, `MAX_FILTER_TAPS = 2^16`, and
`MAX_ORDER = 2^10`. The exported aliases above share implementations; inventory
both the alias and canonical name. `filtfilt`, `firwin`, and the additional
Butterworth high/band-pass constructors are TypeScript-only public functions
at this pinned revision and must not be silently omitted as non-parity.
`FilterCoefficients` is `{b: Float64Array, a: Float64Array}`;
`FirwinOptions` is `{window?: string, passZero?: boolean}`. A scalar cutoff
selects low/high pass by `passZero`; a `[low, high]` pair selects band-pass or
band-stop. The FFT window parser accepts rectangular, Hann/Hanning, Hamming,
Blackman, and Kaiser; Python accepts its four enum names, stripping and
lowercasing string input.

## 5. Warrant and source-proof status

At the pinned revision, the canonical, Rust, and Python Warrant copies share
one blob; TypeScript is a distinct copy. Each declares the six operations
`fir`, `fir_fft`, `iir`, `design_low_pass`, `design_high_pass`, and
`design_band_pass` using `Bytes`/`Nat`. The files have no functional claim or
example that reaches an implementation, no Biquad/SOS declaration, and no
lane binding, generated evidence harness, or assurance report for this package.
The TypeScript copy retains work and heap expressions for FIR and FIR-FFT, a
work expression for IIR, and omits hostile-input rows for high-pass and
band-pass `window`. That is a lane-specific unresolved obligation; this
inventory does not infer that retained rows are false or their resource units
are meaningful.

Warrant `Bytes` length is not a sample/tap count without a lane-specific codec
and representation. Rust `f32`, Python binary64 sequences, TypeScript
`Float64Array`/`ArrayLike<number>`, FFT scratch, padding, and allocation must
not be assigned a common byte framing by assumption. Warrant's checked binding
validator requires every declared operation to have a binding and negative
control; the DSP package has no such bindings. The Rust evidence-harness
compiler translates a checked Warrant but translation does not execute or
validate the native source binding. HostTy and the filter state protocol are
separate unresolved capabilities.

The existing resource pilot does not establish heap/depth bounds. The current
main revision extends VER04h §4.1 with exact-enumerable refinement rescue and
an acceptance floor for non-enumerable refined properties; the pinned AF-04a
subject predates that addition, so producer evidence must name its VER04h
revision. AF-04b may later bind a deliberately scoped public operation with
explicit gaps; a partial FIR pilot
must not become a six-operation or package-wide badge. AF-05b is a separate
release-blocking native/source float proof prerequisite. It must identify the
compiler/toolchain, f32/f64 bit framing, endianness, NaN/subnormal/signed-zero
and rounding policy, FMA, state horizon or induction, transitive FFT/libm and
allocator behavior, and source/IR/CNF/DRAT identities with an independent
DRAT check and faulty control. FL1 scope, a SAT syntax check, WIR model, or a
portable exact fixture is not that proof.

## 6. Producer inventory and dependencies

The producer audit is deliberately per implementation:

* Python: seeded `for_all` and mutational fuzz exist. The current mutator's
  1-in-10 corpus admission is not execution coverage feedback. Callback
  exceptions are the crash path; callback return values are ignored by that
  runner. The engine has no verified process watchdog or native branch
  instrumentation.
* TypeScript: PBT and semantic coverage-map fuzz entry points exist. The
  current runner does not account timeout/OOM enum outcomes as campaign
  results. It must not be credited with native edge instrumentation.
* Rust: the fuzz runner reports callback-returned Timeout/OOM; the separate
  PBT runner does not provide that fuzz-outcome accounting. The fuzz target
  supplies the `CoverageBitmap`. This is semantic/caller-provided feedback,
  not compiler-instrumented native coverage.

AF-04c remains a P1 follow-up for feedback/outcome claims. AF-04d is a separate
P2 for automatic Python optional test-dependency selection. AF-02b's explicit
ordinary BUILD edge is the current conservative workaround; runtime Python
DSP dependencies remain unchanged. AF-04b bindings depend on this inventory
and producer correction. AF-05b remains a hard source-proof gate.

## 7. Machine-readable inventory and validation contract

AF-04a's implementation artifact is
`code/specs/assurance/dsp-filters-inventory-v1.json`. It contains:

1. subject commit and package manifests/source blob OIDs, plus the shared
   executable fixture's exact blob and case identities;
2. exhaustive declared public-export entries, including aliases, module paths,
   methods, types, constants, errors, and lane visibility;
3. operation-local scalar types, buffer forms, output form, validation and
   error behavior, caps with units, state/reset/commit semantics, and
   intermediate/resource notes;
4. named test/source paths with test identity and bounded domains, plus
   provenance requirements for executable run receipts;
5. per-lane PBT/fuzz producer capability and accounting profile;
6. each Warrant copy's digest, operations, declarations, bindings, generated
   harness/report status, and precise unresolved resource/representation rows;
7. evidence rung status (`source`, `public_execution`, `model`,
   `Warrant_binding`, `native_refinement`) with explicit `not_live`/`unknown`
   states rather than inferred zeros.

The validator compares inventory in both directions against an immutable
baseline pinned by this specification and source loaded with
`git show <subject>:<path>`. It also compares audited source, test, producer,
Warrant, and shared-fixture blobs at committed `HEAD` with the baseline;
changed inputs cannot silently inherit the old inventory. It separately walks
the pinned and current committed package trees for bindings and reports. These
are Git-object/tree guards, not a dirty working-tree check. It must not trust an editable manifest to supply its own
expected export set or digest. It recognizes a documented finite
set of Python AST, TypeScript export-block, Rust re-export/module, and Warrant
declaration forms; unknown syntax fails closed or is marked unresolved, never
treated as an empty API. The baseline covers qualified module paths, aliases
and targets, argument order, type/runtime namespace, public methods/fields,
and package tree paths. Warrant copies are checked as comment-aware
declarations. A missing file in one blob does not prove that no package-level
binding exists; inspect the complete pinned package tree.

Schema, source identity, and semantic completeness are separate failure
classes. The checker provides 44 negative corruption/source controls and one
positive candidate-path control. The controls include scope/precision and
typed-namespace mutations, duplicate identities, producer-role swaps,
contract-note deletions, Warrant resource/provenance promotions, trait/error
surface omissions, shared-fixture drift, upstream/constructor error omissions,
and unrecognized TypeScript exports. Detailed behavior prose is a curated,
reviewed source fact, not mechanically derived behavior or native proof.
They prove that (a) malformed data
fails schema validation, (b) removing a known export, alias, method, or field
fails completeness, (c) changing an alias target or swapping same-named
Biquad lane identities fails semantic binding checks, (d) changing a pinned
source blob fails identity validation, (e) a historical receipt for another
subject/lane/op/domain/kind does not satisfy the current key, and (f) promoting
a non-live binding/native proof fails even when valid unrelated evidence is
present. Evidence IDs bind subject commit, operation, lane, evidence kind, and
domain. `public_execution` requires a matching run artifact; a test-source
declaration is only `configured`, not `executed`. The no-binding/no-native-proof
baseline is independently checked against the pinned package tree, including
known package-root binding and harness paths. The checker admits only
source-configured evidence for this inventory; it does not mint an executed
receipt or promote a Warrant/native proof rung. JSON schema validation alone
does not establish source completeness; independent source comparison remains
required.
