## Unreleased — #18417 — the JIT's McCarthy car / cdr of a non-pair fail

- `jit_lisp`: `dyn_pair_first` / `dyn_pair_rest` (McCarthy `CAR` / `CDR`) answered nil for a non-pair, so `(CAR 5)` returned a value on the JIT while the VM, LLVM and native columns failed. They now fail on both tiers with `dynval-runtime`'s refusal text (`dyn_pair_first: argument with tag 0 (int) is not a pair`). The interpreter tier gets `VMError::TypeError`. The compiled `GenericCirJit` callback records `TypeError: …` in the JIT's error slot, and the JIT stops after that call (new in `jit-core`). The module docs no longer describe mapping the error to nil.
- `jit_mccarthy`: new `car_and_cdr_of_a_non_pair_fail_on_the_jit`. It covers `(CAR 5)`, `(CDR 5)`, `CAR` of a symbol, and the same reads inside `LAMBDA` and a recursive `LABEL`, which run on the compiled tier. Each must fail with the refusal text, `TypeError` and no `0x`. The reference `mccarthy-lisp-vm` must refuse each one too, and a real pair still reads. Falsified two ways: with the old callbacks `(CAR 5)` returned 0, and with only the compiled callback's report disabled, the `LAMBDA` row returned 0.
