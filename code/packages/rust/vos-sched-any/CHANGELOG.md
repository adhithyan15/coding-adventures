# Changelog

All notable changes to this package are documented here.

## Unreleased — the component check and the coverage gate (VOS-039a)

- `vos.toml` declares `coverage-floor = 95`; BUILD gains the Linux `cargo tarpaulin ... --fail-under 95` line (VOS-D070) and, last, `vos-link check-component .` (BUILD and BUILD_windows), which checks the file set, the BUILD lines 1 to 6 and 9 with their guards, the build-tool row and the floor (VOS04 5.6). Nothing else about the crate changed. Measured line coverage of `src/lib.rs`: 100% (67 of 67 lines).

## Heap rows restored (VOS-038c)

- `heap <= 0` is declared on every bound operation again (VOS-D063): the harness's heap observer now
  counts the export call only, not its own result marshalling. `warrant/impl.part`, the generated
  `code/specs/vos-sched-any.warrant`, `tests/generated/warrant_evidence.rs` and `evidence/test-manifest.json`
  regenerated; every operation records `max_observed_heap 0`.

## Unreleased — regenerated evidence harness (VOS-038b)

- `tests/generated/warrant_evidence.rs` regenerated with `gen_evidence` for the observer timeout clamp (`WARRANT_OBS_TIMEOUT_SECS` at most 24 h, `checked_add` deadline; VER04j). No test, case count or recorded evidence manifest changes.

## [0.1.0] - Unreleased

### Changed (VOS-038a, WX-SV2)

- `init` is bound with `field-flip` and `alpha_w` with `field-zero,field-flip`; the harness is
  regenerated (49 ok, still no tolerance script; `-any` has no `init` control, no claim has `init`
  as subject). New sabotage lines: `safety_init` (flip of `init`, flip of `alpha_w`) and
  `dispatch_covers_run` (flip of `alpha_w`), neither attackable with `field-zero`.

### Changed (VOS-D081)

- Regenerated for the contract's new `safety_init` claim: `code/specs/vos-sched-any.warrant`, the
  generated harness and the manifest. 8 exhaustive claims, 262,914 cases, 45 tests, all pass. An
  `init` with mask 8 now fails `safety_init` in the exhaustive, property and fuzz suites (checked in a
  scratch copy). No BUILD sabotage line: the claim's only fault, `field-zero` on `alpha_w`, is inert.

### Added

- VOS-012a: the most-general scheduler (`code/specs/VOS10-scheduler-contract.md` section 11.2).
  `impl Sched for AnySched` at `N = 8`: a ready-set byte plus a private oracle byte `choice`;
  `dispatch` proposes the thread the oracle names, validates it and defaults to `Idle`;
  `insert` and `remove` never read the oracle. Sound and covering. Class K, kind `any`.
  `no_std`, `forbid(unsafe_code)`, no loop, no division, no panic path.
- The ghost face (the only oracle write path): feature `ghost`, a public-field `Image`
  (`mask`, `choice`), `AbsW`, `CfgN` and `vos_ghost_*` wrappers.
- `vos.toml` (kind `any`, obligations `any` and `safety`, no `canonical`),
  `warrant/impl.part`, `evidence.bindings`, `required_capabilities.json` (empty).
- `code/specs/vos-sched-any.warrant`, generated by `vos-link gen-doc`, and `check-doc` with the
  R6 rules for kind `any` in BUILD.
- The VER04h evidence: 7 exhaustive claims, 262,912 cases, all passing, with 18 negative controls
  and the regeneration check and sabotage lines in BUILD.
- `tests/behaviour.rs`: every mask and every oracle value against a reference, and a mutation
  sanity check of the soundness and coverage predicates. 100% line coverage measured once by hand.

### Changed

- WD-HARN1b: `tests/generated/warrant_evidence.rs` regenerated with `gen_evidence` for the WD-HARN1b
  changes to the obs region of the Warrant prelude (`Bail out!` is written with `writeln!` to
  stderr, the dead latch is gone). No hand edit; the evidence manifest is unchanged.
- The sabotage lines in `BUILD` and `BUILD_windows` now fail when the sabotaged run prints
  `Bail out!`, not only when it lacks a `not ok ` line (a hang after an intended failure no longer
  passes silently).
