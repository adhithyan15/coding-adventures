## 0.583.0 (UNRELEASED)

- LANG84 phase 4b — release selection in lang-aot. New `compile_source_to_iir_at(language, release: Option<&str>, source, module_name)`; `compile_source_to_iir` is `_at(.., None, ..)`. New `LanguageRequest { language, release }` with `LanguageRequest::parse("perl@5.004_72")` (splits on the first `@`; `perl@` is an error) and `From<Language>`. Every `compile_file_to_*` entry point now takes `impl Into<LanguageRequest>`, so existing `Language` callers and fn-pointer tables compile unchanged while the CLI's `--lang perl@<release>` reaches all of them through one helper. New typed errors `LangAotError::UnknownRelease { language, release, nearest }` and `ReleaseNotAvailable { language, release, stage }`, mapped from the Perl frontend's own variants; a release for a language with no inventory (`twig@1`) is `UnknownRelease`, and release text is bounded to 64 characters with control characters escaped before it is echoed. Perl's default is now `5.38.0` (an inventory release grounded in tag `v5.38.0`), and the produced module records its release in `IIRModule::release`. Tests: `language_request_parses_an_optional_release`, `compile_source_to_iir_at_selects_and_records_one_release`, `release_errors_are_typed_and_never_fall_back`, `file_entry_points_honour_a_release_request`. Locally the eleven Perl matrix rows ran 66 cells (22 CLR/BEAM skipped: no `dotnet`/`erl`) and agreed with host perl v5.38.2, whose `perly.y`, `toke.c` and `keywords.h` blobs are identical to v5.38.0's. Security review (sibling session, all findings low/info, all addressed): `Display` for both release variants passes every field through an idempotent `neutralize` (escapes ASCII controls and every non-ASCII character `char::escape_debug` treats as unprintable, which covers bidi overrides, U+2028/U+2029 and tag characters, plus the blank Hangul fillers; keeps printable ASCII as is; caps at 512 characters). A re-review returned VERDICT: PASS, so a value built outside lang-aot cannot inject terminal sequences and already-escaped text is not escaped twice; `Language::parse` now echoes at most 64 escaped characters of an unknown name (new test `release_errors_neutralize_text_built_outside_this_crate`).
