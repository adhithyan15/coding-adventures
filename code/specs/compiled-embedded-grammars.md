# Compiled / Embedded Grammars

## 1. Motivation

Every lexer and parser in this monorepo is driven by a grammar file under
`code/grammars/<name>/<name>.tokens` (lexers) or `<name>.grammar` (parsers).
A package can obtain that grammar in one of two ways:

- **Embedded (compiled-in):** the grammar is baked into the build artifact at
  compile time — as native data structures, an embedded string constant, or a
  bundled resource. The package never touches the monorepo source tree at run
  time.
- **Runtime-file (fragile):** the package walks up from its own source location
  at run time (`#filePath`, `__file__`, `runtime.Caller`, `__DIR__`, …) and
  reads `code/grammars/...` off disk.

The runtime-file approach has bitten us repeatedly and by construction:

1. **It breaks when the grammar tree moves.** PR #7475 relocated every grammar
   into a per-grammar `code/grammars/<name>/` subdirectory. Every embedded
   consumer kept working; the Swift lexers/parsers — which hard-coded the old
   flat `grammars/<name>.tokens` path — all failed at test time with
   *"The file doesn't exist"*, turning `main` red (fixed reactively in PR #8133).
2. **It cannot work for a published, standalone package.** These packages are
   meant to be publishable to their language registries. A published artifact
   does not carry the monorepo `code/grammars/` tree, so a runtime walk-up finds
   nothing on an end user's machine.
3. **It couples run-time behavior to repository layout**, which is exactly the
   kind of hidden dependency that a refactor cannot see and CI does not localize.

This spec makes **compile-time embedding the required standard** for every
grammar-driven lexer and parser, and defines a CI guard so the fragile pattern
cannot come back.

## 2. Standard

> **Every lexer and parser package MUST obtain its grammar from a compile-time
> embedding of the canonical grammar file. Reading `code/grammars/**` from the
> filesystem at run time is forbidden.**

The single source of truth remains `code/grammars/<name>/<name>.{tokens,grammar}`.
Embedded copies are **generated** from that source and checked in; a CI
sync-check regenerates them and fails on drift, so the canonical file and the
embedded copy can never disagree.

### 2.1 Accepted embedding mechanisms

**Native-struct is the standard.** The grammar is parsed at build time by the
generator and emitted as source that constructs the language's `TokenGrammar` /
`ParserGrammar` value directly — a generated `_grammar.*` /
`Generated/TokenGrammar.*` module. Nothing is parsed at run time; the compiled
artifact contains the grammar as native data. This is what Rust, Python,
TypeScript, and Haskell already do, and it is the target for every remaining
language (Swift, Go, Elixir, Ruby).

The repo also contains a weaker **embedded-text** variant (C# `EmbeddedResource`,
Java jar resource, a few Rust `include_str!` stragglers) that embeds the raw
grammar text and parses it at first load. It satisfies the *"no runtime tree
read"* bar but is **not** the target style: new migrations use native-struct so
the grammar is truly compiled, not merely bundled. Existing embedded-text
packages (C#, Java) are already off the fragile path and are left as-is; only
their CI guard is enabled.

## 3. Swift mechanism (first slice)

Swift joins the **embedded-text** family, matching the other statically-typed,
resource-embedding languages (C#, Java). SwiftPM cannot bundle a resource that
lives *outside* the target directory (the grammars live in `code/grammars/`), so
`Bundle.module` is not an option without duplicating files. Instead we generate
a Swift source file that embeds the grammar text as a **raw string literal**, and
parse it with the existing, well-tested `parseTokenGrammar` / `parseParserGrammar`.

### 3.1 Generated file

For a package `swift/algol-lexer`, the generator emits
`Sources/AlgolLexer/_Grammar.swift`:

```swift
// Code generated by grammar-tools. DO NOT EDIT.
// Source: code/grammars/algol/algol60.tokens
// Regenerate with: swift run grammar-tools-embed swift/algol-lexer

enum EmbeddedGrammar {
    /// Raw contents of code/grammars/algol/algol60.tokens, embedded at
    /// compile time so the lexer never reads the monorepo tree at run time.
    static let algol60Tokens: String = #"""
    <verbatim grammar text>
    """#
}
```

Key rules for the generator:

- **Raw string literals only.** `.tokens`/`.grammar` files contain regex source
  with backslashes (`\d`, `\(`, `\\`) that a normal Swift string literal would
  misinterpret as escapes or interpolation. The literal MUST be raw
  (`#"""…"""#`). If the grammar text itself contains the closing fence
  `"""#`, the generator adds pound signs until the fence is unambiguous
  (`##"""…"""##`, etc.).
- **Verbatim bytes.** No trimming, re-indenting, or newline normalization — the
  embedded string must be byte-identical to the source file so parsing behaves
  exactly as reading the file did.
- **Versioned families** (e.g. `algol60`, or ecmascript `es1`/`es3`/`es5`) emit
  one constant per version and a lookup, so the existing version-selection logic
  is preserved.

### 3.2 Migration of `loadGrammar()`

Only the *source of the text* changes; the parse call is unchanged. Before:

```swift
let thisFile = #filePath
var url = URL(fileURLWithPath: thisFile)
for _ in 0..<6 { url = url.deletingLastPathComponent() }
let tokensURL = url.appendingPathComponent("grammars")
    .appendingPathComponent("algol")
    .appendingPathComponent("\(normalizedVersion).tokens")
let content = try String(contentsOf: tokensURL, encoding: .utf8)
return try parseTokenGrammar(source: content)
```

After:

```swift
let content = try EmbeddedGrammar.tokens(for: normalizedVersion)
return try parseTokenGrammar(source: content)
```

`Foundation`/`URL` file access disappears from the loader entirely.

## 4. Generator

A `grammar-tools-embed` executable target is added to `swift/grammar-tools`
(mirroring Haskell's `grammar-tools` `app/Main.hs`). It takes a package path,
reads the canonical grammar file(s) that package needs from `code/grammars/`,
and writes the package's `_Grammar.swift`. Because the embedded-text transform
is a trivial, deterministic wrapping (fence + escape-free copy), a portable
regeneration script is also provided so the **CI sync-check** can run without a
Swift toolchain on the runner path if needed.

## 5. CI guard (regression prevention)

Two checks, added to the build-tool BUILD-contract validator and scoped to Swift
in this slice (extended per-language as each language migrates):

1. **No runtime grammar reads.** Fail if a Swift lexer/parser package's
   `Sources/**` references `#filePath` together with `grammars` /
   `String(contentsOf:` — i.e. resolves a grammar path at run time.
2. **Embedded copy in sync.** Regenerate `_Grammar.swift` from the canonical
   grammar and fail if the checked-in file differs.

Together these make the fragile pattern un-mergeable and keep the embedded copy
honest.

## 6. Rollout

The Swift slice is delivered first (it is the pattern that just broke and is the
smallest 100%-fragile language). It establishes the generator shape, the
`_Grammar.*` file convention for embedded-text languages, and the CI-guard
mechanism. The remaining languages follow in their own PRs, in rough order of
value: **Go** and **Elixir** (100% fragile, need new generators), then finishing
**Ruby** (wire up its already-generated output), **Python**, **TypeScript**, and
**Rust** stragglers. Each language turns on its CI guard as it completes.

## 7. Non-goals

- Changing the grammar file format or the `grammar-tools` parsers.
- Native-struct pre-parsing for Swift/Go/Elixir. Embedded-text is the required
  bar; a later optimization may pre-parse, but it is out of scope here.
- Touching the already-complete languages (Haskell, C#, Java) beyond enabling
  their CI guard.
