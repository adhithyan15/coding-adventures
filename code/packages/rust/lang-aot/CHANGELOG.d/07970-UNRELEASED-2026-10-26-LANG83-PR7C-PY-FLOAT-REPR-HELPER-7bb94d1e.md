## Unreleased — LANG83 PR7c-py — Python prints floats through its own `repr` helper

- `python-iir-compiler` 0.4.0 no longer emits `write_f64_py`: a Python module that prints a float carries the compiler-written `__py_write_float` (built from `f64_class`, `f64_signbit`, `f64_digits`, `f64_exp10`) and three integer helpers, and each float `print` is one `call` of it, then `putchar 10`. A module that prints no float is unchanged. All 138 Python rows print exactly what they printed before; locally 828 cells ran (native x86-64, LLVM, WASM, JVM, VM, JIT; 372 trapped as expected) and the Python 3 rows agree with host CPython 3.13.16. No row changed its columns: the five literal-only float rows still list all eight, and every row BEAM refuses does `f64_*` arithmetic.
- `python_rows_pass_the_lang83_check_on_all_nine_backends` walks every function, allows `main` its old ops (minus `write_f64_py`) plus `call`s of the four helpers, allows the helpers their ops (`f64_class`/`f64_signbit`/`f64_digits`/`f64_exp10`, integer `add`/`sub`/`mul`/`div`, `cmp_eq`/`cmp_lt`/`cmp_gt`/`cmp_ge`, `putchar`, branches), rejects any `write_f64_py`, and now requires BEAM's refusal to name only the five arithmetic ops (it used to allow any `f64_*`).
- New `python_float_prints_lower_on_beam_once_the_arithmetic_is_gone`: every `py-float-print` row's module with its arithmetic replaced by constants passes BEAM's op check and lowers to BEAM bytes, helpers included.
- New `python_float_rows_run_with_their_call_free_float_helpers_compiled_by_the_jit`: pins the JIT's share of every float row's module (exactly `__py_digit_count` and `__py_write_digits`; `main` now `call`s the helper and runs on the interpreter tier), runs `main` with those compiled, and checks that the stdout and trap are unchanged and that the compiled tier wrote the significant digits.
- `Language::Python`'s docs and the README's Python float table describe the helper. The VM and JIT harnesses keep their `write_f64_py` sinks until PR7e.
