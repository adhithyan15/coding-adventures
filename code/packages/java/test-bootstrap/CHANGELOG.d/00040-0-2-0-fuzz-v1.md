## 0.2.0 - coverage-guided fuzz engine (VER06f)

### Added
- Package `com.codingadventures.testbootstrap.fuzz`: the VER06 mutator algebra
  (`Mutate`: flips by parity, O(len) for any count; arithmetic and boundary
  widths 1/2/4/8, both endians; block delete, insert, duplicate; splice;
  `mutateSequence` with a growth cap), each with a `...Big` form for
  arbitrary-size integers.
- 65,536-edge `Bitmap`, `Bitmap.corpusAdmit`, `Bitmap.calculateEnergy` (half away
  from zero).
- Deterministic `Fuzz.run` / `Fuzz.runOutcomes` campaign meeting every VER06
  section 9.1 contract: exact iteration budget, input-length cap, empty corpus
  becomes `[0]`, crashing seeds never mutated, every execution accounted for,
  honest `isClean`, timeouts and OOMs counted.
- Executor: any `Throwable` from the target is a crash (kind = class name, frames
  normalised to colon-free `Class.method`, JDK and engine frames dropped, deep
  recursion collapsed, the message never read); deterministic timeouts
  (`Handle.tick` step budget, which keeps throwing so it cannot be swallowed) and
  OOM (`Handle.reserve`, or a real `OutOfMemoryError` raised by the target).
- Coverage by caller-reported edges (`Handle.edge`, `Handle.edgeId`); the tier
  label is `caller-reported` or `black-box-uninstrumented`, never more than was
  collected. The JDK has no in-process per-edge API; a `java.lang.instrument`
  agent is recorded as future work only (VER06f 4.2).
- Signature dedup (`Signature.crashSignature`), exact-signature minimiser under a
  per-crash and a campaign-wide budget in which rejected candidates count, closed
  failure-id vocabulary, sanitised `Signature.formatTapFailure` and
  `tapFailures`; `Report` and `CrashRecord` print counts, signatures and frames
  only.
- `Corpus`: the production runner for the shared `fuzz-v1` corpus (25 cases),
  with package-private sabotage hooks for negative controls.
- Tests: the whole committed corpus replayed with per-op, per-case corruption
  controls that must name exactly the corrupted case; the 820 oracle vectors of
  the Go lane (read from their committed path) through both the `long` and the
  `BigInteger` entry points; targeted tests for the corpus weaknesses of backlog
  PT-F1 (unequal splice splits, every interest and delta constant); campaign,
  executor, minimiser, TAP and privacy tests.

### Security (CWE-400), applied from the start
- Every public count and size entry point has a ceiling (`Options` fields,
  `MAX_INITIAL_CORPUS`, `MAX_INPUT_BYTES`, `MAX_CRASHES`).
- `mutateSequence` counts the bytes it copies against `MAX_SEQUENCE_WORK`.
- Minimisation counts every candidate execution, accepted or rejected, against a
  per-crash and a campaign-wide budget.
- A campaign retains at most 256 MiB of seeds and crash inputs
  (`Report.admissionsDropped`, `CrashRecord.inputDropped`).
- Rendering an untrusted target's throwable catches `RuntimeException |
  StackOverflowError | AssertionError | LinkageError`, never `OutOfMemoryError`,
  and walks at most 4,096 stack elements.
- CI-redacted output (TAP lines, `toString`) carries no input bytes and no seed.

### Changed
- `build.gradle.kts`: version 0.2.0; sources compile as UTF-8.
