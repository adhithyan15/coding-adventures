## 0.586.0 (UNRELEASED)

- LANG84 phase 5b, slice 1: Ruby is an inventory language. `Language::has_release_inventory` now lists Ruby, so `--lang ruby@3.3.5` / `ruby@3.3.7` (and `compile_source_to_iir_at(Language::Ruby, Some(..), ..)`) compile against exactly that release, and `--lang ruby` against `DEFAULT_RELEASE` `3.3.6`; the module records the resolved ID in `IIRModule::release`. The Ruby frontend's `UnknownRelease { requested, suggestions }` and `ReleaseNotAvailable { release, stage }` map one for one onto lang-aot's typed variants: `ruby@3.3` is `UnknownRelease` with up to five `3.3.x` suggestions, `ruby@3.3.4` (no grammar pair) and `ruby@0.49` (a pair, but no IIR profile) are `ReleaseNotAvailable`. Nothing falls back. `ReleaseNotAvailable` now reads `<lang>: release X cannot compile yet (<reason>)` with a self-describing reason (`no grammar pair: pending` for Perl; `no grammar pair: grammar_stage none` or `no IIR profile: …` for Ruby), because "has no grammar pair yet" was wrong for a Ruby row that has one. Test: `ruby_release_requests_select_record_and_refuse_exactly` (selection, recording, all three refusals, hostile release text bounded and escaped, post-resolution errors name the release). Matrix rows with `Prog.release` on 3.3.5/3.3.7 are slice 2.
