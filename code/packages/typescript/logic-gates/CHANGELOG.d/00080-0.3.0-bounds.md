## 0.3.0

- BREAKING (security): `decoder`/`demuxN` reject select widths above
  `MAX_SELECT_BITS = 16` with RangeError before shifting or allocating.
  Previously JS `<<` (shift count mod 32) made 32/64/1000-bit selects silently
  return one output, 31 bits return `[]`, and 25-30 bits exhaust memory.
  `demuxN` no longer uses `Math.log2`; `nOutputs` must be an integer.
- `register`/`shiftRegister`/`counter` widths must be integers in 1..`MAX_WIDTH`
  (65536; counter `MAX_COUNTER_WIDTH` = 64); NaN/Infinity/fractions/-0 rejected
  before allocation.
- Caller state is validated on every path (hold, reset, increment) including
  `dFlipFlop`: real arrays, exact length, flip-flop objects with four bit
  fields, `counter` `value` length == width. Errors name the path, e.g.
  `state.value[3]`. Counter hold returns a fresh array.
- Hardening: caller arrays/state are snapshotted once by index and validated
  as a private copy (Proxy/getter/own `map`/`Symbol.iterator` cannot change
  values between check and use); flip-flop fields must be own data properties
  (no inherited/polluted or accessor fields); `muxN`/`encoder`/`priorityEncoder`/
  `decoder` require real arrays of at most 65536 elements before any `n & (n-1)`;
  error messages never stringify non-number values.
