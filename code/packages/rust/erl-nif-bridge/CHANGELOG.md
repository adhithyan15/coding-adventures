# Changelog — erl-nif-bridge

## [Unreleased]

### Added

- Windows support. A Windows NIF DLL cannot leave `enif_*` imports undefined and
  `beam.smp.dll` exports no `enif_*` names, so OTP passes `nif_init` a table of
  function pointers (`TWinDynNifCallbacks`). `src/win_dyn.rs` (generated by
  `tools/gen_win_dyn.py`) keeps a copy of that table and provides functions with the
  same names and signatures as the `extern "C"` block, so code using the crate does
  not change. The table order comes from the real OTP 27 (ERTS 15.2.7.8)
  `erl_nif_api_funcs.h`, read off the Windows CI runner and committed in
  `tools/otp27_nif_api_order.txt`; a unit test pins the entries this crate uses.
- `nif_init!` takes the callback table on Windows (`nif_init(callbacks)`) and stores
  it before returning the entry; hand-written entry points do the same with
  `win_dyn::win_init`.
- `make_i64` / `get_i64` use the 64-bit table entries on Windows (C `long` is 32 bits
  there).
- A README and this changelog (the crate had neither).

### Changed

- Fixed `ERL_NIF_UTF8`: it was 4, the real `erl_nif.h` value is 2 (found while checking the header; nothing in the repository used the constant).
- `win_init` copies the OTP 27 table size, so Windows needs OTP 27 or newer (the repository's CI pins 27.3.4.11); older releases have a shorter table.
- The `extern "C"` block is now `#[cfg(not(windows))]`; behaviour on Linux and macOS
  is unchanged.
