## 0.1.1

### Fixed

- `writeClassFile` now works on Windows. The embedded Python secure writer
  walked the output tree with `os.open(dir, O_DIRECTORY|O_NOFOLLOW)` and
  `dir_fd`, neither of which Windows supports: `os.open()` on a directory
  always raised `PermissionError [Errno 13]`, so every write failed on the
  `windows-2025` CI job. When `os.supports_dir_fd` lacks `os.open`/`os.mkdir`
  the writer now uses a path-check walk instead: each directory is created and
  then `lstat`ed, symlinks *and* junctions (`FILE_ATTRIBUTE_REPARSE_POINT`) are
  refused, a root or package directory that is a file is refused, an existing
  output that is a link or not a regular file is refused, and the bytes go to
  an `O_CREAT|O_EXCL|O_BINARY` temp sibling that is then `os.replace`d over the
  target (which never follows a link at the destination). The POSIX
  descriptor walk is unchanged.
- The relative path sent to the writer is now always `/`-separated. On Windows
  `join()` produced `demo\Example.class`, which the writer's `PurePosixPath`
  treated as one component, skipping the checks on `demo`.
- Class-filename components containing `\`, `:` or NUL are rejected, so a
  hand-built artifact cannot use a Windows separator or drive prefix
  (`..\..\x.class`, `C:x.class`) to escape the classpath root.

### Known limitation

- On Windows the path-check walk cannot detect a directory swapped for a
  junction *between* its `lstat` and the write; that needs handle-relative
  `NtCreateFile` traversal. The Rust and Python ports accept the same
  residual race on Windows.

### Tests

- Every write-safety test now runs under both the `auto` and `path-checks`
  strategies (via the internal `writeClassFileWithStrategy` seam), so POSIX
  runs exercise the Windows walk too. Directory links are made as junctions,
  which need no privilege on Windows. New cases cover creating missing
  directories, overwriting an existing class file without leaving temp files,
  a root that is itself a link, a package directory or output path of the
  wrong type, a symlinked output file (sentinel preserved), and escaping class
  filenames.
