## [0.2.1] — 2026-11-24

### Security
- LGE-KT-NARY: `AND_N`/`OR_N`/`XOR_N` now take ONE `copyOf()` snapshot after shape checks, then validate and compute only from the copy (closes the CWE-367 check-then-use window on a mutated array).
- Length is checked on `inputs.size` before copying; new public `MAX_INPUTS = 65536` (CWE-400). Null from Java callers (CWE-476) raises `InvalidShapeException` (module compiled with `-Xno-param-assertions` so the guard, not the compiler's NPE, fires).
- Bad elements are reported as `inputs[i]` (first offender) for all three gates.

### Added
- `InvalidShapeException(parameter, message)`, an `IllegalArgumentException` subclass for null / too short / too long input arrays. Shape errors win over bit errors.

### Changed (behaviour, note for callers)
- Bit-error parameter name is now `inputs[i]` for all three gates; previously `bit[i]` (`XOR_N`) and `a`/`b` (`AND_N`/`OR_N`).
- New 65536-input cap on `AND_N`/`OR_N`/`XOR_N` (previously uncapped). BREAKING for callers passing more than 65536 inputs.
- `-Xno-param-assertions` is module-wide: any new public function with a reference-typed parameter must carry an explicit null guard and a Java-null test.
