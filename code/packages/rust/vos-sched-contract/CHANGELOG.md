# Changelog

All notable changes to this package are documented here.

## [0.1.0] - Unreleased

### Added (VOS-040c)

- `vos.toml` says `sat = "model"`: the contract opts in to the host model-SAT lane (VOS31). `BUILD` and `BUILD_windows` are regenerated by `vos-link gen-build` and run `vos-model-sat check .` after `check-contract`; `warrant/lemmas.sat` is generated by `vos-model-sat gen .` and committed (40 rows, 36 counted obligations and the 4 trivial `closure_at_m` rows). No `src`, `Cargo.toml`, `contract.vos` or `.part` file changed, so the capacity recording is not staled.

### Added (VOS-039c)

- `warrant/obligations-any.part` gains seven oracle-preservation claims (VOS10 section 9.3): `insert_oracle_lo`, `insert_oracle_hi`, `insert_oracle_ids`, `remove_oracle_lo`, `remove_oracle_hi`, `remove_oracle_ids` and `alpha_build_with_oracle`.  Each of the six states, for one operation and every oracle value, that the image keeps the oracle (`.choice == c`, first, so the `_img` operation is the claim's subject), that its abstraction is the abstract step of the abstraction of the state, and that the answer is the abstract answer; they are split by half of the ids (`_lo` 0 to 3, `_hi` 4 to 7, from two `Bool` binders) and by four masks (`_ids`) to stay at 262,144 cases (the budget is 400,000).  Residual: the ids 8 to 255 on the 252 masks other than 0x00, 0xA5, 0x5A and 0xFF.  This is a contract-text change event: every `-any` regenerates (only `vos-sched-any` exists); the safety, policy, canonical and representation digests and the other two implementations are unchanged.

### Changed (VOS-039b-2a)

- `warrant/lemmas.table` is regenerated by `vos-link gen-contract` as `vos-lemmas 2`: it gains the two rows
  `variant Upd = Changed | Unchanged | OutOfRange` and `variant Pick = Idle | Run(U8)`, the CK10 correspondence of
  `src/lib.rs`'s enums with `contract.part`.  No source, lemma or mutant changed.  The crate is also judged by the new
  SH19 command-type rule in its BUILD (`Upd` and `Pick` pass: `u8` is the only payload).

### Changed (VOS-039b-1, VOS02 D-GD11)

- The generic contract check, `vos-link check-contract`, replaces the sibling crate
  `vos-sched-contract-check` (deleted).  `warrant/lemmas.part` gains a tenth lemma,
  `config_n_is_the_id_range` (`pre_insert(empty(), t) == (t < cfg_N())`), which ties `contract.vos`'s
  `config N 8` to the Warrant text: the tool generates `cfg_N` and must see the lemma fail on `N = 7` and
  `N = 9`.  Nothing embedded in an implementation's document changed, so no document digest moves.
- Added `warrant/mutants/<lemma>.part` (ten files, one `model` each: the nine mutants of the old suite
  and one for the new lemma) and the generated `warrant/lemmas.table`.
- `BUILD` and `BUILD_windows` are now generated by `vos-link gen-build` (identical, no shell syntax) and
  run `check-contract` and `check-component`.  `cargo test --lib --tests` replaces the single named test.
- The Rust-enum/Warrant-variant constructor test, the Warrant-model implementations and the 21 obligation
  mutants of the retired suite are not carried over (VOS10 section 12 records the fate of each part;
  VOS-D109 the controls lost).

### Added (VOS-012b0, VOS-D061)

- `tier representation` in `contract.vos` and `warrant/obligations-representation.part`: eight
  claims (`rep_init`, `rep_alpha`, `insert_rep_lo`, `insert_rep_hi`, `remove_rep_lo`, `remove_rep_hi`,
  `dispatch_rep`, `dispatch_rep_post`) over an implementation-supplied `rep(m: Ready, h: U8) -> Impl`
  and `hist(s: Impl) -> U8`.  `insert`/`remove` quantify EVERY `t: U8` (output, abstraction and closure of
  the post-state together), split by history half (`h` in 0..3 and 4..7 from two `Bool` binders;
  262,144 cases each); `rep_alpha` and `dispatch` use one packed `k: U8` (history in its low three bits;
  65,536 cases).  (A first draft packed `t = shr(k, 3)`, which missed ids 32..255 from image states.)  The contract text names no field of
  `Impl`.  `contract.part`, and so every existing document and digest, is unchanged.

### Added (VOS-D081)

- `warrant/obligations-safety.part`: `safety_init` (`forall b: Bool. dec(alpha_w(init())) == empty()`), the
  fifth safety claim. Before it nothing constrained `init` in the safety tier (`canon_init` is
  canonical-only), so an `-any` or round-robin scheduler could start from a non-empty ready set
  and pass every generated test. The safety block's digest and every implementation's embedded
  safety block change; the contract block, the policy, canonical and `any` blocks and every other
  claim's `claim_sha256` are unchanged.

### Changed (VOS-012a PR, VOS-D054, VOS-D079)

- `warrant/obligations-any.part`: `dispatch_covers_run` lost its `| t < 8u8` refinement. `mem` is
  false outside `0..7`, so the claim means the same, and the generated property suite can now run
  (the generator's rejection sampler gave up at 3 percent acceptance). Its enumerated cases are
  65,536 (were 2,048). Only the `any` tier's digests change; the safety, policy and canonical
  claims, the contract block and `vos-sched-fp-bitmap`'s document are unchanged.

### Changed (VOS-011 PR, VOS-D064)

- The nine model-level lemmas moved from `warrant/contract.part` to the new
  `warrant/lemmas.part`, which no implementation document embeds: the evidence generator
  refuses a claim that calls no operation (W0701). The contract-block digest changed
  (`1cafa96a...` to `fd4b88aa...`); every obligation's `claim_sha256` and every obligations
  block digest is unchanged. `vos-sched-contract-check` evaluates the lemmas from the new part.

### Added

- VOS-010: the scheduler interface contract (`code/specs/VOS10-scheduler-contract.md`).
  - `trait Sched` (`State`, `N`, `init`, `insert`, `remove`, `dispatch`), `Upd` and
    `Pick`; `no_std`, `forbid(unsafe_code)`, no dependency.
  - `warrant/contract.part`: the abstract state (ready set over 8 thread ids,
    priority = id), total abstract operations, `inv`, the safety and policy
    relations, `pre_` models and nine model-level lemmas.
  - `warrant/obligations-{safety,policy,canonical,any}.part`: 4 + 1 + 7 + 3 claims at VOS-010 (`safety_alpha_build` is a safety claim; `safety_init` made it 5 + 1 + 7 + 3, VOS-D081) in
    the fixed vocabulary of VOS02 R3, interim projection form (VOS02 section 4.4).
  - `contract.vos`: ceilings (`16 N + 32` steps, heap 0, depth 2; `init` `8 N + 16`)
    and the instance `N 8`.
  - `vos.toml` (class K, kind `contract`), `required_capabilities.json` (empty),
    `tests/trait_usable.rs`.
