## Unreleased

- LANG84 phase 7a — Python on every backend. `Language::Python` (`--lang python` or `py`, `.py` files) compiles through `python_iir_compiler::compile_source_at(.., None, ..)`. That is the frontend's default release, `3.13.16`, whose compiler walks the tree the generic `GrammarLexer`/`GrammarParser` build from `python3.13.16.tokens`/`.grammar`. LANG79's float pilot is not reachable from lang-aot. The module holds only LANG83 registry ops, plus `const`/`ret`. `+ - *` and unary `-` are the PR4 checked ops `i64_add_ovf`/`i64_sub_ovf`/`i64_mul_ovf`/`i64_neg_ovf`. `//` is `i64_div_floor`, `%` is `i64_mod_floor`, `print` is `print_i64` and `print()` is `putchar 10`. A known `-1` divisor is folded, so `MIN // -1` and `MIN % -1` never reach a divide. `main` returns `i64` 0, so no backend needed a change. `tests/lang_matrix.rs` gains eighteen Python rows, which declare all eight executable columns. They are every accepted case of `code/grammars/python/corpus/py-int-print/` verbatim: precedence, the floor `//` and `%` sign tables, unary signs, PEP 515 `_`, `print()` and `;`, layout, both i64 ends, the `-1` fold, four `Trap.DivZero` rows and five `Trap.Overflow` rows (`MAX + 1`, `MIN - 1`, `3037000500²`, `-MIN`, `MIN // -1`). For the overflow rows the oracle checks that CPython prints an int outside i64 there, which is the subset's stated divergence. The matrix gains `Expect::StdoutThenTrap(stdout, kind)` and `RunResult::TrappedAfter { stdout, kind }`, ported identically to the LANG84 phase 5a (Ruby) branch:
  - native, LLVM, JVM and CLR read the kind from stderr (`trap_kind_in`, pinned by `trap_kinds_are_read_from_every_columns_stderr`);
  - the WASM host resolves `env.__trap` and records the kind id;
  - VM and JIT map `VMError::Trap { kind }`;
  - BEAM rows run under a `try … catch error:K` launcher.

  There are four named tests: `python_rows_run_on_every_available_backend`, `python_rows_are_py_int_print_corpus_cases`, `python_rows_agree_with_the_host_python_oracle` (host CPython 3.13, skipped otherwise) and `python_rows_pass_the_lang83_check_on_all_nine_backends`. All are in BUILD with `-- --exact`. `feature_coverage_doc_counts_match_programs_source` pins Python at 18 rows / 144 cells. Locally (no `dotnet`, no `erl`), 108 Python cells executed and 54 of them trapped as expected; the 36 CLR/BEAM cells were skipped, and CI runs those.

- The host-python oracle test folds Windows' text-mode `\r\n` stdout back to `\n` before comparing, as the Ruby oracle had to on `build (windows-2025)`.
