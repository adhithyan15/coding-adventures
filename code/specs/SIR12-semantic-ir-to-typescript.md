# SIR12 — Semantic IR → TypeScript (Rust backend)

## Status

First backend for the narrow-waist Semantic IR
([`SIR10`](SIR10-narrow-waist-semantic-ir.md)).  Implemented as the
Rust crate
[`semantic-ir-to-typescript`](../packages/rust/semantic-ir-to-typescript/).

The crate consumes [`semantic_ir::Module`] and emits a single
**self-contained** TypeScript source file — no external runtime
imports, the helpers are inlined.  This is the user-chosen output
style (zero-runtime: copy-paste-deployable single file).

## Overview

```text
semantic_ir::Module                 (narrow-waist SIR v0)
   │
   ▼  semantic_ir_to_typescript::compile
Artifact { filename, source, metadata }
        │
        ▼ source is a single .ts file
        │
        ▼ no imports of @coding-adventures/* runtimes
        ▼ inlined helpers cover cons/car/cdr/symbols/print/closures
```

## Public API

```rust
use semantic_ir::{Backend, Module, Artifact, BackendError};

pub struct TypeScriptBackend { /* ... */ }

impl TypeScriptBackend {
    pub fn new() -> Self;
}

impl Backend for TypeScriptBackend {
    fn target_tag(&self) -> &'static str { "typescript" }
    fn accepts_features(&self) -> &'static [Feature] { ... }
    fn accepts_intrinsics(&self) -> &'static [&'static str] { &[] }  // v0
    fn compile(&self, module: &Module) -> Result<Artifact, BackendError>;
}

/// Convenience wrapper bypassing the trait.
pub fn compile(module: &Module) -> Result<Artifact, BackendError>;
```

## Capability declaration (v0)

Features the TypeScript backend accepts:

- `Closures` — lowered to JS function objects with bound captures.
- `Pairs` — lowered to a `__Pair` tuple type in the inlined runtime.
- `Symbols` — lowered to interned strings via `__Sym.intern`.
- `Strings` — lowered to TypeScript `string`.
- `DynamicTyping` — every value is typed `__Val` (a union).
- `OptionalTypeAnnotations` — narrowing emitted where SIR provides a
  type; otherwise `__Val`.
- `MutualRecursion` — JS hoisting of `function` declarations handles
  this naturally.
- `Globals` — lowered to module-level `let` declarations + an
  immediately-invoked `_init()` call.

Features it **rejects**:

- `TailCalls` — JS does not guarantee TCO; modules requiring it are
  rejected with a clear error.
- `Intrinsics` — the v0 backend accepts no intrinsics by name.
  Modules using intrinsics are rejected.  (A future revision may add
  `typescript`-tagged intrinsics like inline JS strings.)

A frontend whose manifest declares an unsupported feature is
rejected with:

```text
BackendError {
    kind:    UnsupportedFeature,
    message: "typescript backend rejects feature `tail_calls`",
    span:    module.span,
}
```

## Generated file layout

```ts
// Generated by semantic-ir-to-typescript v0 from SIR module `<name>`.
// Source language: <metadata.source_language>
//
// This file is self-contained — no runtime imports.  The `__Sir`
// namespace at the bottom contains all helpers.

// ── runtime (inlined) ──────────────────────────────────────────────
namespace __Sir { ... }

// ── globals ────────────────────────────────────────────────────────
let <global_name>: __Sir.Val = __Sir.NIL;
// ...

// ── functions ──────────────────────────────────────────────────────
function <function_name>(/* params */): __Sir.Val { ... }
// ...

// ── synthesised entry points ───────────────────────────────────────
_init();
const __sir_result: __Sir.Val = main();
```

The runtime block is **always** emitted, regardless of whether the
module uses pairs or symbols.  Dead-code elimination is the
consumer's problem (e.g. `esbuild --minify`).  v0 favours simplicity
over compact output.

## Inlined runtime

The runtime namespace is small and stable.  It defines:

```ts
namespace __Sir {
  // Value model.  Every Twig value is one of:
  export type Val =
    | number            // Int
    | boolean           // Bool
    | null              // Nil
    | string            // Str  (the value)
    | Sym               // Symbol
    | Pair              // cons cell
    | Closure;          // user-defined closure handle

  // Sentinel singletons.
  export const NIL: null = null;

  // Symbols — interned by name.
  export class Sym { readonly name: string; constructor(name: string) { this.name = name; } }
  const SYMBOL_TABLE = new Map<string, Sym>();
  export function intern(name: string): Sym {
    let s = SYMBOL_TABLE.get(name);
    if (s === undefined) { s = new Sym(name); SYMBOL_TABLE.set(name, s); }
    return s;
  }

  // Cons cells.
  export class Pair { car: Val; cdr: Val;
    constructor(car: Val, cdr: Val) { this.car = car; this.cdr = cdr; } }

  // Closures.  A Closure wraps a JS function plus its captured env.
  export class Closure {
    readonly fn: (...args: Val[]) => Val;
    constructor(fn: (...args: Val[]) => Val) { this.fn = fn; }
  }
  export function applyClosure(c: Val, args: Val[]): Val {
    if (!(c instanceof Closure)) {
      throw new Error("apply on non-closure");
    }
    return c.fn(...args);
  }

  // Builtins.
  export const builtins = {
    "+":  (a: Val, b: Val): Val => (a as number) + (b as number),
    "-":  (a: Val, b: Val): Val => (a as number) - (b as number),
    "*":  (a: Val, b: Val): Val => (a as number) * (b as number),
    "/":  (a: Val, b: Val): Val => Math.trunc((a as number) / (b as number)),
    "=":  (a: Val, b: Val): Val => sameValue(a, b),
    "<":  (a: Val, b: Val): Val => (a as number) < (b as number),
    ">":  (a: Val, b: Val): Val => (a as number) > (b as number),
    "cons": (a: Val, b: Val): Val => new Pair(a, b),
    "car":  (a: Val): Val => (a as Pair).car,
    "cdr":  (a: Val): Val => (a as Pair).cdr,
    "null?": (a: Val): Val => a === null,
    "pair?": (a: Val): Val => a instanceof Pair,
    "number?": (a: Val): Val => typeof a === "number",
    "symbol?": (a: Val): Val => a instanceof Sym,
    "print":  (a: Val): Val => { console.log(format(a)); return null; },
  };

  function sameValue(a: Val, b: Val): boolean {
    if (a instanceof Sym && b instanceof Sym) return a.name === b.name;
    return a === b;
  }

  export function format(v: Val): string { /* recursive formatter */ }

  // Truthiness — only false and nil are falsy.
  export function truthy(v: Val): boolean { return v !== false && v !== null; }
}
```

The actual emitted runtime is byte-identical across modules (apart
from comments) — backends produce it from a single inlined template
constant.

## Per-node lowering rules

| SIR node                    | Emitted TypeScript                              |
|-----------------------------|------------------------------------------------|
| `IntLit { value }`          | `<value>`                                       |
| `BoolLit { value }`         | `true` / `false`                                |
| `NilLit`                    | `null`                                          |
| `SymLit { name }`           | `__Sir.intern("<name>")`                        |
| `StrLit { value }`          | `"<escaped>"`                                   |
| `VarRef { name, Local }`    | `<name>`                                        |
| `VarRef { name, Param }`    | `<name>`                                        |
| `VarRef { name, Capture }`  | `<name>` (captured as ordinary closure)         |
| `VarRef { name, Global }`   | `<name>`                                        |
| `VarRef { name, Builtin }`  | `__Sir.builtins["<name>"]`                      |
| `If { cond, then, else }`   | `(__Sir.truthy(<cond>) ? <then> : <else>)`     |
| `Block { stmts, value }`    | `(() => { <stmts>; return <value>; })()`        |
| `LetBinding`                | `const <name> = <value>;`                       |
| `LetStarBinding`            | `const <name> = <value>;`                       |
| `ExprStmt`                  | `<expr>;`                                       |
| `DirectCall { fn, args }`   | `<fn>(<args>)`                                  |
| `IndirectCall { tgt, args}` | `__Sir.applyClosure(<tgt>, [<args>])`           |
| `BuiltinCall { name, args}` | `__Sir.builtins["<name>"](<args>)`              |
| `MakeClosure { fn, caps }`  | `new __Sir.Closure((..._a) => <fn>(<caps>,..._a))` |

Notes:

- Direct calls use plain TS function calls — top-level functions are
  emitted as plain `function` declarations, no name mangling.
- `MakeClosure` wraps a JS arrow that prepends the captured values to
  the call's argument list.  This matches the convention that the
  generated `Function` has `captures` first, then `params` (the
  order the lowerer commits to).
- `Block` is lowered to an IIFE because the statements may contain
  let bindings that should not leak.  Backends that want flatter
  output for some shapes (e.g. `If` whose branches are atomic) can
  add peephole passes later.

## Output formatting

- Indentation: 2 spaces.
- Line endings: `\n`.
- Generated file ends with a trailing newline.
- A `// SIR span: file:line:col` comment is inserted before each
  function declaration for source-trace.  Inline expression-level
  spans are NOT emitted in v0 (would bloat output).

## Validation

The backend calls `semantic_ir::validate(module)` before lowering.  A
module that fails validation is rejected without code generation.
This catches manifest / scope / structure errors at the SIR boundary
rather than producing malformed TypeScript.

## Tests

- **Unit tests** for each node-kind lowering rule.  Each rule has a
  positive test asserting the emitted snippet.
- **Golden tests** comparing the entire `.ts` output of canonical
  Twig programs (lowered via `twig-to-semantic-ir`) against committed
  fixture files.
- **Execution tests** — the emitted TypeScript is written to a temp
  file and run via `tsx` (or `ts-node`) if available on the CI box;
  expected stdout is asserted.  When TS tooling is not installed,
  these tests are gracefully skipped with a message.  A
  TypeScript-syntax-only check uses `swc-rs` (already a workspace
  dependency for other crates) to confirm the source at least parses
  cleanly.
- **Round-trip** integration: parse Twig, lower to SIR, compile to
  TS, parse the TS — every step must succeed for a corpus of
  ~10 small programs.
- **Negative tests** for rejected manifests:
  - A module declaring `TailCalls` must be rejected.
  - A module declaring `Intrinsics` (with any intrinsic) must be
    rejected by v0 (the backend has an empty intrinsic whitelist).

Coverage target: **≥ 95%**.

## Out of scope (deferred)

- **Source maps.**  v0 emits only function-level position comments.
- **Optimization passes** like constant folding or dead-let removal
  inside blocks — emitted code is correct but not tight.
- **Idiomatic top-level await / async** — v0 has no async surface.
- **Pretty-printer options** (line width, indent style) — the
  emitter is opinionated.
- **TS source-string-level intrinsic injection** — would let users
  embed raw TS via the intrinsic node.  Designed for a future
  revision; v0 rejects all intrinsics.
