# Changelog

## Unreleased - Round-3 security review fixes (VER08a divergence D25 onwards)

Each fix has a regression in `tests/test_secreview_round3.rs` built from the
reviewer's proof-of-concept crate, which printed `PASS` while `cargo check`
compiled the capability in.

- [false negative, HIGH-3] A file starting `#!/x"` (a shebang line rustc ignores) opened a string in the analyzer that swallowed the following code. The lexer now applies rustc's `strip_shebang` rule exactly (after a leading BOM: `#!` is a shebang line unless, after whitespace and non-doc comments, the next token is `[`).
- [false negative, HIGH-6] Whitespace was `char::is_whitespace`, not Rust's `Pattern_White_Space`: `std::fs::<U+200E>write` read as `std::fs` (PoC t9). Identifiers used `is_alphanumeric`, not XID: `extern crate std as s·x;` (U+00B7) bound `s` in the analyzer and `s·x` in rustc (PoC t4). Whitespace is now exactly `Pattern_White_Space`; any other non-ASCII character outside a literal or comment is lexed into an identifier and is `CAP003` (no XID/NFC tables in a zero-dependency crate); a byte-order mark is skipped only at offset 0. `extern crate NAME [as ALIAS]` must be followed by `;`, otherwise `CAP003`.
- [false negative, HIGH-7] `c"`/`cr#"` were lexed as C strings in every edition. In an edition-2018 crate `cr#" a " { std::fs::write(..) } " "#` is `cr`, `#`, a string, a block and a string, so the block is code (PoC t8). `Cargo.toml` `package.edition` is now read first (`CargoFacts::edition`) and passed to the lexer (`scan_sources_with_edition`, `Edition`): C-string prefixes exist only from 2021. An unknown edition (missing, `edition.workspace = true`, a per-target `edition` key, a future value, unparseable `Cargo.toml`) makes a raw C-string prefix `CAP003`; a cooked `c"` has the same boundaries either way and is not flagged.
- [false negative, HIGH-4] `include!` was matched only as `include!` or `std::include!`; the preludes re-export it and `prelude` is a pure module, so `std::prelude::v1::include!("payload.txt")` passed (PoC t3). Any `std`/`core`/`alloc` path ending in `include`, at any length, is now `CAP003`, including the `use` that imports it (`use std::prelude::v1::include as i;`). `include_str!`/`include_bytes!` stay pure (data, L-B).
- [false negative, HIGH-1] A glob re-exported through a local module was spelled only as `glob + <whole path>`: with `mod m { pub use std::*; }`, `m::process::Command::new(..)` became `std::m::process::Command` (unknown std module, whose `CAP003` glob spellings suppressed) and passed (PoC t12); with `mod m { pub use std::fs::*; }`, `m::remove_dir_all` became `std::fs::m::remove_dir_all`, i.e. only `fs:read` (PoC t13). Glob spellings are now `glob + suffix` for *every* suffix of every alias spelling (crate-/self-rooted paths included), glob paths are normalised through bindings at every segment (`use crate::s::*` with `pub use std as s`), a glob over a bare `std`/`core`/`alloc` root (`use std::*`, `use s::*` after `use std as s`) is `CAP003`, and `CAP003` from glob spellings is no longer suppressed when the glob prefix is such a bare root.
- [denial of service, LOW] Glob normalisation materialised (globs x binding targets) and counted only the globs it kept. Every spelling, pure or not, now counts against a 4,096 cap checked inside the loop; exceeding it is `CAP003`. Glob spellings in the walk are charged to the per-file 200,000-spelling budget.
- [false negative, MEDIUM-1] The `.read_dir()`-style receiver waiver (L4) checked only that the type name had no `use`/`type` binding. With a local `struct PathBuf` (own inherent `read_dir`) in one module and `use std::path::*;` in another, `PathBuf::from("/etc").read_dir()` is std's and was waived (PoC t11). The waiver is now refused whenever any glob import reaches outside the crate (head other than `crate`/`self`/`super`/`Self` after normalisation).
- [false negative, HIGH-2] A `macro_rules!` transcriber could build a path or attribute out of a `tt` metavariable and its neighbours without `::` or `#[` ever touching a `$`: `($s:tt) => { std $s fs $s write(..) }` with `m!(::)` (PoC t2), `($a:tt) => { # $a pub mod hidden; }` with `m!([path = ".."])` (PoC t6, also `[no_mangle]` without `CAP002`). Bodies are now split into `(matcher) => {transcriber}` arms; in each transcriber a `#` not starting `#[`/`#![` is `CAP003`, and a `tt` (or undeclared) metavariable or a repetition containing one, directly next to a path-capable identifier or another metavariable, or followed by `[` / `!`, is `CAP003` (also across repetition iterations and separators). Other fragments (`ident`, `expr`, `ty`, ...) cannot produce `::`/`#`, and a verbatim `$($t)*` pass-through of a matcher `$($t:tt)*` re-emits the caller's own tokens; neither is flagged. Matchers are no longer checked as code (a `$(#[$m:meta])*` *matcher* is not a splice); a body that is not a list of arms is `CAP003`. Accepted false positive: `a $op b` with `$op:tt` (vm-core, already failing).
- [false negative, HIGH-5] Root-level files reached the directories the scanner skips at the root: `build.rs` with `mod examples;` compiled `examples/mod.rs` (PoC t5); `[lib] path = "lib.rs"` with `mod tests;` (or inline `mod tests { mod x; }`) compiled `tests/` (PoC t10). In any root-level `.rs` file a `mod` whose name is a skipped directory (`tests benches examples target node_modules _build`, ASCII case-insensitive, inline or out-of-line, any nesting) is now `CAP003`, as is an out-of-line `mod` in a root file named like one (`tests.rs`) and a `mod` keyword not followed by a name (`m!(mod)`). In any `macro_rules!` transcriber, `mod $name;` and `mod $name { .. }` whose body may declare a module are `CAP003` (the invocation site may be a root file). The skipped-directory list is now one constant (`scanner::SKIPPED_ROOT_DIRS`) shared with the `Cargo.toml` reader.
- [hardening, LOW] `--generate-module` (`write_module_to_disk`) followed a symlinked `src/` or `src/capabilities.rs` and overwrote a file outside the package. Both are now checked with `symlink_metadata` and refused before writing (VER23a V11).
- [false negative, INFO] `std::fs::File::create_buffered` (creates/truncates like `File::create`) was `fs:read` (PoC t7). It is now `fs:write`.

### Second review of the round-3 fixes (VER08a divergence D34 onwards)

A second review built small crates that printed `PASS` (exit 0) while
`cargo check` compiled a std capability call. Each fix has a regression in
`tests/test_secreview_round4.rs` named after the review's case directory.

- [false negative, H1] Renames resolved only one level deep: a binding was expanded only through its *first* segment and a written path was substituted once, so `mod a { pub use std as s; } use a::s as t; t::env::var(..)` read as `a::s::env::var` (pure). The same hole covered `use super::i as j` over `use std::io as i`, `use crate::Q as P`, a nested `pub extern crate std as s2` renamed again, `use j::*` over such a rename and `t::include!(..)` (cases `alias2-*`, `extern-crate-nested-2level`). The binding table is now closed under substitution at every segment, to a fixed point. Each spelling carries the set of original bindings it came from and never reuses one, so self-similar names (`pub use self::sha256::sha256;` + `use crate::sha256;`) converge. Caps: 64 segments, 20,000 spellings, 4,000,000 substitution attempts, 16 rounds; exceeding one is `CAP003`. VER08a G-8 claimed same-named bindings were already followed; it now describes what the analyzer does. A converging alias cycle (invalid Rust) is no longer `CAP003`.
- [false negative, H6] Clock access through the pure list: `std::time::UNIX_EPOCH` was pure, so `std::time::UNIX_EPOCH.elapsed()` read the clock under an empty manifest (case `unix-epoch-elapsed`), and `rx.recv_timeout(..)` / `c.wait_timeout(..)` on the pure `std::sync` types slept (case `sync-timed-wait`). `UNIX_EPOCH` and the method `.elapsed(` are now `time:read`; `.recv_timeout(`, `.recv_deadline(`, `.wait_timeout(`, `.wait_timeout_ms(`, `.wait_timeout_while(` and their `Condvar::` / `Receiver::` UFCS forms are `time:sleep`, like `thread::park_timeout`. The evasion corpus case "time UNIX_EPOCH is pure" is now `time:read`.
- [false negative, MEDIUM] `file.set_times(..)` on a handle from `File::open` changed file metadata under an `fs:read`-only manifest (case `handle-method-escalation`). `.set_times(`, `.set_modified(`, `.set_permissions(` and `std::fs::File::{set_times, set_modified, set_permissions}` are now `fs:write`. The method heuristic is one function, `rules::method_call_rule`.
- [false negative, H2] `Self` was treated as a local path head and never resolved, so `impl Probe for std::path::Path { fn probe(&self) -> bool { Self::exists(self) } }` and `<Self>::is_file(self)` were pure (cases `self-impl-path`, `qualified-self-angle`). Inside the braces of every `impl [Trait for] Type` block, `Self::x` is now also classified as `Type::x` through the binding table. `Self` is resolved against every enclosing `impl` region (a misread region can only add spellings). When the self type is unknown (a metavariable, a `<A as B>::C` projection, or any `Self` inside a `macro_rules!` body), `Self::name` gets the method-call verdict of `.name(`.
- [false negative, H3] `type` aliases bound only the first path after `=`, and any other shape bound nothing without a finding: `type $n = std::path::Path;` in a transcriber, `type P = (std::path::Path);` and `type P = <std::path::PathBuf as std::ops::Deref>::Target;` left `P::exists(..)` pure (cases `type-ident-name`, `type-paren`, `type-qualified`); so did `type P = $t;`. The alias is now bound to every path on its right-hand side up to the terminating `;` (the alias's own generic parameters skipped); a right-hand-side metavariable binds it to an unknown type whose `P::name` gets the method-call verdict of `.name(`; a metavariable name, or an item the reader cannot delimit, is `CAP003`. `type` inside a `macro_rules!` matcher is a pattern and is skipped. The sweep shows new `CAP001` evidence (e.g. `type F = extern "C" fn(*const c_char)` now resolves `F::..` to `c_char`) only in packages that already fail.
- [false negative, H4] An `ident` fragment matches keywords, so a caller could supply the keyword of an item the transcriber spells: `($k:ident) => { $k std::io as out; }` with `kw!(use)` bound `out -> std::io` unseen (case `ident-keyword-use`), and `$k crate std as s;` with `kw!(extern)` bound `s -> std`, passing under an `ffi:call` manifest (case `ident-keyword-extern-narrow`). In a transcriber, an `ident`/`tt` metavariable (or a repetition ending in one) followed by a path-capable identifier, a string literal, another metavariable, a `{ .. }` group that can be a use tree, or `<` at the start of an item is now `CAP003`. `use` directly followed by a metavariable other than `$crate` (`use $i as out;`) is `CAP003`; `use $crate::..` is read as `use crate::..`. The rule is on the transcriber, not the call site: a call-site "bare keyword argument" rule is unsound (`kw!(use std;)` with `($k:ident $s:ident ;) => { $k $s as out; }`). The controls `ident-keyword-extern` and `ident-keyword-unsafe` still fail.
- [false negative, H7] `($e:expr, $m:ident) => { $e.$m() }` with `call!(Path::new(".."), exists)` called `Path::exists` without the method name ever appearing after a `.` (case `ident-method-splice`). In a transcriber, `.` followed by a repetition, or by a metavariable and then `(` or a turbofish `::`, is now `CAP003`; a spliced field (`$e.$f`) is not. bignum-core (already failing) gains two such findings for `self.$engine(&rhs)`.
- [false negative, H5] `Cargo.toml` target paths and `build` were only checked for escaping the scanned set, but the scanner reads only `.rs` files: `[lib] path = "src/lib.txt"`, `[[bin]] path = "src/tool.inc"` and `build = "build.txt"` compiled code the analyzer never read (cases `cargo-lib-nonrs`, `cargo-bin-nonrs`, `cargo-build-nonrs`), and `--emit-cert` certified the decoy `src/lib.rs` as `proved`. A `[lib]`, `[[bin]]`, `[[example]]`, `[[test]]` or `[[bench]]` `path`, or a `build` value, that does not end in `.rs` is now `CAP003`. `--emit-cert` and `--verify-cert` refuse a package whose `[lib] path` is not `src/lib.rs` (`CargoFacts::lib_path`), because the certificate's entry points and `source_digest` describe `src/lib.rs` only (VER23a V12). The three committed certificates (ct-compare, gf256, ca-assurance-report) still verify.
- [denial of service, LOW] `matcher_has_tt_repeat` rescanned the whole matcher for every transcriber repetition, so a long matcher with many `$($t)*` repetitions was quadratic (`perf-matcher-rescan-80000`: 14.3 s release; 40,000 x 40,000 in a debug test: 32 s). The matcher's `$( $x:tt ) sep? op` repetitions are now collected once per arm (`matcher_tt_repeats`) and looked up by name (0.5 s and 0.2 s). Verdicts are unchanged; the repo-wide sweep is identical.
- [hardening, LOW] `--generate-module` used `fs::write`, which truncates the existing file in place: a `src/capabilities.rs` hard-linked to a file outside the package overwrote that file (case `generator-hardlink`; `symlink_metadata` cannot see a hard link). The module is now written to a new temporary file in `src/` (`create_new`, never following an existing name) and renamed over the target, which replaces the directory entry and leaves the other link untouched (VER23a V13). A failed write leaves the non-`.rs` temporary file and names it, since the analyzer declares no `fs:delete`.

### Third review (VER08a divergence D43 onwards)

A third review built more crates that printed `PASS` while `cargo check`
compiled a capability call. The cheap cases are fixed, each with a
regression in `tests/test_secreview_round5.rs` named after the review's case
directory; the rest are documented as known open gaps (VER08a §8.1).

- [false negative, R5-1] The method heuristic tested only the token right after the method name, so an empty turbofish hid the call: `Path::new("Cargo.toml").exists::<>()` and `c.wait_timeout::<>(g, d)` were pure (cases `turbofish-exists`, `turbofish-wait-timeout`). An optional `::<..>` is now skipped before testing for `(`, and a `::<` that does not close counts as a call.
- [false negative, R5-2] A macro invocation in type position was read as a path named after the macro: `<ty!()>::exists(p)` classified `ty::exists`, `impl P for ty!()` made `Self` mean `ty`, and `type F = ty!();` bound `F -> ty`, all pure although `ty!()` expanded to `std::path::Path` or `std::sync::Condvar` (cases `type-macro-qualified`, `type-macro-impl-self`, `type-macro-alias`, `type-macro-condvar`). Each is now an unknown type, so `X::name` gets the method-call verdict of `.name(` (`exists` is `fs:list`, `wait_timeout` is `time:sleep`), as a metavariable already did. Found while fixing: `<(std::path::Path)>::exists(p)` named no self type; a parenthesised qualified self type is now read through the parentheses.
- [false negative, R5-3] `std::thread::park_timeout_ms(10)`, the deprecated `u32` form of `park_timeout`, was `thread:spawn`, so a package declaring only `thread:spawn` slept unseen (case `park-timeout-ms`). It is now `time:sleep`, like `park_timeout`.
- [false negative, R5-3] `use std::net::*;` brings `ToSocketAddrs` into scope without naming it, so `("127.0.0.1", 80).to_socket_addrs()` did a name lookup under a manifest declaring only `net:connect` (case `net-glob-to-socket-addrs`). `.to_socket_addrs(` is now `net:dns` through the method heuristic.
- [false negative, R5-3] `std::io` was pure apart from the standard streams, so `std::io::pipe()` created an OS pipe under an empty manifest (case `io-pipe`). `std::io::{pipe, PipeReader, PipeWriter}` are now `ffi:call`, the row VER08a already uses for raw OS handles: the capability taxonomy has no IPC category, and `CAP003` would make pipes undeclarable although the analyzer sees them exactly.
- [false negative, R5-3] Every `std::os::…::net` item was `net:connect`, so `std::os::unix::net::UnixListener::bind` (listens, and creates a socket file) passed under a `net:connect`-only manifest (case `unix-listener-class`). `UnixListener` and `UnixDatagram::{bind, bind_addr}` are now `net:listen`, like `TcpListener` and `UdpSocket::bind`.
- [false negative, R5-4] Associated-type projections were read as paths, so `<std::path::PathBuf as std::ops::Deref>::Target::exists(p)` (`Target` is `Path`), `D::Target::exists(d)` for `D: Deref<Target = Path>`, `Self::Target::exists(self)` under a `Deref<Target = Path>` supertrait, `<Self as Deref>::Target::exists` in a blanket impl and `<Arc<Condvar> as Deref>::Target::wait_timeout` were pure (cases `proj-deref-target`, `proj-generic-bound`, `proj-self-target-trait`, `proj-blanket-impl`, `proj-condvar-wait`). `<T as Tr>::A::item`, `Self::A::item` and `P::A::item` for a generic parameter `P` declared in the file are now unknown types, and an unknown type (projection, alias to a metavariable or type macro, unknown `Self`) gets the method-call verdict of its *last* segment instead of its second.
- [known open gaps] Still open after the third review, and documented with an example, root cause and intended fix in VER08a §8.1 (backlog rows in `code/specs/VER-BACKLOG.md`): **CA-OG1** (review G-C) a type alias whose generic parameter default names the type, `type F<P: ?Sized = std::path::Path> = P; <F>::exists(p)` (case `alias-default-param`); **CA-OG2** (review G-E) bypasses of the local-receiver waiver L4 when the local type derefs to `Path`: a `cfg`-ed out or `macro_rules!`-body inherent impl, an inherent method on another generic instantiation, a constructor building another instantiation, a same-named type in another module, and `self: Rc<Self>` (cases `waiver-cfg-out`, `waiver-macro-body`, `waiver-generic-instance`, `waiver-ctor-wrong-type`, `waiver-same-name-module`, `waiver-arbitrary-self`). Review G-A (associated-type projections) is closed by R5-4.

### Follow-up review of the third-review fixes (VER08a divergence D50 onwards)

A focused review of D43-D49 found no regressions, but some shapes the new
turbofish and projection rules did not reach. Each fix has a regression in
`tests/test_secreview_round5.rs` named after the review's case directory.

- [false negative, F4] The turbofish skip of D43 walked `::<..>` with a counter blind to brackets, so a `>` inside them closed it early: in `c.wait_timeout::<[u8; (2 > 1) as usize]>(g, d)` the token after the comparison was `1`, not `(`, and the call read as a field (case `tf_paren_gt`). `.name::<` is now a method call whatever follows, since a field takes no generic arguments; the turbofish is not walked.
- [false negative, F2] An attribute on a generic parameter hid its name from the projection rule of D49: in `fn probe<#[allow(unused)] D: Deref<Target = Path>>(d: &D)` the token before `D` is the attribute's `]`, not `<` or `,`, so `D` was not a parameter and `D::Target::exists(d)` read as a local path (case `proj_attr_param`). An identifier after the `]` that closes an attribute now starts a parameter too.
- [false negative, F3] A generic type alias carried a projection past the D49 rule: `type X<D> = <D as std::ops::Deref>::Target;` bound `X` only to `Deref` and `Target` (the alias's own parameter `D` is skipped), and `type X<D: Deref> = D::Target;` to `D::Target`, so `X::<std::path::PathBuf>::exists(p)` was pure (cases `proj_alias_generic`, `proj_alias_short`). An alias whose right-hand side holds a qualified group `<..>::` or a path headed by one of its own parameters is now also bound to the unknown type, so `X::name` gets the method-call verdict of `.name(`. Found while fixing: the alias's parameter reader counted names inside bounds as parameters (`type F<D: AsRef<File>>` declared `File`, against which a one-segment right-hand-side path `File` was dropped as trivial) and missed attributed ones; and both parameter readers ended a list at a `>` inside a bracketed default (`trait Tr<T = [u8; (2 > 1) as usize], D: ..>` hid `D` from the projection rule). Both now share one bracket-aware reader that takes top-level names only (`generic_list_names`). VER08a's D49 sentence claiming the three projection shapes "cover every projection path" is corrected.
- [false negative, F1] A turbofish on the associated-type segment hid a projection: at `exists` in `<std::path::PathBuf as std::ops::Deref>::Target::<>::exists(p)` the walk back from `::<>::` collected `Target` and stopped at the `>` closing `<PathBuf as Deref>`, so the path read `Target::exists`, pure; likewise `<D>::Target::<>::exists(d)` (cases `proj_qual_tf`, `proj_angle_tf`). `qualified_self_path` now continues through that `>` into the group before it, prepends its self type, and reports the group's `as` and the number of segments written after it, so the D49 projection rule applies. The walk is capped at 8 groups per path (`MAX_QUALIFIED_HOPS`); a longer chain is `CAP003`. A 2.1 MB file of 8-group chains takes 0.39 s (0.29 s before).
- [tests] Some turbofish regressions used shapes rustc rejects (E0107: a non-empty turbofish on a method with no generic parameters, `p.is_file::<u8>()`, `t.elapsed::<Vec<Box<u8>>>()`, and two F4 cases). They now use `Condvar::wait_timeout` / `wait_timeout_ms`, which take a type parameter (checked with rustc); the one unclosed-turbofish case is marked as exercising only the lexer. No analyzer behaviour changes.
- [known open gaps] VER08a §8.1 and `code/specs/VER-BACKLOG.md` are updated after the follow-up review. **CA-OG1**: the intended fix also binds the alias to the unknown type when a parameter default is a metavariable or a macro invocation (`type F<P = $t> = P;`, `P = ty!()`). **CA-OG2**: the root cause also ignores visibility (case `og2_private2`: a private inherent `exists` in another module is skipped by method lookup at the call site, which then reaches `Path::exists`), and the intended Deref check must also catch impls not spelled `impl Deref for Name` (derive macros such as `derive_more::Deref` and `shrinkwraprs`, `macro_rules!`-generated impls, a renamed trait, an impl through a type alias), failing closed on any non-std derive or macro-generated impl. A new backlog row, **CA-IPC**, records that the taxonomy has no IPC category, so `std::io::pipe` is `ffi:call` as a stand-in. F1-F4 are fixed, so no new open gap is added.

## 0.3.1 - Security-review fixes (VER08a divergence D14-D21)

Specs first: VER08a updated (rules §3.2-3.5.1, work ceilings §5, divergence log D14-D21).
Every fix has a regression that fails on 0.3.0 (corpus group `SECFIX` in
`tests/test_evasion_corpus.rs`; `tests/test_secfix_regression.rs`).

- [false negative, M1] `Path::exists(p)`, `std::path::Path::metadata(p)`, `PathBuf::read_dir(p)`, `<PathBuf>::is_file(p)` and `let g = Path::canonicalize;` were pure. Any `…::Path/PathBuf::<fs method>` is now `fs:list`; `std::path::absolute` is `env:read`. The path reader understands `>::item` and turbofish.
- [false negative, M2] `m!(include, "../tests/evil.rs")` through `macro_rules! m { ($mac:ident, $f:expr) => { $mac!($f) } }` evaded `CAP003`. A bare `include`/`include_str`/`include_bytes` argument of a macro invocation and any `$name!(..)` in a `macro_rules!` body are now `CAP003`.
- [false negative, M3] The line-oriented `Cargo.toml` reader missed top-level inline tables, `bin = [{ path = .. }]`, `package = { build = .. }`, `lib = { proc-macro = true }`, quoted table names, multi-line strings and multi-line arrays that reset the "current section". Replaced by a tokenizing reader that flattens every value to a key path, flags `path`/`build`/`proc-macro`/`proc_macro` anywhere outside dependency tables, refuses unverifiable values (multi-line strings, escapes, tables, arrays) and fails closed on anything it cannot parse. A line the old reader ignored (garbage without `=`) is now a finding.
- [denial of service, M4] Alias expansion materialised (entries x targets) before checking its cap (264 KB input -> 2.3 GB abort); candidate generation was quadratic in path length; `matching_close` rescanned from every `#[` (O(n^2) on `#[#[#[…`); glob count was uncapped. Now: de-dup before expansion and caps inside the loops, 64 segments / 64 spellings per path, per-file work budget, a single-pass bracket table, 256-glob cap, macro-body scan budget. All reviewer inputs finish in well under a second in a debug build and yield `CAP003`.
- [false negative, L1] `type F = File; F::create(..)`, `<File>::create(..)`, `type U = UdpSocket; U::bind(..)` escalated within a category. `type` aliases are bindings and `<T>::item` is classified as `T::item`.
- [false negative, L2] `core::arch`/`std::arch` `_rdrand*`/`_rdseed*` intrinsics are `rand:read` (`__cpuid` documented as informational).
