## 0.582.0 (UNRELEASED)

- LANG83 PR1b — the first op family runs everywhere. `tests/op_conformance.rs` gains ten PR1b cases (floor div/mod sign tables over ±7/±2, `MIN / 1`, `MIN mod -1 = 0`, `MIN / -1` → `Trap.Overflow`, zero divisor → `Trap.DivZero` for both ops, an unused-result `i64_div_floor` that must still trap, `write_i64` of 0 / negative / `MIN` / `MAX` interleaved with `putchar` and `print_i64`, and print-then-trap with unflushed `write_i64`/`putchar` output), a **JVM execution column** (real `java` with the verifier on, a generated `main(String[])` launcher, the `env` host classes compiled once per process), and two new gates: `pr1b_ops_are_lowered_on_every_backend` and `flush_before_trap_is_proven_on_every_executable_column` (WASM, VM, JIT always; LLVM/native/JVM when their toolchain exists). Every column must now report the trap *kind* (native/LLVM stderr `trap: <kind>`, JVM `RuntimeException: <kind>`, WASM the `env.__trap` id, VM `VMError::Trap`, JIT's `trap: <kind>` error slot); `None` fails. The conformance WASM host implements `env.__write_i64`/`env.__trap`, and the VM/JIT runners register `write_i64` on the shared ordered sink. `refused_ops_are_rejected_at_compile_time`'s bound is now derived from the JIT's interpreter-tier refusals instead of the retired PR1b count. `concretize_scalar_any_for_jvm` keeps a module that uses `write_i64`, `i64_div_floor` or `i64_mod_floor` on the wide i64 model (those ops are defined on i64; narrowing to `i32` would change `MIN` semantics). `StdoutThenTrap` stays in `op_conformance` until the first language row emits a PR1b op (LANG83 PR2).
