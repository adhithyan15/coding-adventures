## Unreleased - S10a: lowering, typing, `requires` and cost of the `ir.fixed` built-ins (VER04r A.1)

No version bump and no emitted byte changes: the committed `synth-v2`, `accept-blind-v2` and
ct-compare fixtures verify unchanged, and evaluating or emitting an `ir.fixed` suite still
refuses with the level `ir.fixed`.

### Added

- **Lowering and typing of the 35 built-ins** of Appendix A.1 (`lower.fixed_call`): exactly the
  documented JSON shape per tag, a static type argument as the canonical type name in position 1,
  operand types inferred, every mismatch a `type` error (mixed widths, `sar` on an unsigned type,
  a count that is not a `Nat`, `from_be` of a `Bytes` of the wrong width, a signed `div`, `widen`
  past the target's range, ...). `div`/`rem` on two `Nat` operands are `Option<Int>` ([R7]).
- **`Option<T>` is an IR-only intermediate** ([D23], [R8]): `unwrap_or` is the only consumer, as
  its first operand and directly; any other use, and an `Option` in a model, op or binder type,
  is refused with the level `ir.data` by the lowerer and by the typed IR compiler.
- **`ir_eval.Program(analyze=True)`** types and costs the `ir.fixed` tags (`1 +` the operands;
  `max_value`/`min_value` cost 1); the closure raises the `ir.fixed` level instead of evaluating.
  A default `Program` still refuses the tags, so every verification path is unchanged. The tag
  table is now the exact 35 names (`try`, not `try_nat`).
- **`levels` module and `requires` inference** ([R9]): `ir_levels` is the sorted union of the levels
  of every tag and of the call closure of every `model_call`; a tuple *type* (binder, parameter,
  result, sub-expression) adds `ir.tuple`. Units record `requires` (`LoweredSuite`, `OpSig`,
  `LoweredModel`, `LoweredExample`); `derive` writes it into suite and op rows and into `levels`
  (identical to the old constant for every document it emits today).
- **`dump-lowering`** subcommand and `lowering_dump` module: the canonical lowering dump
  (`warrant-lowering-parity-v1`: lowered IR, computed `requires` and `ir_cost`) that the generator's
  S10b must reproduce byte for byte. `tests/fixtures/fixed-forms-v1/` commits the synthetic
  document (all 35 built-ins at every allowed width, generated by `make_fixed_forms.py`) and its
  dump; `BUILD` and `BUILD_windows` run both `--check`s.
- Tests: `test_fixed_lowering.py`, `test_fixed_requires_cost.py`, `test_fixed_dump.py`,
  `test_fixed_followups.py`.

### Follow-ups of VER04r 16.9 folded in

- **Fail-closed parity with the generator's `W0301`:** `lower_op_admit` refuses an op `admit` that
  calls a subject op even when no claim or example calls it (`ir: a subject call is forbidden
  here`, found on the source tree so a call next to a higher-level construct is still found).
- **Memoised callee-`admit` compilation:** `ir_eval.compiled_admit` compiles each op's `admit` once per
  `(op, static widths)` and keeps it on the `Program`; the D19 check, its cost and the example
  check share it. No output changes.

### Changed

- The level named for a unit is the first construct the lowerer cannot lower; a unit that only uses
  `ir.fixed` is named `ir.fixed` (and keeps its IR). A suite mixing `ir.fixed` with tuples or
  constructors is therefore counted under the latter, so the pinned census moved (wasm-leb128,
  logic-gates, arithmetic).
- Tuple tags, tuple projection and `match` on a `Result` are refused with `ir.tuple` (they were
  `ir.data`); `match` on any other scrutinee stays `ir.data`; `unwrap_or` left `ir.data`.
- An op whose signature mentions `Option` is refused (`ir.data`) even if no claim calls it.
