# vos-probe-ready

The fixture of the VOS-028b capacity probe (`code/programs/rust/vos-capacity-probe`,
VOS30 section 9). Class H: it has no contract and is not a verified-OS component, and
nothing depends on it but the probe.

## Why it exists

Experiment E1 of the probe measures how fast the *generated by-value harness*
(`warrant-grammar`'s evidence generator) enumerates a claim, and where its 400,000-case
budget refuses one (W0706). The real scheduler `vos-sched-fp-bitmap` is the fixture of every
knob that fits its fixed `N = 8`; the sizes beyond it come from here:

| Claim | Binders | Binder product |
|---|---|---|
| `pick_n8` | 8 `Bool` | 256 |
| `insert_n8_bool` | 8 `Bool`, `t: U8` | 65,536 |
| `insert_n8_mask` | `mask: U8`, `t: U8` (the `Impl(mask: U8)` form) | 65,536 |
| `insert_n10` | 10 `Bool`, `t: U8` | 262,144 |
| `insert_n8_mask_tagged` | `mask: U8`, `t: U8`, `Option<Bool>`, `Bool` | 393,216 |

The `N = 11` document the generator must refuse is **not** here as a harness: the probe
builds it from the N = 10 document in memory and expects W0706.

## What is in the package

* `src/lib.rs`: `insert8`, `insert10`, `pick8` over a bitmap in a `u8` or `u16`.
* `code/specs/vos-probe-ready.warrant` and `evidence.bindings`: the hand-written Warrant
  document and its binding manifest (the `shift-mask` fault is the negative control the
  probe uses).
* `tests/generated/warrant_evidence.rs`: the generated harness. Never edit it by hand; BUILD
  runs `gen_evidence --check` and fails on drift. The probe `include!`s the same file and
  drives its `exh_*` functions in process.

## Usage

```text
cargo test -p vos-probe-ready          # behaviour tests and the generated harness
cargo run -q -p coding_adventures_warrant_grammar --example gen_evidence -- vos-probe-ready
```
